## 0. 최종 발표자료 원칙

- 창업자의 개인 서사는 제외하고 고객 문제와 사업 검증 논리만 사용한다.
- 첫 5장만 읽어도 집신이 어떤 상황에서 어떤 일을 해결하는지 이해되어야 한다.
- 실제 매물 의뢰 상황에서 시작해 `불편 → 제품 화면 → 사용자 가치 → 수익과 검증` 순서로 설명한다.

- 현재 성과처럼 보일 수 있는 숫자는 사용하지 않고, 산식과 검증 방법을 함께 제시한다.

## 1. 사업 정의

집신은 계약 전부터 입주·거주·수리·관리·퇴거까지 발생하는 사진, 문서, 대화, 일정과 다음 할 일을 `집 한 채` 기준으로 연결하는 주거 기록 협업 서비스다.

집신은 수리기사 중개, 견적 비교와 앱 결제를 중심으로 하는 수리 플랫폼이 아니다. 수리는 집에서 발생하는 여러 사건 가운데 대표적인 사용 사례다.

## 2. 고객과 사용자

- 초기 결제 고객과 도입 채널: 공인중개사무소
- 핵심 사용자: 대표 공인중개사, 보조원, 임대인, 임차인
- 초기 고객 가설: 여러 집 또는 다가구 건물을 관리하고, 대표와 보조원이 함께 근무하며, 자료가 개인 휴대전화와 종이 파일에 흩어진 소규모 사무소

## 3. 해결하려는 문제

- 집 관련 연락, 사진, 계약서, 영수증과 처리 상태가 여러 도구와 개인 기억에 흩어진다.
- 직원이나 참여자가 바뀌면 누가 무엇을 어디까지 했고 다음에 무엇을 해야 하는지 알기 어렵다.
- 변경사항 확인을 위한 재방문과 반복 전달이 발생한다.

시간과 비용의 실제 절감 폭은 유료 파일럿에서 측정해야 하는 가설이다.

## 4. 제품 원리

- 집 ID는 시스템이 자동 생성한다.
- 주소만으로 기록을 공개하지 않는다.
- 기록은 집·계약·사무소 업무와 사건에 연결한다.
- 계약이 바뀌면 참여자와 접근 범위도 새로 만든다.
- 이전 임차인의 개인정보는 다음 계약으로 자동 전달하지 않는다.
- 대표는 직원의 접근을 종료하고 담당 업무를 이전한다.
- 개인정보와 계좌정보는 PDF에서 기본 제외한다.

## 5. 현재 상태

### 구현 완료

- Next.js App Router 기반 랜딩페이지
- 역할별 체험 화면
- 요금제 선택과 체험용 사전가입 폼
- GitHub, Vercel, `start.zipsin.net` 배포

### 아직 미구현

- 실제 회원가입, 로그인과 데이터베이스
- 실제 파일 저장과 관계자 초대
- 실제 채팅, 알림과 PDF 생성
- 직원 권한, 업무 이전과 결제

현재 사전가입 폼은 정보를 저장하거나 전송하지 않는다.

## 6. 수익모델 가설

- BUSINESS: 월 99,000원, 공인중개사무소 최대 50채
- 현재 가격은 출시 전 가설이다.
- 실제 가격은 사무소당 활성 집 수, 저장량, 본인확인·알림·PDF 비용, 도입 지원 시간과 재결제 의사를 확인한 뒤 결정한다.

## 7. 유료 검증안

- 대상: 문제가 뚜렷한 공인중개사무소 3곳
- 기간: 4주
- 범위: 실제 관리 집을 이용한 매물 의뢰·사건 흐름과 직원 변경 인수인계 시나리오
- 지표: 실제 결제, 주간 반복 사용, 등록 집 수, 초대 수락률, 재방문 횟수, 처리 기간, 인수인계 시간과 PDF 사용

파일럿 할인, 포함 집 수와 수치형 성공 기준은 사용자 승인 후 확정한다.

실행 순서는 `MVP 범위 승인 → MVP 개발·개인정보 기본 통제 검수 → 4주 유료 실증`이다.

## 8. 시장 배경

- 2024년 일반가구: 2,229.4만 가구
- 2024년 임차가구 비율: 38.0%
- 주택을 2건 이상 소유한 가구: 330.4만 가구
- 국토교통부는 개업공인중개사 현황을 분기별로 공표한다.

위 수치는 주거 기록이 발생하는 배경을 설명할 뿐, 집신의 결제 수요를 증명하지 않는다. 획득 가능한 초기 시장은 파일럿 지역과 고객 조건을 정한 뒤 산정한다.

## 9. 주요 미결정

- 공식 소유권 확인 수준
- 집 매매와 사무소 폐업 시 기록 이전
- 계약 종료 후 임차인의 열람 기간
- 계좌정보와 업로드 파일의 보존·마스킹 정책
- MVP 개발 일정, 예산과 팀 구성
