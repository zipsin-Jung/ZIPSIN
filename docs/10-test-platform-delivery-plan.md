# 집신 테스트 플랫폼 제작·배포 계획

- 작성일: 2026-10-02
- 상태: **계획 초안 · 사용자 승인 대기**
- 대상: Next.js App Router의 `/test` 클릭형 테스트 플랫폼
- 구현 상태: 시작하지 않음

## 목표

가상 데이터로 집신의 핵심 사용자 흐름을 직접 눌러보게 하고, 공인중개사무소의 업무 인수인계와 집 중심 기록이 실제로 이해되는지 검증한다. 실제 회원가입·접수·저장·초대·PDF 생성 기능으로 오해되지 않게 한다.

## 권장 첫 배포 범위

첫 배포는 `T-01 사무소 업무 인수인계`를 중심으로 한 얇은 완성 흐름으로 시작한다.

`대표 역할 → 오늘의 업무 → 기한 초과 업무 → 담당자 변경 → 보조원 역할 → 같은 집의 기록과 다음 행동 확인`

T-02 임차인 사건 기록과 T-03 공실 현황 공유는 T-01의 사용성 검증 뒤 확장한다. 이는 권장안이며 사용자 승인 전에는 확정하지 않는다.

## 기획과 설계의 구분

- 기획: 누구의 어떤 문제를 어떤 범위와 성공 기준으로 해결할지 정한다.
- 설계: 승인된 기획을 어떤 화면·상태·데이터·컴포넌트·권한·테스트 구조로 만들지 정한다.
- 요구사항 ID와 수용 기준이 승인되기 전에는 개발하지 않는다.

## 테스트와 검수 순서

1. 정적 검사: 타입, 린트, 빌드
2. 단위 테스트: 권한 판정, 상태 전환, 입력 검증, 개인정보 분리
3. 통합 테스트: 화면·상태·가상 데이터 연결
4. 역할별 시나리오와 E2E: 직접 URL, 새로고침, 뒤로가기 포함
5. 접근성·반응형: 키보드, 레이블, 대비, 320·390·1440px
6. 반복·스트레스: 연속 클릭, 빠른 역할 전환, 긴 텍스트, 많은 목록, 지연·실패
7. 수정 후 회귀 검사
8. 실제 배포 주소 smoke 검사

클릭형 데모의 스트레스 검사는 서버 부하 시험이 아니다. 화면 상태와 브라우저 안정성을 검사했다고만 보고한다.

## 자동화와 커버리지 원칙

- 단위·통합: Vitest, React Testing Library, user-event
- 브라우저 시나리오: Playwright
- 접근성 자동검사: axe 계열 도구와 수동 키보드 확인
- Lines, Statements, Functions, Branches를 각각 80% 이상으로 관리한다.
- 권한, 계약 분리, 개인정보 차단과 대표 사용자 흐름은 커버리지 수치와 별개로 필수 시나리오 100% 통과가 필요하다.
- 생성물·설정 파일 등 제외 대상은 파일과 이유를 문서에 남긴다.
- 빌드 성공과 실제 브라우저 검수 성공을 별도로 보고한다.

```text

features/test-platform/
  components/
  fixtures/
  state/
  types/
tests/
  unit/
  integration/
  e2e/
```

- 실제 백엔드·DB·업로드 없이 개인정보가 없는 고정 가상 데이터를 사용한다.
- 화면에서 숨기는 것만으로 실제 보안이 구현됐다고 표현하지 않는다.
- 기존 랜딩페이지 `/`는 보존하고 `/test`만 추가한다.

## 배포와 되돌리기

1. 로컬 자동검사와 독립 검수를 통과한다.
2. Vercel 미리보기 같은 스테이징 주소에서 실제 브라우저 검수를 한다.
3. 사용자 승인을 받은 뒤 정식 주소로 승격한다.
4. 배포 전 직전 성공 커밋과 배포 주소를 기록한다.
5. 흰 화면, 핵심 흐름 중단, 개인정보 노출 또는 심각한 화면 붕괴가 발견되면 직전 성공 배포로 되돌린다.

## 주요 위험

- TEST-001~016 전체를 한 번에 구현하면 테스트 플랫폼이 실제 MVP 개발로 팽창할 수 있다.
- 가상 초대·공유·PDF 미리보기가 실제 기능처럼 보일 수 있다.
- 80% 커버리지만 채우고 중요한 권한·사용자 흐름을 놓칠 수 있다.
- 최신 역할 체계와 `docs/BRIEF.txt`의 과거 역할 구성이 다르다. 이번 기준은 대표 공인중개사·보조원·임대인·임차인이다.
- 공개된 `/test`가 완성 제품으로 오해될 수 있다.

## 사용자 승인 필요 사항

1. 첫 배포 범위를 T-01 사무소 업무 인수인계로 시작할지
2. 배포 대상을 누구나 볼 수 있는 공개 주소로 할지, 제한된 내부 테스트로 할지
3. 커버리지 80% 기준을 신규 `/test` 관련 코드에 우선 적용할지, 저장소 전체에 즉시 적용할지

## 현재 다음 행동

사용자가 이 작업 순서와 첫 범위를 승인하면 1단계 PRD 보강과 T-01 상세 유저플로우 작성부터 시작한다. 승인 전에는 구현·배포하지 않는다.
