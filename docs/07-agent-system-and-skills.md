## 주요 운영 기준

- 작업 시작 전에 순서를 보고한다.
- 신규 작업은 여섯 역할의 최초 회의로 시작한다.
- 요구사항 ID와 수락기준이 없으면 개발하지 않는다.
- 기능 정의, UX·UI, 기술설계와 테스트설계를 별도 게이트로 승인한다.
- 설계·개발 에이전트는 자신의 결과를 최종 승인하지 않는다.
- 검수·비판 에이전트는 코드를 조용히 수정하고 스스로 승인하지 않는다.
- 빌드 성공과 브라우저 검수 성공을 구분한다.
- 측정 대상 제품 코드의 라인·문장·함수·분기 각각 80%를 기본 게이트로 쓰되 범위와 제외를 공개한다.
- 핵심 권한·계약 분리·PDF 필터는 정의된 보안 경로를 모두 테스트한다.
- 사용자 승인 전 최종 상태는 `검수 통과, 승인 대기`다.
