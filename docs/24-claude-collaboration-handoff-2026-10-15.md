2. 변하지 않는 집신의 정의
────────────────────────────────────────

집신은 집에 관한 일의 반복·누락·단절을 막는 집 중심 기록·업무 관리 웹앱입니다.

사진·문서·대화·일정·할 일을 `집 한 채`와 `현재 계약`에 연결합니다. 사람이 바뀌거나 시간이 지나도 허용된 집·사무소 업무 이력은 이어져야 합니다.

초기 결제 고객과 도입 채널은 공인중개사무소입니다. 그러나 공인중개사 전용 서비스가 아닙니다. 대표 개업공인중개사, 소속공인중개사, 중개보조원, 임대인, 임차인이 개인 계정과 서로 다른 권한으로 함께 사용합니다. 초대받은 수리기사·가족·건물관리자 등은 필요한 기간과 범위만 사용합니다.

수리는 집에서 발생하는 여러 사건 중 하나일 뿐입니다. 수리 중개 플랫폼, 시세·세금·임대료 수납 중심 자산관리 서비스, 매물 광고 서비스로 바꾸지 마세요.

제품 핵심 원칙:

- 주소나 집 ID를 안다고 기록을 볼 수 없습니다.
- 역할을 골랐다고 특정 집의 기록을 바로 볼 수 없습니다.
- 역할은 가능한 행동을 정합니다.
- 관계는 접근할 집·계약·사무소를 정합니다.
- 조건은 기간·상태·범위를 제한합니다.
- 중개보조원에게 공인중개사 자격이 필요한 확인·설명·계약 조율·계약서 작성·승인을 허용하지 않습니다.
- 직원 퇴사, 계약 종료, 관계 종료, 공유 철회 다음 요청부터 접근을 끝냅니다.
- 사람의 권한은 끝나도 허용된 집과 사무소 업무 기록은 남습니다.
- 이전 임차인의 개인정보, 계약서, 개인 대화와 생활 사진은 다음 계약자에게 자동 승계하지 않습니다.
- 휴대전화 본인확인은 계정 확인이지 소유권이나 공인중개사 자격 인증이 아닙니다.

제품 문장:

“부동산 계약했다면, 이제 만기까지 집신으로.”
“사람이 바뀌어도, 집의 기록은 남습니다.”

4. 인증의 현재 사실
────────────────────────────────────────

일반 로그인은 `아이디 + 비밀번호`입니다.

- 이메일은 회원가입 확인과 계정 복구에 사용합니다.
- 휴대전화는 회원가입 과정의 본인 확인에 사용합니다.
- 이메일과 전화번호는 현재 일반 로그인 입력값이 아닙니다.
- Google·카카오·네이버는 실제 환경 설정이 완료된 제공자만 표시하고 검증합니다.
- 로그인 뒤에는 검증된 안전한 내부 `next` 경로로 돌아갑니다.
- 로그인 시도 제한과 계정 존재 여부를 드러내지 않는 오류 원칙을 유지합니다.

다음 항목을 참고 화면만 보고 가짜로 추가하지 마세요.

- 이메일 로그인
- 전화번호 로그인
- 정책이 정의되지 않은 `로그인 유지`
- 미연결 소셜 로그인 버튼
- 데모 계정 또는 테스트 계정 노출

`로그인 유지`가 필요하다면 세션 기간, 공용 PC, 로그아웃, 모든 기기 로그아웃 정책을 먼저 설계하고 사용자 승인을 받아 별도 요구사항으로 진행합니다.

5. 바로 다음 과업: 로그인 수정안
────────────────────────────────────────

사용자의 가장 최신 화면 과업은 로그인 수정안입니다. 참고 화면은 중앙 카드형 구도와 단순한 시선 흐름만 참고하며 기능은 그대로 복제하지 않습니다.

먼저 코드를 바꾸지 말고 다음 3개를 하나의 일관된 시안으로 제출하세요.

1) 데스크톱 기본 상태
2) 로그인 오류 상태
3) 390px 모바일 상태

권장 구조:

- 밝은 뉴트럴 또는 아주 옅은 딥그린 배경
- 데스크톱 440~480px 중앙 카드
- 집신 로고
- 제목 `집신 로그인`
- 보조 문장 `집과 사무소의 기록을 이어서 확인하세요.`
- 실제 연결된 경우에만 소셜 로그인
- 소셜 로그인이 있을 때만 구분선
- 아이디
- 비밀번호와 보기·숨기기
- 아이디·비밀번호 찾기
- 주 버튼 `로그인`
- `집신이 처음이신가요? 회원가입`
- `집신은 권한 없이 집의 기록을 공개하지 않습니다.` 정도의 짧고 사실적인 보호 안내

모바일에서는 외곽 카드의 테두리와 그림자를 약하게 하고 입력과 버튼을 화면 너비에 맞게 사용합니다. 큰 캐릭터나 광고 문구가 로그인보다 먼저 보이거나 입력을 밀어내지 않게 합니다.

필수 상태:

- 기본
- 입력 중
- 비밀번호 보기·숨기기
- 아이디 또는 비밀번호 오류
- 너무 많은 로그인 시도
- 인증 서비스 일시 오류
- 로그인 처리 중과 중복 제출 방지
- 소셜 로그인 0개·1개·여러 개
- 안전한 next 경로 복귀

사용자가 시안을 승인하기 전에는 로그인 제품 코드를 수정하지 마세요.

────────────────────────────────────────
7. 에이전트 운영 체계: SOC와 SOP
────────────────────────────────────────

SOC는 역할별 책임 분리입니다. SOP는 각 역할이 따라야 할 작업 순서입니다.

사용자: 최종 결정과 승인

총괄비서:
- 범위, 순서, 회의, 충돌, 기록, 승인 게이트 관리
- 어떤 파일도 복구 불가능하게 삭제하지 않음
- 결과를 통합해 사용자에게 쉬운 말로 보고

제품기획:
- 문제, 사용자 가치, PRD, 기능 정의, MVP와 후속 구분
- 기획은 무엇과 왜를 정하고 설계와 구분

UX·UI 디자인:
- 유저플로우, 정보 구조, 화면, 상태, 문구, 접근성
- 예쁜 화면보다 실제 행동과 이해를 우선
- 승인된 기능만 표현

설계·개발:
