# DEC-014 집신체크 서브서비스 방향

- 작성일: 2026-10-13
- 상태: 제안 · 사용자 승인 대기

## 결정 제안

`집신체크`는 별도 가입·별도 데이터 제품이 아니라 **집신 단일 계정 안의 서브서비스**로 시작한다.

- 사용자 노출명: `집신체크 | 집신의 집보기·입주·퇴거 체크`
- 첫 구현 위치: 기존 Next.js 앱의 `/check`
- 후보집 기록: 사용자의 개인 초안으로 집신 장기 집 이력과 분리
- 전환: 사용자가 최종 선택한 집과 선택한 기록만 명시적으로 집신 본체에 연결
- 비교: 단일 안전 점수 대신 `확인됨 / 미확인 / 주의 / 전문가 확인 필요`

## 이유

- 집신 가입은 하나라는 사용자 원칙을 가장 단순하게 지킨다.
- 집신체크가 만든 현장 기록을 입주·거주·퇴거 흐름으로 자연스럽게 이어갈 수 있다.
- 후보집 주소나 사진이 기존 집 기록과 자동으로 섞이는 개인정보·권한 위험을 줄인다.
- 별도 앱·별도 DB·중앙 로그인 연동의 불필요한 초기 복잡성을 피한다.

## 대안

- `check.zipsin.net` 별도 프런트 앱: 캠페인 독립성은 좋지만 인증·배포·디자인 관리가 복잡하다.
- 별도 앱·별도 DB: 장기적인 조직 분리에는 유리하지만 현재 검증 단계에는 과도하다.

## 영향

- 첫 제품은 집 보기 체크와 후보 비교에 집중한다.
- 입주·퇴거는 같은 서비스 안의 후속 단계로 확장한다.
- 정확 주소, 사진, 공유와 보존 정책은 구현 전에 별도 승인한다.
- 실제 계정·저장을 구현할 때 현재 정적 export 구조를 서버 런타임으로 전환하고 기존 랜딩과 데모를 회귀 검수해야 한다.

## 승인 필요

사용자가 이름, 첫 대상, 상태형 비교, 첫 체크 후 가입 유도와 `/check` 통합 방향을 승인하면 확정으로 변경한다.
