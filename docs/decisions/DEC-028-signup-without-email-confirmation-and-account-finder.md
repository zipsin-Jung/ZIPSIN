# DEC-028 이메일 확인 없는 가입·로그인과 아이디·비밀번호 찾기 방식

- 날짜: 2026-10-16
- 결정자: 사용자(정민선)
- 상태: 승인(시안 ⑤~⑨ "좋아", 10:19)

## 사용자 지시 원문

- "아이디 비밀번호 찾기 도 만들어야해 이메일로 아이디 찾기 하는거고 이메일 확인은 로그인 할땐 필요 없어"
- "이메일 .. 인증은 없이 이메일 치면 아이디 나오게 하고 비밀번호는 핸드폰 인증하면 다시 설정 가능하게 하자"
- "비밀번호는 이름 휴대폰 인증 후에 새 비밀번호 만들기 하는거로"
- (10:56) "이비밀번호 잊었을때 아이디 이름 휴대폰 해야해 같은 번호 OR 휴대폰 하나에 회원가입 하나로 규정하든가"

## 결정

1. **이메일 확인은 가입·로그인 조건이 아니다.**
   - 휴대폰 인증을 마친 가입만 Auth 계정을 만들고, 관리자 API로 `email_confirm: true` 상태로 만든다. 확인 메일은 보내지 않는다.
   - 가입 직후 자동 로그인하고 `/signup/complete`(가입 완료 → 집신 시작하기)로 간다.
   - 예전 방식으로 만들어진 미확인 계정은 **비밀번호가 맞은 뒤에만** 확인 처리하고 한 번 다시 로그인한다.
2. **아이디 찾기 = 이메일 입력 → 화면에 바로.**
   - 메일 발송·인증은 없다.
   - 아이디는 일부를 가린다(`zip***nt`).
   - 접속 위치별 1시간 20회, 이메일별 1시간 5회로 제한한다.
3. **비밀번호 재설정 = 아이디 + 이름 + 휴대폰 문자 인증 → 새 비밀번호.** (10:56 수정)
   - 세 가지가 모두 맞는 계정이 없으면 문자를 보내지 않는다.
   - 휴대폰 번호 하나에는 계정 하나만 가입된다(기존 서버 규칙 `phone_already_registered`, 이번에 확인·유지).
   - 인증 세션은 10분, 한 번만 쓸 수 있다.
4. 회원가입에 **이름** 칸을 추가한다(`profiles.display_name`에 저장). 실명 인증이 아니라 사용자가 적은 이름이다.

## 위험과 대응

| 위험 | 대응 |
|---|---|
| 남의 이메일로 아이디 일부 노출 | 아이디 일부 가림, 시도 횟수 제한 |
| 이메일 오타 시 아이디 찾기 불가 | 가입 완료 화면에 찾기용 이메일(가림) 표시. 휴대폰 인증으로 비밀번호는 복구 가능 |
| 이름+번호 조합 존재 여부 노출 | 번호별 문자 발송 제한(기존 `reserveSmsSend`)이 이름 추측도 함께 막음 |
| 이 결정 이전 가입자 | `display_name`이 아이디로 저장되어 이름이 맞지 않음 → 테스트 계정만 해당, 출시 전 재가입 또는 이름 수정 필요 |

## 바꾸지 않은 것

- DB migration 없음(이름·이메일·휴대폰은 이미 `profiles`에 저장됨).
- Supabase Auth 설정 변경 없음. Production 변경 없음.
- 기존 이메일 재설정 경로(`request-account-recovery`, `/auth/callback`)는 삭제하지 않고 화면에서만 뺐다.
