# DEC-032 사무소 아이디 하나 + 직원 이름·4자리, 개인 아이디는 따로

- 결정일: 2026-10-18
- 상태: **1·2번은 DEC-040(한 아이디에 계정 여러 개)으로 기본 방식에서 내려옴 (2026-10-19).** 3~5번 취지(누가 했는지 남기기·퇴사자 차단·개인과 업무 분리)는 DEC-040이 이어받음. 공용 PC 모드는 나중에.

## 결정
1. 공인중개사무소는 **사무소 아이디 하나**로 로그인하고, 직원들이 동시에 접속해 같은 집 목록으로 일한다.
2. 로그인 뒤 **"누가 쓰나요?"**에서 이름을 고르고 **4자리 비밀번호**를 넣는다. 같은 휴대폰에서는 다음부터 이름만 고른다. 맨 위 이름을 눌러 쓰는 사람을 바꾼다.
3. 기록·수리 단계·임대인 확인 체크는 **고른 직원 이름**으로 남는다.
4. 직원을 내보내면 그 이름만 막는다. 사무소 비밀번호는 바꾸지 않아도 되고, 그 직원이 올린 기록은 남는다.
5. 대표 개인의 집은 **개인 아이디**로 따로 쓴다. 개인 아이디에는 사무소 업무가 보이지 않는다.

## 이유
- 아이디를 그냥 같이 쓰면 누가 했는지 남지 않아 DEC-029의 확인 기록 근거가 사라지고, 퇴사자가 계속 들어올 수 있다.

## 남은 설계
- DB: 사무소 계정(로그인) ↔ 직원 프로필(이름·4자리 해시·상태) ↔ 기록의 작성 직원. 4자리 연속 실패 잠금.
- 기존 "직원마다 자기 아이디" 구현(office_memberships)과의 관계 정리.
