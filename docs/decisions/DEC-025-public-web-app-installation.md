# DEC-025 공개 홈의 앱 다운로드를 온라인 전용 PWA 설치로 제공

- 날짜: 2026-10-14
- 상태: 설계 승인 대기
- 결정권자: 사용자

## 결정

공개 홈의 `앱으로 다운로드`는 네이티브 앱이나 가짜 스토어 링크가 아니라 현재 집신 웹앱을 기기에 설치하는 PWA 방식으로 제공한다.

- 지원 Chromium: 사용자 클릭 뒤 실제 설치 프롬프트
- iPhone·iPad: Safari의 `공유 → 홈 화면에 추가 → 추가` 안내
- 미지원 브라우저: 브라우저 메뉴 설치 안내
- 설치된 환경: `앱 설치됨` 상태

이번 단계에는 서비스 워커·오프라인 캐시·푸시 알림을 포함하지 않는다.

## 비교

| 선택지 | 장점 | 위험·한계 | 판단 |
|---|---|---|---|
| 설치 안내만 | 가장 빠르고 단순함 | 실제 설치 요청을 충족하지 못함 | 제외 |
| Manifest+점진적 설치 | 실제 설치, 웹 배포 하나로 운영, 되돌리기 쉬움 | iOS는 수동 안내가 필요함 | 권고 |
| 네이티브 스토어 앱 | 스토어 발견성과 기기 기능 확장 | 현재 바이너리·심사·이중 운영 준비 없음 | 후속 |

## 이유

- 사용자는 실제 `앱으로 다운로드` 진입을 요청했다.
- Next.js 16.4는 App Router Manifest를 지원하고 HTTPS에서 홈 화면 설치가 가능하다.
- 서비스 워커 없이도 설치 진입을 제공할 수 있다.
- 계약·주소·채팅이 있는 인증 화면을 성급히 오프라인 캐시하면 개인정보나 오래된 자료가 남을 위험이 있다.

## 영향과 실패 대비

- 즉시: 헤더에 설치 CTA가 생기고 플랫폼별 안내가 필요하다.
- 6개월 운영: 웹 배포 하나로 유지할 수 있지만 스토어 검색 유입은 없다.
- 장기: 카메라·푸시·백그라운드 기능이 핵심이고 PWA로 해결되지 않는 사용자 증거가 생기면 네이티브 앱을 다시 검토한다.
- 실패 신호: 설치 프롬프트 준비 비율 저조, iOS 안내 이탈, 설치 뒤 재방문 부족.
- 롤백: 설치 컴포넌트와 manifest 연결만 제거하면 기존 공개 홈으로 돌아간다.

## 제외

App Store·Google Play 배지, QR, 네이티브 앱 주장, 오프라인 보장과 Production 배포는 이 결정에 포함되지 않는다.
