# 유료 출시 범위와 완료 판정 기준

날짜: 2026-10-13
상태: 권고안 — 사용자 최종 승인 대기

## 결정 배경

홈 화면과 개별 기능을 반복 수정해도 가입부터 결제·반복 사용·이용 종료까지 연결되지 않으면 돈을 받고 운영할 수 있는 제품이 되지 않는다. `완벽해서 영원히 손댈 것이 없는 제품`은 검증할 수 없으므로, 완료의 의미를 출시 범위와 증거로 고정해야 한다.

## 선택지

| 선택지 | 즉시 | 6개월 | 장기 위험 |
|---|---|---|---|
| 화면을 계속 다듬기 | 시각 품질 일부 개선 | 결제·사용 데이터가 없음 | 같은 재설계 반복 |
| 유료 사용 흐름 하나를 완결 | 가입부터 종료까지 실제 검증 | 실제 전환·이탈·지원 데이터를 학습 | 검증된 기반 위 확장 가능 |
| 모든 장기 기능을 한 번에 개발 | 범위와 일정 급증 | 운영·권한 결함 증가 | 되돌리기 어려운 복잡성 |

## 권고 결정

두 번째 선택지를 채택한다.

출시 완성 단위를 다음으로 고정한다.

`문제 인지 → 가입·실인증 → 첫 집·첫 기록 → 가치 경험 → 요금 확인 → 결제 → 권한 활성화 → 반복 사용 → 결제/이용 종료 → 자료 처리`

첫 판매 구조는 기존 결정에 따라 `사무소당 99,000원 / 8주 / 자동 결제·자동 전환 없음`으로 유지한다. 249,000원은 과금 주기와 포함량이 승인되기 전까지 정가나 확정 상품으로 판매하지 않는다.

## 완료의 정의

완료는 다음 조건을 모두 만족한 상태다.

- 승인된 출시 범위의 P0·P1 0건
- 실제 Preview에서 실제 DB·승인된 공급자 테스트 환경으로 전체 흐름 완주
- 출시 필수 E2E skip 0건
- 역할·관계·기간별 권한 종료 음성 검증
- 결제 서버 검증·중복 방지·실패 복구·환불/종료 검증
- 약관·개인정보·환불·보존 정책과 운영 절차 준비
- 백업 복구·모니터링·롤백 증거
- 사용자 Production·실결제 최종 승인

## 되돌릴 수 있는 부분

- 요금과 한도는 하나의 catalog 설정으로 변경한다.
- 가입·SMS·OAuth·결제·업로드·채팅은 기능 플래그로 중단할 수 있게 한다.
- 앱 코드는 정확한 안정 SHA로 롤백한다.

## 되돌리기 어려운 부분

- 실제 고객 데이터가 들어간 뒤의 파괴적 schema 변경
- 개인정보 보존·파기 약속
- 고객에게 공개한 자동 갱신·환불·가격 조건
- 잘못 부여된 집·계약 접근 권한

따라서 위 항목은 Production 전 독립 검수와 사용자 승인을 필수로 한다.

## 사전 실패 분석

1. **결제는 성공했지만 권한이 열리지 않음**
   서버 승인과 webhook inbox, 멱등 처리, 운영자 재처리 절차로 방지한다.
2. **관계 종료 사용자가 파일·채팅을 계속 봄**
   UI가 아닌 API·RLS·signed URL·직접 URL 음성 테스트로 차단한다.
3. **99,000원과 249,000원 문구가 화면마다 다름**
   단일 가격 catalog와 계약 테스트를 사용한다.
4. **디자인만 반복하고 출시 흐름이 미완성**
   디자인 동결과 P0/P1 우선순위, 변경 요청 절차를 적용한다.
5. **PG·SMS·법정 정보가 없어 마지막에 출시 중단**
   사용자만 할 수 있는 외부 준비를 초기에 한 번에 제시한다.

## 사용자 승인 필요

- 이 완료 정의와 작업 범위
- 파일럿 VAT·포함량·환불·종료 뒤 자료 정책
- PG·SMS·OAuth 공급자와 계정 준비
- 정책 문안의 전문가 검토
- Production 배포와 실결제 활성화
