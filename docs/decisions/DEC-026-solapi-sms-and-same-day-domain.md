# DEC-026 회원가입 문자 인증 공급자 솔라피 연결과 zipsin.net 당일 연결

- 날짜: 2026-10-15
- 상태: 코드 구현·자동검사 완료, 실제 발송 미검증(발신번호 심사 대기)
- 결정권자: 사용자

## 결정

1. 회원가입 휴대전화 인증은 모의 공급자 대신 **솔라피(SOLAPI)** 실제 문자 발송을 사용한다.
2. 사용자는 Preview 다계정 권한(RLS) 검증 전이라는 위험을 안내받은 뒤 **zipsin.net을 오늘 바로 연결**하기로 선택했다.

## 비교 (문자 인증)

| 선택지 | 장점 | 위험·한계 | 판단 |
|---|---|---|---|
| 솔라피 연결 | 개인도 가입 가능, 국내 문자 전용, 실제 본인 번호 확인 | 발신번호 심사 영업일 1~3일, 문자 단가 확인 필요 | 사용자 선택 |
| 당분간 휴대전화 인증 생략 | 오늘 바로 가입 가능 | 가짜 가입 방어 약화, 제품 원칙과 다름 | 제외 |

출처: https://solapi.com/guides/start (2026-10-15 확인)

## 구현 요약

- `features/auth/phone/solapi-provider.ts`
  - 6자리 인증번호, 5분 만료
  - 인증번호 원문은 저장하지 않고 번호·사용자·만료시각을 서버 비밀값으로 HMAC 서명한 값만 challenge id로 사용 → 서버 인스턴스가 여러 개여도 확인 가능, 새 DB 테이블 불필요
  - 확인 시도는 기존 `consume_auth_rate_limit`로 사용자당 5분 5회 제한
- `PHONE_VERIFICATION_PROVIDER=solapi`일 때만 사용, 설정값이 비면 공급자 오류(503)로 안내
- 운영에서 모의 공급자 차단 규칙은 그대로 유지

## 필요한 환경변수 (Vercel에 사용자가 직접 입력, Git·대화에 저장 금지)

| 이름 | 내용 |
|---|---|
| `PHONE_VERIFICATION_PROVIDER` | `solapi` |
| `SOLAPI_API_KEY` | 솔라피 API 키 |
| `SOLAPI_API_SECRET` | 솔라피 API 시크릿 |
| `SOLAPI_SENDER_NUMBER` | 승인된 발신번호 |
| `PHONE_CODE_HMAC_SECRET` | 32자 이상 무작위 문자열 |

## 위험과 되돌리는 조건

- 솔라피 인증 헤더 형식은 실제 발송으로 아직 검증하지 않았다. 첫 실발송에서 실패하면 공식 개발자 문서로 형식을 재확인한다.
- zipsin.net 당일 공개는 RLS 다계정 검증 전 공개다. 타인 데이터 노출이 한 건이라도 확인되면 즉시 이전 랜딩으로 도메인을 되돌리고 P0로 수정한다.
- 발신번호 승인 전까지 새 회원가입은 휴대전화 인증 단계에서 멈춘다.
