# DEC-013: 집신 혼합 권한 모델

- 날짜: 2026-10-08
- 상태: 권고안 · 사용자 승인 대기
- 결정 책임자: 사용자
- 미룰 경우: 로그인·집 연결·초대·파일 열람 구현의 권한 기준이 확정되지 않아 실제 서비스 개발을 시작하지 않는다.

## 제안 결정

집신의 권한은 다음 세 요소를 함께 사용한다.

1. RBAC: 대표 공인중개사·보조원·임대인·임차인의 기본 행동 범위
2. ReBAC: 사용자와 사무소·집·계약·사건 사이의 활성 관계
3. 제한적 ABAC: 참여 상태, 계약 상태, 공유 기간, 기록 공간과 자료 민감도

기본은 거부하며, 참여 종료·공유 철회·명시적 차단은 허용보다 우선한다. 역할 선택, 주소 입력, 휴대전화 본인확인만으로 특정 집의 권한을 부여하지 않는다.

## 이유

- 순수 RBAC는 같은 임대인·임차인이라도 접근 가능한 집이 서로 다르다는 점을 표현하기 어렵다.
- 순수 ABAC는 MVP에서 정책 복잡성과 잘못된 속성 관리 위험이 크다.
- 집신의 핵심은 사람과 집·계약·사무소의 관계이며, 상태와 기간은 그 관계를 제한하는 조건이다.
- 현재 Supabase/Postgres 계획에서 관계 테이블과 RLS로 시작할 수 있어 별도 정책 엔진을 즉시 도입하지 않아도 된다.

## 영향

- 사용자 문구는 `집 키`보다 `집 연결 초대`, `공유 승인`, `접근 종료`를 우선한다.
- 사무소 내부 원본과 임대인 승인 공유 공간을 분리한다.
- 모든 서버 읽기·쓰기·파일 접근은 공통 권한 판정과 RLS를 통과한다.
- Amazon Verified Permissions/Cedar는 여러 서비스가 동일 정책을 공유하거나 고객별 정책 편집 요구가 생길 때 재검토한다.

## 남은 결정

- 공식 소유권 확인 수준
- 공동소유·법인·대리인의 승인 규칙
- 계약 종료 후 임차인의 열람 기간
- 임대인 승인 전 사무소 자료 보관의 법적 범위
