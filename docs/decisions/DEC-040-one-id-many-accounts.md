# DEC-040 한 아이디에 계정 여러 개 (인스타 방식)

- 결정일: 2026-10-19
- 상태: 대표 결정 ("인스타 계정처럼 한 아이디에 계정을 여러개" 14:22 → "오케이 일단 진행시켜" 14:25)
- 바꾸는 것: DEC-032의 1·2번(사무소 공용 아이디 + 직원 4자리)을 기본 방식에서 내린다. DEC-032 문서는 그대로 두고 상태만 고친다.

## 결정
1. 로그인은 **사람 한 명당 아이디 하나**. 휴대전화 본인 확인은 한 번.
2. 그 아이디 안에 계정이 여러 개: **개인(내 집)** · **내가 구성원인 사무소** · (나중에) **파트너 업체**.
3. 위쪽 **'이름 ▾'**로 다시 로그인하지 않고 바꾼다. 사무소는 실제 구성원(office_memberships 활성)일 때만 보인다. 고른 계정은 쿠키에 남기되, 서버가 매번 구성원인지 다시 확인한다.
4. 기록은 **그 사람 아이디**로 남는다(누가 했는지 = 실제 사람). 퇴사하면 사무소 구성원만 끝나고, 사무소 기록과 그 사람의 개인 집은 각각 남는다.
5. 개인 계정 화면에는 사무소 업무가 섞이지 않는다(내가 임대인·임차인으로 직접 연결된 집만).

## 이유
- 누가 했는지가 정확히 남는다(DEC-029 확인 기록 근거). 4자리는 같은 사무소 사람이 남인 척할 수 있다.
- 지금 DB(office_memberships·home_memberships)로 바로 된다. 새 로그인 체계를 만들지 않는다.
- 임차인이 나중에 청소 파트너가 돼도 새로 가입하지 않는다.

## 남은 것
- 사무소 공용 PC가 꼭 필요하면 "공용 PC 모드"는 나중에 따로 설계(DEC-032 2번 아이디어 재사용 가능). 지금은 만들지 않는다.
- 하위 서비스(ck·cl·rp)까지 한 로그인으로 묶는 것은 쿠키 도메인 정리 뒤.
