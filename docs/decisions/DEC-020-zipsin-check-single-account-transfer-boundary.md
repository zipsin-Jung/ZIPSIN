# DEC-020 집신체크 단일계정·후보기록 이전 경계

- 상태: 승인
- 결정일: 2026-10-13
- 승인 근거: 사용자 설계 승인(“승인”, 후속 “응”)
- 관련 문서: `docs/superpowers/specs/2026-10-13-zipsin-check-account-sync-design.md`

## 결정

집신체크는 별도 회원체계를 만들지 않고 집신 단일 계정을 사용한다. 로그인 전 기록은 현재 브라우저에 남기며, 사용자가 직접 선택하고 동의한 후보집만 계정 소유자 전용 `candidate_draft`로 이전한다.

가입 출처 `zipsin_check`와 사용자가 확인한 `집 구하는 중/임차인` 유형은 유입 분석용 계정 정보다. 이것만으로 집, 계약, 사무소, 임대인 또는 임차 관계 권한을 만들지 않는다. 동일 주소의 기존 기록이나 이전 사용자의 개인정보도 자동 연결하지 않는다.

## 기술 경계

- Next.js App Router 서버 런타임과 Supabase 쿠키 세션을 사용한다.
- 소유권은 서버 세션, Postgres RLS, 비공개 Storage 정책으로 중복 검증한다.
- 이전 요청과 로컬 후보는 사용자별 고유키로 멱등 처리한다.
- 서버 저장 성공 후에도 로컬 원본은 자동 삭제하지 않는다.
- 서버 후보 삭제와 현재 브라우저 로컬 삭제는 별도 행동이다.
- Production 배포, DNS, 실 OAuth 공급자 활성화는 G6 승인 전 수행하지 않는다.

## 이유

체크 도구의 낮은 진입 장벽을 유지하면서 실제 임차인 사용자를 집신 계정으로 연결할 수 있다. 동시에 역할 선택이나 주소만으로 타인의 집·계약 기록에 접근하는 개인정보 위험을 차단한다.

## 되돌리기

계정 저장 CTA를 비활성화하고 기존 localStorage/IndexedDB 흐름만 유지한다. 이미 생성된 서버 후보는 파괴하지 않으며 소유자가 계속 조회·삭제할 수 있게 한다.
