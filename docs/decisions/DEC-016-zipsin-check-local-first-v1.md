# DEC-016 집신체크 로컬 우선 V1

- 작성일: 2026-10-13
- 상태: 확정 · 사용자 승인 2026-10-13
- 관련 요구사항: ZC-001~008

## 결정안

첫 구현은 기존 Next.js App Router 앱의 `/check`에 만들고, 브라우저 `localStorage`에만 후보 집과 체크 결과를 저장한다. 서버 전송, 실제 회원가입, 사진 업로드와 정확 주소 수집은 하지 않는다.

## 이유

- 현재 앱은 `output: 'export'`인 정적 배포 구조여서 서버 인증과 데이터베이스를 억지로 섞지 않고도 핵심 가치를 검증할 수 있다.
- 비회원도 체크·요약·최대 3채 비교를 끝낼 수 있어 가입 강요 없이 제품 가치를 먼저 보여준다.
- 실제 주소·사진·계약정보를 수집하기 전에 개인정보 범위, 보존기간, 삭제·내보내기 정책을 별도 승인할 시간을 확보한다.

## 범위

- 포함: 빠른/꼼꼼 모드, 공통 핵심, 항목별 설명, 관찰 상태와 출처, 메모, 요약, 최대 3채 비교, 기기 내 복원, 집신 가입 안내
- 제외: 실제 계정 생성, 서버 저장, 여러 기기 동기화, 사진, 외부 서류 조회, AI 안전 판정
- 후보 제거는 즉시 삭제 대신 `비교에서 제외`로 보관하고 사용자가 다시 복구할 수 있게 한다.

## 대안

1. 처음부터 서버·인증 포함: 기기 간 복원이 가능하지만 현재 정적 구조 변경, 개인정보 정책과 보안 검증이 먼저 필요하다.
2. 저장 없는 화면 시안: 제작은 빠르지만 재방문·후보 비교라는 핵심 가치 검증이 어렵다.

## 영향과 후속 승인

- 로컬 데이터는 같은 브라우저·기기에서만 보이며 브라우저 데이터 삭제 시 복구할 수 없음을 알린다.
- 공용 기기 노출 위험 때문에 정확 주소, 비밀번호, 연락처 등 민감정보 입력을 피하도록 안내한다.
- 실제 가입 CTA는 기존 랜딩의 안내 영역으로만 연결하며 가입 완료나 서버 저장으로 오인시키지 않는다.
- 계정 저장 단계 전에는 데이터 분류, 보존·삭제·내보내기, 접근권한, 서버 런타임 전환을 다시 승인받는다.

## 되돌리기

`/check` 경로와 집신체크 전용 모듈을 제거하면 기존 랜딩과 `/demo`에 영향을 주지 않고 되돌릴 수 있다. 로컬 저장 키는 버전명으로 분리한다.
