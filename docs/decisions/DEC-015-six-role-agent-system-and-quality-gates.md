# DEC-015 여섯 역할 에이전트 체계와 품질 게이트

- 작성일: 2026-10-13
- 상태: 제안 · 사용자 승인 대기
- 선행 결정: DEC-005 네 역할과 여섯 스킬 공식 적용

## 결정 제안

집신의 공식 체계를 다음 여섯 역할로 확장한다.

1. 총괄비서
2. 제품기획
3. UX·UI 디자인
4. 설계·개발
5. 검수·비판
6. 시간선·대안 분석

작업 단계는 `기능 정의 → UX·UI 스펙 → 기술 설계 → 테스트 케이스 → TDD 개발 → 자동검사 → 독립 검수 → 수정·재검수 → 완료보고 → 사용자 승인`으로 운영한다.

## 이유

- 기획, 화면 설계와 기술 구조의 책임과 승인 시점을 분명히 한다.
- 구현 전에 테스트 케이스를 고정해 구현 결과에 맞춰 검사를 약화하는 일을 막는다.
- 시간선 분석을 독립 자문 역할로 두되 근거 없는 미래예측 권한을 주지 않는다.
- 사용자 요구인 코드 커버리지와 대표 기능의 소스·테스트 매칭을 검증 가능한 형식으로 만든다.

## 품질 기준

- 측정 대상 제품 코드의 lines/statements/functions/branches 각각 80% 이상
- 대표 기능의 REQ/AC/FLOW/SCREEN/SOURCE/TEST/실행 증거 추적
- P0/P1 0건, 핵심 권한·개인정보 경로 100% 실행
- 빌드와 실제 브라우저 검수를 별도 보고
- 스트레스 테스트는 정의된 용량 위험과 임계값이 있을 때 안전한 환경·합성 데이터로 실행

## 호환성과 영향

- DEC-005와 기존 `product-design.md`는 과거 기록과 링크를 위해 보존한다.
- 기존 결합 기획·디자인 역할은 새 작업에서 제품기획과 UX·UI 디자인으로 나눈다.
- 새 스킬 `zipsin-timeline-analysis`를 추가해 총 일곱 스킬로 운영한다.
- 사용자 승인 전에는 제안 상태이며 실제 제품 구현 권한을 주지 않는다.
