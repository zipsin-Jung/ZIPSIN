# DEC-012 아이디 로그인과 소셜 로그인 병행

- 날짜: 2026-10-06
- 상태: 사용자 승인 · 로컬 구현 완료 · Preview 검증 대기
- 관련 요구사항: `PSV1-AUTH-001`~`004`

## 결정

집신 로그인은 Google·카카오·네이버 간편 로그인과 별도 아이디·비밀번호 로그인을 함께 제공한다. 로그인 화면에서는 이메일을 받지 않고, 이메일은 회원가입 확인과 계정 복구에 사용한다.

## 구조

- Supabase Auth가 이메일 확인, 비밀번호 검증과 세션을 담당한다.
- 직접 조회가 차단된 `account_usernames`가 아이디와 Auth 사용자를 연결한다.
- 아이디→Auth 이메일 해석은 서버에서만 수행하고 클라이언트·응답·로그에 이메일을 노출하지 않는다.
- 비밀번호 원문은 애플리케이션 DB와 로그에 저장하지 않는다.
- 같은 이메일만으로 소셜 계정과 일반 계정을 자동 병합하지 않는다.

## 가입 순서

`아이디·비밀번호·이메일 → 이메일 확인 → 휴대전화 인증·이름 → 필수 동의 → 역할 선택`

## 안전 조건

- 아이디는 4~20자의 영문 소문자·숫자·밑줄이며 초기에는 변경하지 않는다.
- 로그인 실패는 계정 상태와 관계없이 같은 문구를 사용한다.
- DB 고유 제약으로 동시 중복 아이디를 막는다.
- 아이디 로그인은 기능 플래그로 끌 수 있고 소셜 로그인은 유지한다.
- 로그인·가입·복구 요청 제한은 Postgres 원자 카운터를 사용한다. 아이디·이메일·요청 출처는 서버 비밀값으로 HMAC 처리한 뒤 DB에서 다시 해시하므로 원문을 저장하지 않는다.
- 가입 중 아이디 예약 보상 삭제가 실패하면 비공개 `auth_cleanup_queue`에 남겨 운영자가 재처리한다.

## 롤백

기능 플래그로 아이디 로그인·가입을 중단하고 소셜 로그인을 유지한다. 사용자 데이터가 생긴 뒤 매핑 테이블이나 Auth 사용자를 일괄 삭제하지 않는다.
