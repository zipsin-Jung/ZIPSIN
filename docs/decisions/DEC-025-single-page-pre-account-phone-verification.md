# DEC-025: 단일 화면 계정 생성 전 휴대폰 인증

- 날짜: 2026-10-14
- 상태: 사용자 서면 검토 대기
- 결정 책임자: 사용자
- 대체 범위: 기존 `AUTHUX-003 두 단계 회원가입`

## 제안 결정

비밀번호 신규가입은 `/signup` 한 화면에서 아이디, 비밀번호, 이메일, 휴대폰 OTP, 필수동의를 입력한다. 휴대폰 OTP가 성공하기 전에는 Auth 사용자나 제품 가입 데이터를 만들지 않고, 인증 증거를 서버에서 한 번만 소비하면서 최종 계정을 만든다.

## 이유

- 별도 `/signup/verify`는 초보 사용자에게 휴대폰 인증 위치를 찾기 어렵게 하고 가입 이탈을 늘린다.
- 단순히 화면만 합치고 계정을 먼저 만들면 문자 실패 때 미완료 계정과 재가입 충돌이 남는다.
- 익명 사전 OTP와 최종 단일 소비는 사용자에게는 한 화면을 제공하면서 서버 보안 경계를 분리한다.

## 보존과 제한

- OAuth와 기존 미완료 계정에 필요한 `/signup/verify`는 유지한다.
- 휴대폰 인증은 번호 소지 확인일 뿐 법적 본인확인·성인인증이 아니다.
- 잔존 `만 14세 이상` 별도 동의·가드는 제거한다.
- 성공 challenge 개인정보는 즉시 최소화하고 실패·만료 데이터는 최대 24시간 안에 정리한다.
- Production 배포는 사용자 최종 승인 전 수행하지 않는다.

## 롤백

새 DB·API는 additive로 추가한다. 문제 발생 시 신규 비밀번호 가입 폼만 기능 플래그로 기존 경로에 되돌리며 기존 OAuth, 미완료 계정과 사용자 데이터는 삭제하지 않는다.
