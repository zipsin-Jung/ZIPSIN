# DEC-025: 단일 화면 계정 생성 전 휴대폰 인증

- 날짜: 2026-10-14
- 상태: Preview DB·WebKit 검수 완료·실문자 공급자 연동 대기
- 결정 책임자: 사용자
- 대체 범위: 기존 `AUTHUX-003 두 단계 회원가입`

## 제안 결정

비밀번호 신규가입은 `/signup` 한 화면에서 아이디, 비밀번호, 이메일, 휴대폰 OTP, 필수동의를 입력한다. 휴대폰 OTP가 성공하기 전에는 Auth 사용자나 제품 가입 데이터를 만들지 않고, 인증 증거를 서버에서 한 번만 소비하면서 최종 계정을 만든다.

## 이유

- 별도 `/signup/verify`는 초보 사용자에게 휴대폰 인증 위치를 찾기 어렵게 하고 가입 이탈을 늘린다.
- 단순히 화면만 합치고 계정을 먼저 만들면 문자 실패 때 미완료 계정과 재가입 충돌이 남는다.
- 익명 사전 OTP와 최종 단일 소비는 사용자에게는 한 화면을 제공하면서 서버 보안 경계를 분리한다.

## 보존과 제한

- OAuth와 기존 미완료 계정에 필요한 `/signup/verify`는 유지한다.
- 휴대폰 인증은 번호 소지 확인일 뿐 법적 본인확인·성인인증이 아니다.
- 잔존 `만 14세 이상` 별도 동의·가드는 제거한다.
- 성공 challenge 개인정보는 즉시 최소화하고 실패·만료 데이터는 최대 24시간 안에 정리한다.
- Production 배포는 사용자 최종 승인 전 수행하지 않는다.

## 롤백

새 DB·API는 additive로 추가한다. 운영 전 문제가 발견되면 이 기능 커밋을 되돌려 신규 비밀번호 가입 폼만 기존 경로로 복구하며 기존 OAuth·미완료 계정과 사용자 데이터는 삭제하지 않는다. 사용하지 않는 런타임 기능 플래그를 별도로 남기지 않는다.

2026-10-14 후속 검수에서 Preview Supabase에 challenge migration과 선행 문자 발송 제한 객체를 적용했고, 15분 주기 개인정보 정리 Cron의 실제 성공 실행과 WebKit 18개 회원가입 시나리오를 확인했다. Preview 브라우저 요청이 challenge 실패 상태로 안전하게 기록되는 공급자 경계도 확인했다. SOLAPI 인증정보와 등록 발신번호가 없으므로 실문자 발송과 성공 가입 정합성은 아직 출시 차단 조건으로 남는다.

DB 롤백 전에는 `select cron.unschedule('redact-anonymous-signup-phone-challenges');`로 예약 작업을 해제한다. 실제 롤백은 적용 migration과 데이터 존재 여부를 확인한 뒤 수행하며, `pg_cron` 확장 자체는 다른 작업이 사용할 수 있으므로 자동 삭제하지 않는다.
