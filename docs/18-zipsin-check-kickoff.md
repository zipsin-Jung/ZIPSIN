# 집신체크 서브서비스 킥오프

작성일: 2026-10-13

상태: 기획 제안 · 사용자 승인 대기 · 구현 전

## 1. 한 문장 정의

**집신체크는 집을 보러 갈 때 놓치지 않게 확인하고, 보고 온 집을 같은 기준으로 비교한 뒤, 선택한 집의 기록을 입주와 퇴거까지 이어 주는 집신의 서브서비스다.**

사용자 표기는 `집신체크 | 집신의 집보기·입주·퇴거 체크`를 권고한다. 별도 회원 서비스가 아니라 집신 계정 하나로 이용한다.

## 2. 확인한 근거와 현재 상태

- 집신은 계약 전부터 입주·거주·수리·관리·퇴거까지 기록을 집 한 채 기준으로 연결한다.
- Google Drive의 과거 논의에서도 체크리스트를 별도 할 일 앱이 아니라 사진·문서·메모 기록을 만드는 입구로 두기로 했다.
- 현재 저장소는 Next.js App Router 기반 랜딩과 클릭형 데모이며 실제 계정·DB·파일 저장은 아직 없다.
- HUG 안심전세 서비스는 전세계약을 계약 전·중·후로 나누어 권리관계, 임대인 확인, 임대차 신고, 전입신고와 보증 가입 등의 확인을 안내한다.
- 주택 유형에 따라 확인할 권리관계가 다르므로 모든 집에 같은 위험 점수를 적용하면 안 된다.

## 3. 사용자 문제와 가치

### 1차 사용자

전·월세 집을 보러 다니는 예비 임차인, 특히 첫 독립이나 이사를 준비하며 무엇을 확인해야 할지 모르는 사람.

### 문제

- 현장에서 확인할 항목을 빠뜨린다.
- 집마다 메모 방식이 달라 나중에 비교하기 어렵다.
- 기억에 의존해 채광, 소음, 곰팡이, 수압과 관리 상태를 판단한다.
- 집을 선택한 뒤에도 현장 메모와 사진이 입주 기록으로 이어지지 않는다.

### 제공 가치

`놓치지 않게 확인 → 같은 기준으로 비교 → 다시 물어볼 항목 정리 → 선택한 집의 입주·퇴거 기록으로 전환`

## 4. 권고하는 첫 MVP

1. 비회원이 `집 보러 가기` 체크를 시작한다.
2. 거래유형과 주택유형에 맞는 필수 10~15개 항목을 확인한다.
3. 각 항목을 `확인됨 / 주의 / 확인 못함 / 전문가 확인 필요`로 기록한다.
4. 사진 없이도 완료할 수 있고 필요한 항목에만 사진·메모를 붙인다.
5. 방문 직후 장점, 주의, 다시 물어볼 것, 확인 못한 것을 요약한다.
6. 후보 2~3채를 같은 축으로 비교한다.
7. 기기 간 저장 또는 장기 비교가 필요할 때 집신 가입을 안내한다.
8. 최종 선택한 집만 사용자 동의를 거쳐 집신의 입주 기록으로 전환한다.

입주·퇴거 체크리스트는 같은 구조로 설계하되, 첫 공개 MVP에서는 콘텐츠 예고 또는 후속 단계로 둔다.

## 5. 보고서 원칙

사용자의 ‘신용카드 분석처럼’이라는 표현은 **정보를 한눈에 정리하는 경험**으로 해석한다. 신용등급처럼 집의 안전을 단일 숫자나 A/B/C로 판정하지 않는다.

- 치명적인 계약·권리·안전 항목은 다른 장점으로 상쇄하지 않는다.
- 사용자 관찰, 중개인 설명, 공식 서류 확인, 전문가 확인을 구분한다.
- 결과에는 근거, 확인일과 미확인 항목을 함께 표시한다.
- `안전한 집`, `하자 없음`, `계약해도 됨`, `보증금 안전 보장` 같은 표현을 쓰지 않는다.
- 법률 자문, 구조·전기·가스 안전진단이나 하자 책임 판정을 대신하지 않는다.

## 6. 브랜드와 기술 구조 선택지

### A. 같은 앱의 `/check`에 통합 — 추천

- 집신 단일 계정, 디자인, 권한과 운영을 그대로 쓴다.
- 후보집 개인 기록은 장기 집 이력과 별도 데이터로 보관한다.
- 유입이 검증되면 같은 앱을 유지한 채 `check.zipsin.net` 진입 주소를 추가할 수 있다.

### B. `check.zipsin.net` 별도 프런트 앱

캠페인 운영은 독립적이지만 로그인, 쿠키, 공통 화면과 배포 관리가 복잡해진다.

### C. 별도 앱·별도 DB·중앙 계정 연동

조직이 큰 장기 구조에는 의미가 있지만 현재 단계에는 지나치게 복잡하고 ‘가입은 하나’라는 원칙을 깨뜨릴 위험이 크다.

## 7. 개인정보와 권한 기본값

- 비회원 체험은 기기 안의 임시 기록으로 시작하고 서버에는 저장하지 않는다.
- 정확한 주소 대신 `후보 A`, `성수동 원룸` 같은 별칭으로도 사용할 수 있게 한다.
- 주소만 같다고 기존 집신 기록이나 다른 방문자의 기록을 보여주지 않는다.
- 후보집 사진·메모는 본인만 보는 것이 기본이며 사무소나 임대인에게 자동 공유하지 않는다.
- 현관 비밀번호, 열쇠 위치와 같은 안전정보는 입력을 금지하거나 강하게 경고한다.
- 얼굴, 우편물, 차량번호, 계약서와 사진 위치정보 노출을 경고하고 EXIF 제거를 검토한다.
- 선택한 집으로 전환할 때도 현재 집·계약 관계를 확인하고 사용자가 선택한 기록만 옮긴다.
- 후보집 보존기간, 삭제, 내보내기와 마케팅 활용 동의는 집신 장기 기록과 별도로 결정한다.

## 8. MVP에서 제외

- AI 하자·안전 판정
- 등기부·건축물대장 자동 분석
- 매물 추천과 중개
- 보증금 반환 또는 계약 안전 보장
- 실계약·전자서명
- 공개 집 리뷰, 임대인 또는 중개사 등급
- 자동 PDF 공유, 수리 견적·결제

## 9. 사용자에게 받을 정보

아래 여섯 가지면 1차 제품 명세와 화면 흐름을 만드는 데 충분하다.

1. 첫 대상: 전세, 월세, 매매 중 무엇을 먼저 할지
2. 첫 주택 유형: 원룸, 빌라, 아파트, 오피스텔 중 무엇을 먼저 할지
3. 실제 집을 볼 때 놓쳤거나 후회한 사례 3개
4. 집끼리 비교할 때 가장 중요한 기준 5개
5. 주 유입 광고 채널: 인스타그램, 네이버, 카카오 등
6. 첫 체크 후 저장할 때 가입시키는 방식에 대한 의견

있으면 더 좋은 자료는 개인정보를 지운 실제 메모, 체크리스트, 현장 사진 예시, 계약 전 질문 목록, 입주·퇴거 분쟁 사례와 원하는 브랜드 문구다. 없어도 가상 사례로 다음 설계를 시작할 수 있다.

## 10. 성공 지표와 검증

- 예비 임차인 5명 이상 현장 사용 관찰
- 최근 이사자 5명 인터뷰
- 공인중개사 3명 항목과 표현 검토
- 체크 완료율, 평균 소요시간, 중단 지점
- 후보 2채 이상 비교율
- 저장을 위한 실제 가입 전환율
- 선택한 집의 입주 기록 전환율과 7일 재방문율
- 점수·주의 표현을 안전 또는 법률 보증으로 오해한 사례 0건

## 11. 승인 게이트와 다음 순서

1. **방향 승인:** 이름, 1차 사용자, 집 보기 중심 MVP, 상태형 비교와 가입 시점
2. **기획 승인:** 요구사항 ID, 공식 근거가 연결된 체크 항목, 모든 화면 상태와 문구
3. **개인정보 승인:** 주소·사진·메모의 목적, 보존, 삭제, 공유와 집신 전환 규칙
4. **프로토타입 검증:** 실제 현장 완주, 오인 여부와 모바일 사용성 확인
5. **구현 승인:** 승인된 요구사항과 수락기준을 기준으로 실제 Next.js App Router에 구현
6. **공개 승인:** 약관·처리방침·삭제 요청·운영 문의·롤백과 실제 브라우저 검수 확인

현재 판정은 **조건부 킥오프 완료, 사용자 방향 승인 대기, 구현 미승인**이다.
