```text
집신(ZIPSIN) 기존 프로젝트를 이어서 “계약 후부터 만기까지 사용하는 집 중심 웹앱”으로 완성해 주세요.

새 프로젝트를 만들지 마세요. 기존 Next.js App Router 코드, Supabase 스키마와 RLS, 채팅, 첨부파일, 문서, 테스트와 Git 기록을 보존하세요. 현재 구현과 승인 문서를 먼저 감사하고, 존재하는 기능은 재사용하며, 남은 기능만 테스트 우선으로 개발하세요.

이번 작업은 단순한 대시보드 디자인 변경이 아닙니다. 가입 후 사용 목적 선택, 집 연결, 계약 기간, 사진·문서·일정·채팅·관계자와 만기 준비를 하나의 집 흐름으로 연결하는 구조 변경입니다. 사용자 승인 전에는 제품 코드를 수정하지 말고, 먼저 명세와 단일 권장 시안을 제출하세요.

────────────────────────────────────────
1. 변하지 않는 제품 정의
────────────────────────────────────────

집신은 집에 관한 일의 반복·누락·단절을 막는 집 중심 기록·업무 관리 서비스입니다.

계약서, 사진, 대화, 일정과 집에서 있었던 일을 “집 한 채”와 “현재 계약”에 연결합니다. 사람이나 담당자가 바뀌어도 허용된 집 이력은 이어지고, 이전 계약자의 개인정보와 개인 대화는 다음 계약으로 넘어가지 않아야 합니다.

초기 결제 고객은 공인중개사무소이지만 공인중개사 전용 서비스가 아닙니다. 임차인, 임대인, 대표·소속공인중개사·중개보조원, 수리기사·가족·건물관리자 등 초대받은 관계자가 같은 집 중심 제품을 서로 다른 권한으로 사용합니다.

수리는 집에서 발생하는 여러 사건 중 하나일 뿐입니다. 집신을 수리 중개, 임대료 수납, 세금, 시세, 매물 광고 중심 서비스로 바꾸지 마세요.

제품 핵심 문장:

“부동산 계약했다면, 이제 만기까지 집신으로.”

보조 문장:

“계약서, 사진, 대화와 일정을 집 한 채에 이어서 기록하고, 지금 무엇을 준비해야 하는지 순서대로 확인하세요.”

보조 브랜드 문장:

“기록으로 신뢰를 쌓아가는 집신.”

절대 표현 금지:

- “집신에게 맡기면 모든 문제가 해결됩니다.”
- “대화가 법적 증거가 됩니다.”
- “퇴거 버튼을 누르면 해지 통보가 됩니다.”
- “사진만 찍으면 모든 정보가 자동 등록됩니다.”
- “계약서를 찍으면 법률 검토가 완료됩니다.”

집신은 기록과 준비를 돕지만, 계약 당사자나 법률·부동산 전문가의 책임을 대신하지 않습니다.

────────────────────────────────────────
2. 역할별로 즉시 느껴야 하는 가치
────────────────────────────────────────

[사회초년생·임차인]

문제:
- 계약 후 무엇을 보관하고 언제 무엇을 해야 하는지 모릅니다.
- 계약서는 집 서랍에 있고 입주 사진은 개인 사진 속에 섞입니다.
- 수리 요청과 만기 준비를 누구에게 언제 말했는지 기억하기 어렵습니다.

집신 가치:
- 계약서, 입주 상태, 수리 요청, 만기 준비를 한 집에서 확인합니다.
- 지금 필요한 행동을 한 번에 최대 3개만 알려줍니다.
- 외부에서도 권한 있는 계약 기록과 날짜를 확인합니다.

사용자 문구:

“첫 계약이라 무엇이 중요한지 모르겠다면, 집신이 만기까지 필요한 순서를 알려드려요.”

[공인중개사무소]

문제:
- 중개 이후에도 사진 찾기, 반복 설명, 수리 연락, 일정 확인과 인수인계가 이어집니다.
- 직원 개인 휴대전화와 컴퓨터 폴더에 자료가 흩어집니다.

집신 가치:
- 여러 집의 계약·사진·일정·대화를 집별로 이어서 확인합니다.
- 반복 문의와 현장 확인을 줄이고 중개 업무에 집중합니다.
- 직원이 바뀌어도 사무소의 집 기록과 다음 일이 이어집니다.

사용자 문구:

“중개사는 중개에 집중하세요. 집마다 반복되던 연락과 기록은 집신에서 이어집니다.”

‘잔심부름’이라는 표현은 내부 문제 정의에는 사용할 수 있지만, 임대인·임차인을 탓하는 느낌이 있으므로 기본 제품 문구에는 사용하지 마세요.

[임대인]

문제:
- 여러 집의 사진·계약·수리·연락이 섞입니다.
- 직접 방문하지 않으면 현재 상태와 진행 상황을 알기 어렵습니다.

집신 가치:
- 집마다 계약, 사진, 변경, 비용 자료와 일정을 구분합니다.
- 어떤 집에서 무엇이 진행 중인지 한눈에 확인합니다.
- 임차인·중개사·수리기사와 허용된 기록을 함께 봅니다.

사용자 문구:

“여러 집의 계약과 변화를 헷갈리지 않게, 한 집씩 한눈에 확인하세요.”

[관리·기타]

문제:
- 수리기사, 가족, 건물관리자마다 필요한 자료와 기간이 다른데 연락은 개인 전화에 흩어집니다.

집신 가치:
- 초대받은 집에서 허용된 사건·사진·일정·대화만 확인합니다.
- 개인 연락처를 기본 공개하지 않고 집신 안에서 연락합니다.

────────────────────────────────────────
3. 네 개의 쉬운 시작 입구와 실제 권한 분리
────────────────────────────────────────

가입과 휴대전화 인증 후 다음 질문을 한 번 보여주세요.

“집신을 주로 어떻게 사용하시나요?”

선택 카드:

1) 임차인
“계약서와 입주 상태, 수리 요청, 만기 준비를 기록해요.”

2) 임대인
“계약과 집 상태, 수리 과정, 만기 일정을 확인해요.”

3) 공인중개사
“여러 집의 계약·사진·일정·대화를 집별로 이어가요.”

4) 관리·기타
“초대받은 집에서 허용된 기록과 할 일을 확인해요.”

반드시 카드 아래에 다음 안내를 표시하세요.

“이 선택은 화면 안내를 맞추기 위한 것입니다. 집 기록은 집을 만들거나 보안 초대를 수락한 뒤에만 볼 수 있습니다.”

네 선택을 하나의 영구 권한 enum으로 평탄화하지 마세요.

- 공인중개사 선택 후: 대표 개업공인중개사 / 소속공인중개사 / 중개보조원을 사무소 참여 단계에서 구분
- 관리·기타 선택 후: 수리기사 / 가족·대리인 / 건물관리자 / 기타 협력자를 다시 구분
- 한 사람은 집마다 관계가 다를 수 있음
- 역할 선택만으로 기존 집, 계약서, 사진, 채팅 접근을 허용하지 않음
- 실제 접근은 사무소 멤버십, 집·계약 관계, 초대 수락, 기간과 범위로 결정

관리·기타 최소 권한 예시:

- 수리기사: 지정된 수리 사건, 필요한 사진·일정·대화만; 자동 만료 필수
- 가족·대리인: 초대한 사람이 선택한 집과 기능만
- 건물관리자: 위임받은 건물·호실과 관리 범위만
- 기타 협력자: 기본 거부, 초대 시 명시한 항목만

────────────────────────────────────────
4. 첫 집 연결 원칙
────────────────────────────────────────

주소 입력만으로 기존 집 기록을 열지 마세요. 동일 주소의 기록이 있더라도 자동 연결하거나 검색 결과로 노출하지 마세요.

권고 구조:

- 대표 공인중개사: 사무소를 만든 뒤 사무소 집 공간을 등록
- 소속공인중개사·중개보조원: 사무소 초대를 수락한 뒤 허용된 집 확인
- 임대인·임차인: 받은 보안 초대를 수락하거나 본인만 볼 수 있는 개인 시작 공간 생성
- 관리·기타: 반드시 유효기간이 있는 초대를 통해 연결

개인 시작 공간은 주소가 같다는 이유로 기존 공유 집 기록과 합쳐지지 않습니다. 나중에 관계 확인과 사용자 승인을 거쳐 연결하는 구조를 사용하세요. 중복 집을 자동 병합하지 마세요.

집 연결 후 최소 입력:

- 집 별칭
- 주소
- 동·호 등 상세 식별정보
- 이 집과의 관계
- 계약 시작일
- 계약 만기일
- 집 만들기 또는 초대 수락 근거

계약서 사진에서 날짜를 자동 추출하거나 확정하지 마세요. MVP에서는 사용자가 날짜를 직접 입력하고 확인합니다.

────────────────────────────────────────
5. 계약 후부터 만기까지 네 단계
────────────────────────────────────────

각 기능을 모두 전역 메뉴로 만들지 마세요. 선택한 집 안에서 다음 네 단계를 하나의 시간 흐름으로 보여주세요.

1) 계약 보관
- 계약서 사진 또는 PDF
- 건축물대장, 등기사항증명서 등 사용자가 직접 올린 참고 서류
- 계약 시작일, 만기일
- 중요 특약 메모

2) 입주 기록
- 입주 전·입주 시 상태 사진
- 도배·장판·시설 상태
- 계량기 등 사용자가 남기기로 선택한 기록

3) 거주·관리
- 수리·변경 기록
- 주요 설비 정보
- 수리 일정과 전·중·후 사진
- 영수증·고지서
- 집 채팅

4) 만기·퇴거
- 만기 D-day
- 만기 뒤 계획
- 연장 준비 또는 퇴거 준비 행동
- 퇴거 상태 사진
- 선택한 기록 확인

한 화면에는 지금 필요한 행동을 최대 3개만 추천하세요. 모든 단계를 같은 강도의 큰 카드로 펼치지 마세요.

6. 홈 화면 최우선 정보
────────────────────────────────────────

[한 집을 사용하는 사용자]

상단 첫 화면에서 다음을 3초 안에 확인해야 합니다.

집신아파트 1401호
서울 노원구 · 주소 일부 마스킹

계약 만기 D-112
2027년 2월 2일

만기 뒤 계획을 정하면 필요한 준비 순서를 알려드려요.

[연장 생각 중] [퇴거 준비] [아직 결정 전]

버튼은 둥근 상태 선택 상자 형태로 만들되, 가장 위험한 의미 오해를 막기 위해 다음 안내를 가까이 표시하세요.

“이 선택은 집신 안에서 준비 순서를 정하기 위한 것입니다. 계약 연장이나 퇴거 통지가 자동으로 전달되지는 않습니다.”

실제로 다른 관계자에게 알릴 때는 별도의 `관계자에게 알리기` 확인 단계를 둡니다.

`퇴거 / 연장` 두 가지로만 강요하지 마세요. 기본값은 `아직 결정 전`입니다.

임대인과 임차인의 계획 상태는 각각 보존합니다. 한 사람이 선택한 상태가 다른 사람의 상태를 덮어쓰지 않아야 합니다. 서로 다르면 `서로 확인이 필요해요`라고 표시합니다.

공인중개사는 당사자의 계획을 임의 변경하지 않습니다. 위임받아 대신 기록한다면 누가 누구를 대신해 언제 기록했는지 감사 이력을 남깁니다.

[여러 집을 관리하는 사용자]

공인중개사와 다주택 임대인은 전체 집 업무 홈을 먼저 봅니다.

우선순위:

1) 오늘 확인할 집
2) 만기 임박 집
3) 답변을 기다리는 집
4) 가까운 일정
5) 최근 사용한 집

집을 선택하면 동일한 `집 이름 + D-day + 계획 + 다음 행동` 집 홈으로 진입합니다. 마지막으로 본 집을 유지하되 언제든 `전체 집`으로 돌아갈 수 있게 합니다.

[집 홈 본문 순서]

1) 지금 할 일 — 최대 3개
2) 집의 시간 — 계약 보관 → 입주 기록 → 거주·관리 → 만기·퇴거
3) 가까운 일정
4) 최근 사진·문서
5) 읽지 않은 집 채팅
6) 이 집 사람들

기능 목록보다 다음 행동을 먼저 보여주세요.

7. 문서와 PDF
────────────────────────────────────────

MVP에서 구현할 것:

- 계약서·고지서·영수증 사진 직접 업로드
- JPEG·PNG·HEIC·PDF 등 승인 형식 업로드
- 집과 현재 계약에 연결
- 문서 종류 선택
- 촬영일 또는 문서일을 사용자가 확인
- 업로드 일시와 등록자 표시
- 권한 있는 사용자만 열람
- 비공개 저장소, RLS, 짧은 만료시간 signed URL
- 파일 크기·MIME·확장자 검증과 실패 안내

문서 유형 예시:

- 계약서
- 건축물대장
- 등기사항증명서
- 고지서
- 영수증
- 설비 자료
- 기타

사용자가 올린 참고 서류를 집신이 최신·진본·법적 유효성이 확인된 공식 문서처럼 표현하지 마세요.

반드시 구분:

- 지금: PDF 파일 업로드·보관·열람
- 나중: 여러 사진·문서·대화·일정을 선택해 하나의 PDF로 정리·내보내기

PDF 내보내기는 이번 MVP의 완료 기능처럼 보이지 않게 `준비 중` 문구도 남발하지 말고, 실제 구현 전에는 버튼을 숨기세요.

────────────────────────────────────────
8. 사진과 즉시 업데이트의 정확한 뜻
────────────────────────────────────────

“사진만 찍으면 자동 업데이트”를 무단 자동 수집·자동 공개로 구현하지 마세요.

MVP 흐름:

1) 사용자가 집 화면 또는 집 채팅에서 촬영·업로드
2) 시스템이 현재 집, 작성자, 서버 시각을 자동 입력
3) 사용자가 `채팅에만 보내기` 또는 `집 기록에도 남기기` 선택
4) 기록으로 남길 때 종류와 공개 범위 확인
5) 저장 성공 후 해당 집의 시간선과 최근 기록이 즉시 갱신

집 채팅 안에서는 현재 집을 미리 선택할 수 있지만, 기록 저장과 공개 범위는 사용자가 확인해야 합니다.

사진 분류 예시:

- 입주 전 상태
- 현재 상태
- 수리 전
- 수리 중
- 수리 후
- 퇴거 상태
- 주요 설비
- 영수증·문서

사진 촬영일은 EXIF가 있으면 제안할 수 있으나 사용자가 확인·수정할 수 있게 하세요. EXIF를 계약상 확정 날짜처럼 사용하지 마세요.

사진은 촬영일 기준 시간선에 자동 표시할 수 있습니다. 하지만 모든 사진을 캘린더 일정으로 만들지 마세요. 캘린더에는 행동과 기한이 있는 날짜만 표시합니다.

금지:

- 휴대전화 사진첩 백그라운드 수집
- AI가 다른 집을 추정해 자동 저장
- 채팅 사진을 동의 없이 집 장기 이력으로 승격
- 얼굴·계약서·계좌정보 자동 공개
- AI 분류 결과 자동 확정

후속 자동화는 `자동 확정`이 아니라 `저장 제안`부터 시작합니다.

────────────────────────────────────────
9. 집 캘린더와 알림
────────────────────────────────────────

집 캘린더에 다음을 함께 표시합니다.

- 계약 시작
- 계약 만기
- 입주
- 퇴거
- 수리 방문
- 일반 집 일정

계약일·만기일·수리 방문일 등 사용자가 저장하고 확인한 날짜만 일정으로 사용하세요. 계약서 OCR이나 사진 분석값을 자동 확정하지 마세요.

MVP 알림:

- 새 집 채팅
- 초대 도착·수락
- 일정 변경
- 만기 임박
- 본인이 참여한 기록 변경

앱 안 알림과 브라우저·모바일 푸시 알림을 구분하세요. MVP에서 실제 지원하는 채널만 표시하고, 운영체제 알람을 지원하지 않으면 `알람`이라고 부르지 마세요.

만기 알림 시점은 설정 가능한 정책으로 설계하되, 임의의 날짜를 법정 통보기한처럼 표현하지 마세요.

────────────────────────────────────────
10. 집 채팅과 대화 기록
────────────────────────────────────────

채팅방은 사람 중심이 아니라 집·계약·사건 중심입니다.

방 유형:

- 현재 계약 대화
- 사무소 내부 대화
- 수리 사건 대화
- 집신 고객지원

기본 기능:

- 텍스트 메시지
- 사진·PDF 첨부
- 집 기록 또는 일정 링크 공유
- 읽음 상태
- 신고·차단
- 관계 종료 시 신규 메시지 차단
- 현재 계약이 끝나면 이전 임차인 대화를 다음 임차인에게 숨김

대화를 “법적 증거”라고 보장하지 마세요. 제품 문구는 다음처럼 사용합니다.

“집과 계약에 연결된 대화를 다시 찾을 수 있게 기록합니다.”

보존해야 할 최소 메타데이터:

- 서버 기준 작성시각
- 작성자 식별자
- 집·계약·대화방 관계
- 첨부 식별자
- 수정·철회 이력

메시지를 수정할 때 원문을 덮어쓰지 않는 변경 이력 방식을 검토하세요. 철회는 완전 삭제처럼 위장하지 말고 `철회된 메시지` 상태와 정책을 정의하세요. 보관기간, 탈퇴 후 열람, 법적 요청 대응은 별도 개인정보·법률 검토 전 임의 확정하지 마세요.

나중:

- 선택 대화 PDF 내보내기
- 외부 메시지·사진의 동의 기반 기록 제안
- AI 대화 요약

────────────────────────────────────────
11. 집신 주소록 = 이 집 사람들
────────────────────────────────────────

휴대전화 주소록 전체를 가져오지 마세요. 전역 사용자 검색도 만들지 마세요.

사용자 화면 이름은 `이 집 사람들`로 하고, 보조 설명에서 `집신 주소록`이라고 표현할 수 있습니다.

표시 대상:

- 현재 집·계약·사무소에서 유효한 관계가 있는 사람
- 수락된 초대 관계
- 아직 유효한 수리 사건 참여자

표시 정보:

- 표시 이름
- 이 집과의 관계
- 참여 상태
- 접근 종료일
- 집신 채팅 버튼

기본적으로 표시하지 않을 정보:

- 개인 전화번호
- 이메일
- 로그인 아이디
- 휴대전화 전체 연락처
- 다른 집과의 관계

문구:

“이 집과 연결된 사람만 표시됩니다. 개인 연락처는 서로 동의한 경우에만 공유합니다.”

외부 연락을 기술적으로 막거나 `집신으로만 연락해야 한다`고 강요하지 마세요. 가치는 다음처럼 표현합니다.

“개인 연락처를 공유하지 않고 집신 안에서 집 관련 대화를 이어가세요.”

관계가 끝나면 새 메시지와 프로필 접근을 막고, 기록 보존 범위는 승인된 정책에 따릅니다.

────────────────────────────────────────
16. 수용 기준
────────────────────────────────────────

- 사용 목적 네 분류만으로 집 접근 권한이 생기지 않는다.
- 공인중개사와 관리·기타는 실제 세부 역할·관계를 다시 확인한다.
- 주소만으로 기존 집 기록이 검색·공개·병합되지 않는다.
- 홈 상단에서 현재 집, 만기일, D-day, 만기 뒤 계획을 3초 안에 확인한다.
- 만기일이 없으면 거짓 D-day 대신 입력 안내를 표시한다.
- 만기가 지났으면 D+숫자를 표시한다.
- 계획 선택에는 `아직 결정 전`이 있다.
- 계획 선택이 법적 통지나 계약 변경이 아님을 가까이 표시한다.
- 임대인과 임차인의 계획을 각각 저장하고 서로 덮어쓰지 않는다.
- 추천 행동은 최대 3개만 노출한다.
- 사진과 PDF는 사용자가 직접 업로드한다.
- 업로드 후 사용자가 분류와 공개범위를 확인한다.
- 모든 기록·문서·일정·채팅은 집 ID와 허용된 권한 공간에 연결된다.
- 사진 촬영일은 시간선에 반영할 수 있지만 모든 사진을 일정으로 만들지 않는다.
- 집신 주소록에는 유효한 관계만 보인다.
- 전화번호와 이메일은 동의 없이 표시하지 않는다.
- 관계 종료 즉시 신규 접근과 채팅 발송을 차단한다.
- 이전 임차인의 개인정보와 대화가 다음 임차인에게 보이지 않는다.
- 비공개 파일은 public URL로 노출되지 않는다.
- 교육·예시 데이터는 실제 고객 데이터처럼 표현하지 않는다.
- 자동이 아닌 기능을 자동이라고 표현하지 않는다.
```

## 공식 자료에 따른 표현 주의

- 전자문서는 전자적 형태라는 이유만으로 효력이 부인되지는 않지만, 모든 채팅이나 출력 PDF의 증거력·진정성이 자동 보장되는 것은 아니다. 집신은 `법적 증거 보장`이 아니라 작성자·시각·관계·변경 이력이 연결된 기록으로 설명한다. 국가법령정보센터, 전자문서 및 전자거래 기본법: https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1030749019
- 연락처를 수집·연동·제공하는 기능은 처리 목적·항목·기간·거부권 등 개인정보 처리 범위를 명확히 해야 한다. 따라서 MVP는 휴대전화 주소록 자동 수집이 아니라 승인된 집 관계 목록으로 제한한다. 국가법령정보센터 개인정보 동의 해석례: https://www.law.go.kr/expcInfoP.do?expcSeq=326221
