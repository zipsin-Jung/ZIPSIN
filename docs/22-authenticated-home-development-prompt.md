2. 집신의 변하지 않는 정의
────────────────────────────────────────

집신은 집에 관한 일의 반복·누락·단절을 막는 집 중심 기록·업무 관리 서비스입니다.

사진, 문서, 대화, 일정과 집에서 있었던 일을 “집 한 채”를 기준으로 연결합니다. 사람이나 담당자가 바뀌어도 필요한 기록과 다음 행동이 이어져야 합니다.

초기 결제 고객은 공인중개사무소이지만 공인중개사 전용 서비스가 아닙니다. 대표 개업공인중개사, 소속공인중개사, 중개보조원, 임대인, 임차인이 같은 집 중심 제품을 권한에 맞게 사용합니다.

집신은 수리 중개 플랫폼이 아닙니다. 수리는 집에서 발생하는 여러 기록 중 하나입니다. 시세·세금·월세 수납 중심 자산관리 서비스도 아닙니다.

역할이 가능한 행동을 정하고, 사무소·집·계약과의 현재 관계가 접근할 집을 정하며, 기간과 공유 범위가 실제로 볼 수 있는 자료를 제한합니다.

주소나 집 ID를 안다고 기록을 볼 수 없어야 합니다. 이전 임차인의 개인정보는 다음 임차인에게 자동으로 넘어가면 안 됩니다. 접근 권한이 끝나도 집과 사무소의 업무 기록 자체는 안전하게 남아야 합니다.

────────────────────────────────────────
3. 현재 문제와 이번 성공 기준
────────────────────────────────────────

현재 로그인 홈의 문제는 다음과 같습니다.

- 큰 홍보 문구와 그라데이션이 첫 화면을 차지해 로그인 후 해야 할 일이 보이지 않습니다.
- 글과 비슷한 크기의 카드가 반복되어 어디부터 봐야 하는지 알기 어렵습니다.
- 실제 사진, 문서, 최근 기록과 다음 행동이 눈에 보이지 않습니다.
- 글자만 크게 만들어 정보가 더 많고 무거워 보입니다.
- 집신의 페인 포인트와 “사진첩이 아니라 집에 기록한다”는 아하 모먼트가 없습니다.
- 첫 사용자와 기록이 쌓인 사용자가 같은 설명 화면을 봅니다.

이번 작업의 성공 기준은 다음과 같습니다.

- 로그인 후 3초 안에 현재 선택한 집, 지금 할 일, 다음 행동을 알 수 있습니다.
- 첫 사용자는 한 번에 해야 할 행동 하나만 강하게 봅니다.
- 사용자는 체크하듯 집의 기록을 하나씩 준비하되, 완료는 실제 저장 데이터로만 계산됩니다.
- 기록이 쌓인 사용자는 교육 화면이 아니라 최근 집·최근 기록·채팅·일정을 먼저 봅니다.
- 공인중개사는 여러 집을 노트북에서 빠르게 이동할 수 있고, 임대인·임차인은 관계 있는 집만 같은 구조로 봅니다.
- 사진은 장식이 아니라 “무엇이 기록되어 있는지”를 보여주는 증거가 됩니다.
- 데스크톱과 모바일이 같은 서비스이되 각 화면 크기에 맞는 내비게이션을 사용합니다.

────────────────────────────────────────
4. 핵심 설계 원칙: 공통 셸 + 상태별 점진 공개
────────────────────────────────────────

역할별로 서로 다른 앱을 만들지 마세요. 모든 사용자가 동일한 집 중심 앱 셸을 사용하되, 권한과 실제 데이터 상태에 따라 행동과 내용만 달라지게 하세요.

홈을 반드시 다음 세 상태로 분리하세요.

[상태 A: 집이 아직 없음]
- 큰 빈 대시보드 여러 개를 보여주지 않습니다.
- 교육용 문제 이미지 1장, 질문 1개, 해결 문장 1개, 기본 CTA 1개만 강하게 보여줍니다.
- 대표 공인중개사에게 사무소 설정이 필요하면 “사무소 만들기”를 우선합니다.
- 초대받아 들어오는 구성원·임대인·임차인에게는 “받은 초대 확인”을 우선합니다.
- 새 집을 만들 권한이 있는 사람에게만 “집 등록하기”를 보여줍니다.
- 다음에 준비할 6가지 기록은 작은 미리보기로만 보여줍니다.

[상태 B: 집은 있으나 기록이 적음]
- 선택한 집, 실제 대표 사진 또는 중립적인 “사진 없음” 표지를 보여줍니다.
- “이 집의 기록을 준비해 보세요” 체크리스트 6개를 보여줍니다.
- 한 번에 다음 미완료 항목 하나만 가장 강하게 강조합니다.
- 각 항목에 작은 “왜 필요한가요?” 상세 설명을 제공합니다.
- 최근 실제 기록을 함께 보여줍니다.
- 교육용 이미지는 현재 선택한 미완료 항목과 관련될 때만 제한적으로 보여줍니다.

[상태 C: 기록이 쌓임]
- 교육용 문제 이미지를 큰 영역에서 제거하거나 작은 도움말로 축소합니다.
- 오늘 이어서 할 실제 일 최대 3개를 우선합니다.
- 최근 변경된 집, 최근 기록, 읽지 않은 집 채팅, 가까운 일정을 보여줍니다.
- 체크리스트는 축약된 완료 상태와 다음 미완료 항목만 보여줍니다.
- 매번 같은 서비스 소개를 읽게 하지 않습니다.

상태 전환 기준은 하드코딩한 가짜 숫자가 아니라 실제 집·기록·관계·채팅·일정 데이터로 계산하세요. 기준을 코드와 문서에 명시하고 테스트하세요.

6. 집 기록 준비 체크리스트
────────────────────────────────────────

첨부 시안의 0/24 계약 전 체크리스트를 그대로 구현하지 마세요. 현재 MVP의 체크리스트는 사용자를 심사하거나 집을 평가하는 기능이 아니라, 집신의 핵심 기록을 하나씩 준비하도록 돕는 시작 안내입니다.

기본 6항목:

1) 집 등록 또는 초대 연결
2) 입주·현재 상태 사진
3) 계약서와 중요한 날짜
4) 주요 설비 정보
5) 수리·변경 기록
6) 함께 확인할 사람 초대

각 항목은 다음 정보를 가져야 합니다.

- 짧은 이름
- 완료/미완료 상태
- 완료 근거가 되는 실제 데이터
- 왜 필요한가요?
- 무엇을 남기면 되나요?
- 개인정보 주의사항
- 다음 행동 CTA
- 사용 권한이 없을 때의 안전한 안내

완료 근거 예시:

- 집 연결: 현재 사용자가 접근 가능한 실제 home 관계가 있음
- 상태 사진: 해당 집에 ready 상태의 사진 기록이 있음
- 계약과 날짜: 허용된 계약 문서와 중요 일정 데이터가 있음
- 설비 정보: 허용된 설비 템플릿 또는 구조화 설비 기록이 있음
- 수리·변경: 해당 집의 실제 변경 또는 수리 기록이 있음
- 사람 초대: 현재 활성 관계 또는 수락된 초대가 있음

일반 메모를 설비 기록으로 잘못 세거나, 파일 하나만 올렸다고 계약서 항목을 완료 처리하지 마세요. 수동 체크만으로 100%가 되게 하지 마세요.

“왜 필요한가요?”는 `<details><summary>` 또는 동등하게 접근 가능한 UI로 구현합니다. 핵심 행동과 중요한 위험은 접어 숨기지 마세요. 짧고 보조적인 설명만 펼치게 합니다.

7. 이미지 적용 계획
────────────────────────────────────────

이미지는 두 종류를 명확히 분리하세요.

[A. 교육용 문제 이미지]

실제 고객 사진이나 실제 집 기록이 아닙니다. 첫 사용자에게 집신이 필요한 순간을 이해시키는 예시 장면입니다. 이미지 근처에 “예시 장면”이라고 표시합니다.

1) 흩어진 사진과 파일
- 경로: public/images/home-pain-scattered-records-v1.webp
- 위치: 상태 A의 기본 첫 장면, 상태 B에서 “입주·현재 상태 사진” 항목을 펼쳤을 때
- 장면: 노트북의 여러 집 폴더와 휴대전화의 개인 사진 사이에 집 사진이 뒤섞여 어느 집인지 바로 알기 어려운 한국 주거 생활 장면
- 질문: “이 사진, 어느 집에서 찍었는지 기억나세요?”
- 해결: “사진첩이 아니라 그 집에 기록하세요.”

2) 외출 중 필요한 종이 계약서
- 경로: public/images/home-pain-paper-contract-v1.webp
- 위치: “계약서와 중요한 날짜” 항목을 펼쳤을 때
- 장면: 밖에서 계약 만기일을 급하게 확인하려는 휴대전화와 집 서랍 속 종이 계약서의 대비
- 질문: “지금 계약 만기일이 필요한데, 계약서는 집 어디에 있나요?”
- 해결: “권한 있는 계약 기록을 밖에서도 바로 확인하세요.”

3) 확인하기 어려운 천장형 에어컨
- 경로: public/images/home-pain-ceiling-aircon-v1.webp
- 위치: “주요 설비 정보” 항목을 펼쳤을 때
- 장면: 천장형 에어컨의 모델명·설치일·수리업체를 바로 확인하기 어려운 상황
- 질문: “이 에어컨, 누가 설치하고 언제 수리했는지 기억나세요?”
- 해결: “제품·설치·수리·영수증을 이 집의 설비 기록에 남기세요.”

교육용 이미지 제작 공통 지침:

- 2026년형 한국 프롭테크의 따뜻하고 정돈된 에디토리얼 사진
- 한국 아파트·빌라에서 실제로 있을 법한 생활 장면
- 과도하게 완벽한 AI 인물, 광고 모델 포즈, 고급 주택 자랑, 수리업체 광고 느낌 금지
- 사람 얼굴, 실제 주소, 전화번호, 주민등록번호, 계좌번호, 계약 조건이 식별되지 않게 함
- 이미지 안에 글자, 버튼, 로고, 가짜 앱 화면을 생성하지 않음
- 따뜻한 자연광, 뉴트럴 아이보리·잉크 네이비·절제된 포레스트 그린과 어울리는 색감
- 데스크톱 16:10, 모바일에서는 중심 피사체를 잃지 않는 4:3 또는 1:1 크롭
- 장면마다 질문 하나만 시각적으로 전달
- 세 이미지의 렌즈, 광원, 색보정, 현실감이 한 시리즈처럼 일치

[B. 실제 사용자 기록 이미지]

- 집 카드: 권한 있는 실제 집의 최근 사진 1장
- 최근 기록: 실제 첨부 썸네일
- 문서 기록: 민감정보를 자동 노출하지 않는 안전한 문서 표지 또는 승인된 미리보기
- 입주·퇴거 비교: 같은 공간의 실제 전·후 사진
- 사진 없음: 중립적인 집 표지와 “사진 없음”; 가짜 집 사진을 붙이지 않음

실제 사진 표시 규칙:

- 로그인 세션과 RLS를 통과한 파일만 표시
- private bucket의 파일은 짧은 만료시간 signed URL 사용
- JPEG·PNG·WebP 등 승인 형식만 홈 썸네일로 사용
- 계약서 원본, 사람 얼굴, 연락처, 계좌정보가 포함된 이미지를 자동 대표사진으로 고르지 않음
- `next/image`를 사용해 width/height 또는 fill 컨테이너, 정확한 sizes, lazy loading, 오류 폴백을 제공
- 교육용 이미지와 실제 기록의 라벨·스타일을 구분
- 이미지가 실패해도 질문, 설명, CTA를 사용할 수 있게 함
- 텍스트를 이미지 안에 넣지 않고 HTML로 제공
- 정보 이미지에는 의미 있는 alt, 장식 이미지는 alt="" 사용

첨부된 손그림 시안과 기존 전체 화면 시안 이미지를 실제 제품 UI 안에 그대로 삽입하지 마세요. 이미지는 참고자료이고 결과 화면은 실제 HTML·CSS·React로 구성합니다.

## 사실·권고·미결정 구분

### 확인된 사실

- 현재 로그인 홈은 큰 마케팅 영역과 글 카드가 실제 업무보다 먼저 보인다.
- 최신 홈 재설계 명세와 구현 계획은 작성되어 있다.
- 교육용 이미지 세 장은 경로와 장면만 정해졌고 실제 파일은 아직 없다.
- 사용자 첨부 시안은 로그인 홈과 체크리스트의 직접 제작 참고안이다.

### 이번 문서의 권고

- 공통 앱 셸과 세 가지 데이터 상태로 복잡도를 단계적으로 공개한다.
- 데스크톱은 좌측 내비게이션을 쓰되 최상위 메뉴는 4개 중심으로 제한한다.
- MVP 체크리스트는 24개 검사표가 아니라 실제 기록 6개 준비 안내로 제한한다.
- 교육용 이미지와 실제 기록 이미지를 명확히 구분한다.

### 아직 사용자 승인 전인 결정

- 좌측 내비게이션 최종 시각 디자인
- 상태 B에서 교육 이미지와 체크리스트의 정확한 좌우 비율
- 집 선택기에서 보이는 주소 마스킹 형식
- 상태 A의 역할별 기본 CTA 최종 문구

### 이번에 만들지 않는 것

- 집신 AI
- 관리비 계산
- 집 찾기·매물 비교
- 계약 전 24개 법률·시설 검사표
- 사용자 정의 체크리스트
- Production 배포
