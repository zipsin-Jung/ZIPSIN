# 집신 배포 직전 완성 명세

- 작성일: 2026-10-13
- 상태: 사용자 원문 요구사항을 문서화한 검토본
- 기준 브랜치: `codex/public-v1-auth`
- 제품 기준: 집에 관한 일의 반복·누락·단절 방지

## 1. 목표와 범위

기존 Next.js App Router 프로젝트를 보존하면서 공개 홈페이지부터 가입, 집, 기록, 첨부, 채팅, 초대와 권한 종료까지 실제로 이어지는 Release Candidate를 만든다. 설명용 데모, 사전가입, 가짜 앱 다운로드와 실제로 작동하지 않는 화면은 범위에 포함하지 않는다.

Production 공개는 포함하지 않는다. 최종 산출물은 실제 데이터 왕복과 브라우저 검수를 거친 Vercel Preview, 추적표, 품질 보고서와 사용자 승인 목록이다.

## 2. 변하지 않는 제품 판단

> 집신은 집에 관한 일의 반복·누락·단절을 막는 서비스다.

- 사진·문서·대화·일정과 집에서 있었던 일을 `집 한 채`에 연결한다.
- 초기 결제 고객은 공인중개사무소이지만 공인중개사 전용 제품이 아니다.
- 임대인·임차인·공인중개사가 함께 사용한다.
- 수리는 집에서 발생하는 사건 중 하나이며 수리 중개가 제품 중심이 아니다.
- 시세·세금·임대료 수납 중심의 자산관리 서비스가 아니다.
- 주소 또는 내부 집 ID를 안다는 사실만으로 비공개 기록 접근 권한을 주지 않는다.
- 사람의 권한은 끝나도 집·사무소 업무 기록은 남는다.
- 이전 계약자의 개인정보는 다음 계약자에게 자동으로 전달하지 않는다.
- 별도 `담당자` 배정을 공식 흐름이나 접근 조건으로 사용하지 않는다.

## 4. 공개 홈페이지 설계

### 첫 화면

- 제목: `집에 관한 일, 다시 묻고 다시 찾지 않도록.`
- 설명: `계약서, 사진, 대화, 일정과 집에서 있었던 일을 집 한 채에 이어서 기록하세요.`
- 주 행동: `웹에서 시작하기` → `/signup`
- 보조 행동: `로그인` → `/login`
- 실제 앱의 집 타임라인 또는 다음 행동 UI를 HTML·CSS·React로 보여준다.

### 메뉴

`집신 소개 / 이런 순간에 집신 / 주요 기능 / 이용 방법 / 고객지원 / 로그인 / 웹에서 시작하기`

### 생활 사례 탐색

| CASE-ID | 상황 | 선택 후 보여줄 실제 UI | 막는 문제 |
|---|---|---|---|
| CASE-01 | 이사 온 집의 에어컨 고장 | 해당 집의 설치·이전 수리·연락 기록 타임라인 | 반복 |
| CASE-02 | 장기수선충당금 자료 확인 | 계약서·고지서·납부 자료 필터 결과 | 누락 |
| CASE-03 | 도배·장판 상태 확인 | 입주 전·현재 사진 비교와 촬영 시점 | 반복·분쟁 |
| CASE-04 | 외부에서 계약 확인 | 계약 문서와 만기일 요약 | 누락 |
| CASE-05 | 사무소 직원 변경 | 집별 최근 활동과 다음 할 일 | 단절 |
| CASE-06 | 퇴거 상태 확인 | 입주 사진·대화·변경사항·퇴거 상태 흐름 | 누락·단절 |

법적 결론을 내리거나 장기수선충당금 반환 가능 여부를 단정하지 않는다. 사례 UI는 설명용 숫자 성과가 아니라 실제 제품 구조를 보여주는 비식별 가상 데이터로만 구성한다.

### 다운로드 영역

실제 앱스토어 URL이 없을 때는 배지·QR·활성 CTA를 렌더링하지 않는다. 이후 URL을 연결할 수 있는 데이터 구조만 준비하며 현재 공개 화면에는 `앱 다운로드`를 약속하지 않는다.

## 5. 핵심 사용자 흐름

### FLOW-RC-01 가입부터 첫 기록

`공개 홈 → 회원가입 → 이메일/전화 확인 → 역할 선택 → 사무소 생성 또는 집 등록 가능 조건 안내 → 집 주소 등록 → 내부 집 ID 생성 → 첫 기록 → 사진/PDF 첨부 → 집 타임라인`

일반 역할이 집을 직접 생성할 수 없는 현재 정책을 유지한다면 화면에서 이유와 초대받기 경로를 명확히 안내해야 한다. 권한 정책을 임의로 넓히지 않는다.

### FLOW-RC-02 집 대화

`집 상세 → 집 대화 → 메시지/사진/PDF 전송 → 읽음 갱신 → 연결 끊김 후 재조회`

채팅 첨부는 첫 출시에서 집 기록으로 자동 전환하지 않는다.

### FLOW-RC-03 초대와 수락

`함께하는 사람 → 역할·관계·기간 선택 → 보안 초대 생성 → 로그인 후 일회성 수락 → 허용 범위 확인`

초대 수락 전 주소·계약서·연락처를 노출하지 않는다.

### FLOW-RC-04 권한 종료

`구성원 종료/계약 종료/공유 철회 → 다음 요청부터 화면·API·파일·채팅 차단 → 기존 집·사무소 업무 기록 보존 → 다음 계약에는 개인자료 미노출`

## 6. 상태와 오류 처리

각 핵심 화면은 다음 상태를 명시적으로 처리한다.

- 로딩
- 처음 사용하는 빈 화면
- 정상 완료
- 입력 오류
- 네트워크·서버 오류와 다시 시도
- 권한 없음
- 관계 종료
- 일부 파일만 실패한 부분 성공
- 중복 클릭·중복 네트워크 요청

오류는 사용자가 다음에 할 수 있는 행동을 가까운 위치에 쉬운 말로 제공한다.

## 7. 개인정보와 권한 경계

- 인증은 `누구인지 확인`, 권한은 `무엇을 할 수 있는지 확인`으로 분리한다.
- 서버 액션·RPC·RLS에서 역할, 사무소/집/계약 관계와 유효 기간을 매 요청 확인한다.
- 사무소 내부 기록, 현재 계약 공유 기록, 장기 집 이력과 개인자료를 분리한다.
- 파일의 저장 경로와 메타데이터도 접근 범위에 포함한다.
- 초대·메시지·기록의 중복 요청은 멱등 처리한다.
- 실제 연락처·계약서·계좌정보·인증정보를 저장소와 검수 자료에 넣지 않는다.

## 9. 구현 순서와 복구 경계

1. 공개 홈의 사례 탐색과 실제 제품 UI 증거를 테스트 우선으로 교체한다.
2. 가입→집→기록→첨부 흐름의 누락 상태와 역할 안내를 보완한다.
3. 채팅→초대→종료 흐름의 화면·권한·실패 상태를 보완한다.
4. 로컬 정적 검사, 단위·통합·커버리지와 빌드를 실행한다.
5. Preview 데이터 백업과 migration 목록을 검토한 뒤 Preview에만 적용한다.
6. 다계정 실제 흐름, 네 해상도, 키보드·접근성·콘솔을 검수한다.
7. 결함을 재현 테스트부터 수정하고 전체 회귀한다.
8. 문서·바탕화면·GitHub를 동기화하고 새 Vercel Preview를 제출한다.

각 migration은 기존 데이터를 삭제하지 않는 후속 migration으로 작성한다. 기능별 플래그와 이전 Preview 배포를 복구 경계로 사용하고 Production은 변경하지 않는다.

## 10. 완료 판정

다음이 모두 충족되어야 `배포 직전`으로 보고한다.

- `RC-*` 요구사항과 수용 기준이 추적표에 연결됨
- 타입 오류 0건
- 단위·통합·E2E 주요 흐름 통과
- 선언한 제품 코드 범위의 statements/branches/functions/lines 각각 80% 이상
- Preview에서 가입·로그인·집·기록·첨부·채팅·초대·종료 실제 왕복 증거
- 320·390·768·1440px 브라우저 증거, 가로 넘침·콘솔·hydration 오류 0건
- 키보드 탐색과 색상 대비 검수
- P0·P1 결함 0건
- 민감정보 Git 포함 0건
- 실제 사용할 수 없는 기능을 완료 또는 활성 기능으로 표시한 항목 0건
- Production 미배포

외부 OAuth 또는 운영 문자 공급자처럼 사용자 계정 설정이 필요한 항목이 남으면 `아직 사용할 수 없는 기능`으로 명확히 분리하며, 이를 숨긴 채 출시 완료로 판정하지 않는다.
