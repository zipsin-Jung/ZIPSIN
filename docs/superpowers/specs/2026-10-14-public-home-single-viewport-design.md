# 공개 홈 단일 화면 가로 스토리 설계

- 날짜: 2026-10-14
- 상태: 구현·로컬 검증 완료, Preview·사용자 화면 승인 대기
- 대상: 비로그인 공개 홈 `/`

## 목적

방문자가 긴 소개 페이지를 내려 읽지 않고 한 화면 안에서 집신의 핵심 가치를 이해하고, 네 장을 좌우로 넘긴 뒤 실제 회원가입 또는 로그인으로 이동하게 한다.

## 확정 요구사항

### REQ-PUB-SV-001 단일 화면

- 공개 홈은 헤더와 네 장 가로 캐러셀만 렌더링한다.
- 기존 소개·기능·연속성·이용 방법·최종 CTA·푸터 섹션은 공개 홈에서 제거한다.
- 헤더에는 로고, 로그인, `웹에서 시작하기`만 남긴다.

### REQ-PUB-SV-002 실제 가로 이동

- 네 장은 하나의 가로 트랙에 배치하고 선택한 장까지 `translate3d`로 이동한다.
- 이전·다음, 네 개 목차, 키보드 좌우·Home·End, 모바일 swipe를 지원한다.
- 자동재생은 한 번만 진행하고 사용자 조작 뒤 중지하며 마지막 장에서 멈춘다.

### REQ-PUB-SV-003 첫 장 연출

- 승인된 `story-01-gather.png`를 왼쪽에 크게 배치한다.
- 처음에는 이미지 위쪽의 흩어진 정보가 확대되어 보이고, 약 2.2초 동안 집 모양을 중심으로 축소·이동해 정보가 집신으로 모이는 인상을 만든다.
- 오른쪽에는 다음 완성 문장을 항상 실제 HTML로 제공하고, 시각적으로만 구절별 타이핑 효과를 준다.

> 계약과 동시에 흩어지는 부동산 정보,
> 집신 한곳에 모아 관리하고
> 하나의 집 이력으로 가치를 키웁니다.

- CTA는 `내 집 기록 시작하기`와 `로그인`이다.

### REQ-PUB-SV-004 반응형·접근성

- 1440×900, 768×900, 390×844, 320×844에서 정상 확대 상태의 문서 세로·가로 넘침은 1px 이하여야 한다.
- 데스크톱은 이미지 왼쪽·문구 오른쪽, 모바일은 이미지 위·문구 아래로 한 화면에 맞춘다.
- 600px 이하에서는 헤더 공간을 위해 로그인 글자를 숨기되 활성 장면 안의 `로그인` 버튼을 항상 유지한다.
- 200% 확대나 매우 낮은 화면에서는 내용 잘림보다 내부 세로 스크롤을 허용한다.
- `prefers-reduced-motion`에서는 이미지 이동·타이핑·자동재생을 생략하고 완성 상태를 즉시 보여준다.
- 비활성 장은 접근성 트리와 탭 순서에서 제외한다.

## 수용 기준

| ID | 수용 기준 |
|---|---|
| AC-PUB-SV-001 | 공개 `/`에 캐러셀 외 본문 섹션과 푸터가 없다. |
| AC-PUB-SV-002 | 네 장은 같은 가로 트랙에서 선택 인덱스마다 정확히 100% 이동한다. |
| AC-PUB-SV-003 | 첫 장 h1에 승인 문장 전체가 있고 이미지·구절 reveal·CTA가 4.3초 안에 완성된다. |
| AC-PUB-SV-004 | 감소된 모션에서는 첫 장이 즉시 완성되고 자동재생 버튼이 비활성화된다. |
| AC-PUB-SV-005 | 네 기준 viewport에서 문서 overflow 1px 이하, 핵심 이미지·문구·CTA·제어가 viewport 안에 있다. |
| AC-PUB-SV-006 | 모든 제어는 44×44px 이상이고 키보드·터치·focus 표시·axe 검사를 통과한다. |
| AC-PUB-SV-007 | `/signup`, `/login`, 카카오 대표 문의 경로를 유지하고 Production은 변경하지 않는다. |

## 구현 경계

- 현재 합성 PNG 안의 서류·사진을 개별 레이어로 분리하지 않는다.
- 카메라 이동, 마스크, 빛의 흐름만으로 모이는 인상을 만든다.
- 외부 통화·문자·카카오톡 기록을 가져오는 것처럼 표현하지 않는다.
- 로그인 후 제품, 데이터베이스, 권한, 결제는 변경하지 않는다.
