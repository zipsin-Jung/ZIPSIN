# 공개 홈 웹앱 설치·시네마틱 모션 설계

- 날짜: 2026-10-14
- 상태: 구현·Vercel Preview 검증 완료, 사용자 승인 대기
- 대상: 비로그인 공개 홈 `/`
- 기준: `docs/superpowers/specs/2026-10-14-public-home-single-viewport-design.md`

## 1. 목적

공개 홈의 승인 이미지 네 장을 첫 시선에 알아볼 수 있을 만큼 크게 보여주고, 각 장의 의미를 서로 다른 1회성 움직임으로 설명한다. 헤더에는 가짜 앱스토어 링크가 아닌 실제 웹앱 설치 진입을 제공한다.

성공한 화면은 다음 세 가지를 동시에 만족한다.

1. 방문자가 첫 장의 흩어진 정보와 집신 집 모양을 3초 안에 식별한다.
2. `모인다 → 이어진다 → 연결된다 → 가치가 된다`가 이미지 움직임만으로도 구분된다.
3. 지원 기기에서는 집신을 웹앱으로 설치하고, 직접 설치창을 열 수 없는 기기에는 정확한 방법만 안내한다.

## 2. 확인된 사실·가정·권고

### 확인된 사실

- 공개 홈은 `헤더 + 한 화면짜리 네 장 가로 캐러셀`로 구현되어 있다.
- 첫 이미지는 941×1672 세로형이고, 나머지 세 장은 1672×941 가로형이다.
- 첫 이미지는 넓은 프레임에서 `contain`으로 축소되어 내용이 작고 좌우 빈 공간이 크게 보인다.
- 첫 장에만 줌·빛·문장 reveal이 있고 2~4장은 트랙 이동 외 고유 모션이 없다.
- 현재 Web App Manifest, 설치 상태 처리와 192·512px 설치 아이콘은 없다.
- Next.js 16.4 로컬 공식 문서는 App Router의 `app/manifest.ts`와 HTTPS 기반 홈 화면 설치를 지원한다. `beforeinstallprompt`는 iOS Safari에서 동작하지 않는다.

### 가정

- 사용자가 말한 `앱으로 다운로드`는 현재 웹 제품을 기기에 설치하는 PWA 방식이다.
- 네이티브 앱과 앱스토어 출시는 이번 작업이 아니다.

### 권고

- 지원 Chromium은 사용자 클릭 시 실제 설치 프롬프트를 연다.
- iPhone·iPad는 `Safari 공유 → 홈 화면에 추가 → 추가` 안내를 보여준다.
- 설치 프롬프트를 사용할 수 없는 브라우저는 거짓 성공 대신 브라우저 메뉴 설치 안내를 보여준다.
- 인증 자료의 구버전·개인정보 캐시 위험을 피하기 위해 이번 범위에 서비스 워커와 오프라인 캐시는 넣지 않는다.

## 3. 범위

### 포함

- 헤더의 `앱으로 다운로드` CTA
- 설치 가능·iOS 안내·일반 안내·설치됨 상태
- Web App Manifest와 집신 브랜드 192·512px 설치 아이콘
- 승인 이미지 네 장의 고유 1회성 모션
- 첫 세로 이미지의 전경·확장 배경 구성과 가시성 개선
- 모바일·데스크톱·모션 감소 대응
- 단위·E2E·접근성·성능·Preview 검수

### 제외

- App Store·Google Play 등록, 가짜 스토어 배지와 QR
- 네이티브 앱, 푸시 알림, 백그라운드 기능
- 서비스 워커, 오프라인 보장, 인증 화면 캐시
- 승인 이미지 내부 물체를 실제 데이터처럼 분리하거나 새 기능처럼 표현
- 로그인 후 제품, 데이터베이스, 권한, 결제 변경
- 사용자 승인 전 Production 배포

## 4. 요구사항과 수용 기준

### REQ-PUB-INSTALL-001 헤더 설치 진입

- 데스크톱 헤더는 `앱으로 다운로드 → 로그인 → 웹에서 시작하기` 순서다.
- 모바일은 폭에 맞춰 `앱 설치` 또는 `앱 받기`로 축약한다.
- 로그인과 회원가입은 활성 장면 CTA에서도 계속 접근할 수 있어야 한다.

수용 기준:

- AC-INSTALL-001: 설치 CTA는 실제 버튼이고 최소 44×44px이다.
- AC-INSTALL-002: 320·390·768·1440px에서 헤더가 가로로 넘치지 않는다.
- AC-INSTALL-003: 기존 `/login`, `/signup`, 카카오 문의 경로가 유지된다.

### REQ-PUB-INSTALL-002 설치 상태와 흐름

설치 버튼은 아래 네 상태를 구분한다.

| 상태 | 사용자에게 보이는 동작 |
|---|---|
| 설치 가능 | 사용자 클릭 뒤 브라우저 설치 프롬프트를 한 번 호출한다. |
| iPhone·iPad | Safari의 `공유 → 홈 화면에 추가 → 추가` 3단계 안내를 연다. |
| 일반 안내 | 현재 브라우저의 메뉴에서 앱 설치·홈 화면 추가를 찾도록 안내한다. |
| 설치됨·standalone | `앱 설치됨` 상태를 표시하고 성공을 다시 꾸미지 않는다. |

수용 기준:

- AC-INSTALL-004: 설치 프롬프트는 자동으로 열지 않고 사용자의 버튼 클릭 뒤에만 호출한다.
- AC-INSTALL-005: 사용자가 취소하면 설치 완료로 표시하지 않고 공개 홈을 계속 사용할 수 있다.
- AC-INSTALL-006: `appinstalled`, `display-mode: standalone`, iOS standalone 상태를 반영한다.
- AC-INSTALL-007: 안내창은 열 때 제목으로 포커스가 이동하고, Escape·닫기 뒤 설치 버튼으로 포커스가 돌아간다.
- AC-INSTALL-008: 안내창은 `앱스토어 앱이 아닌 웹앱 설치`이며 인터넷 연결이 필요하다는 사실을 명시한다.

### REQ-PUB-INSTALL-003 설치 메타데이터

- `app/manifest.ts`에 앱 이름, 짧은 이름, 설명, id·start URL·scope `/`, standalone 표시, 딥그린 테마와 아이콘을 정의한다.
- 기존 `public/icon.svg` 브랜드를 바탕으로 정사각 192·512px PNG와 Apple touch icon을 제공한다.

수용 기준:

- AC-INSTALL-009: Preview의 manifest 경로가 200으로 응답하고 필수 필드를 제공한다.
- AC-INSTALL-010: 설치 아이콘은 192×192와 512×512이며 512px 아이콘은 maskable 용도를 포함한다.
- AC-INSTALL-011: 앱 시작 경로 `/`는 로그인 사용자를 기존 `/home`으로 보내고 비로그인 사용자는 공개 홈을 보여주는 현재 동작을 유지한다.

### REQ-PUB-VISUAL-001 이미지 가시성

- 이미지는 장면의 가장 강한 시각 요소여야 한다.
- 첫 장은 흐린 확장 배경과 선명한 전경을 겹쳐 세로 비율의 빈 공간을 해결한다.
- 선명한 전경은 원본의 핵심 내용을 유지하며 장면 종료 시 집신 집과 제품 UI가 충분히 크게 보인다.

수용 기준:

- AC-VISUAL-001: 1440×900·390×844에서 첫 장 시작 1초 안에 흩어진 자료를, 3초 안에 집신 집을 식별할 수 있다.
- AC-VISUAL-002: 320·390·768·1440px에서 이미지·문구·CTA·제어가 viewport 안에 있고 문서 overflow는 1px 이하다.
- AC-VISUAL-003: 큰 외곽 카드와 겹친 테두리를 약화하고 이미지 무대를 데스크톱 폭의 약 56~60%로 사용한다.

### REQ-PUB-MOTION-001 장면별 고유 모션

각 장면은 활성화할 때 한 번 실행하고 3.5초 안에 안정된 정지 상태가 된다.

| 장면 | 움직임 | 최종 시선 |
|---|---|---|
| 모인다 | 상단 통화·사진·서류에서 아래 집신 집으로 카메라가 이동하고 빛이 한 번 모인다. 문장은 세 줄로 순차 등장한다. | 집신 집과 제품 UI |
| 이어진다 | 봄→가을→겨울 세 구간을 왼쪽부터 드러내고 하단 기록선이 한 번 이어진다. | 같은 집과 이어진 기록선 |
| 연결된다 | 뒤엉킨 연락에서 중앙 ZIPSIN을 거쳐 오른쪽 집별 카드로 경로 빛이 이동한다. | 집별 연락처·집신 채팅 |
| 가치가 된다 | 공간이 안정되며 에어컨→벽지→배관→바닥→휴대폰 이력이 순차 강조된다. | 집 이력 화면 |

수용 기준:

- AC-MOTION-001: 네 장은 서로 다른 motion 식별자를 가지며 활성 장면에만 실행된다.
- AC-MOTION-002: 재선택한 장면은 1회 모션을 자연스럽게 다시 시작한다.
- AC-MOTION-003: 무한 바운스·파티클·큰 글로우·3D 회전은 사용하지 않는다.
- AC-MOTION-004: 기존 7초 자동 넘김 전에 모션이 끝나고 읽을 시간이 남는다.
- AC-MOTION-005: 외부 통화·문자·카카오톡을 집신이 가져오는 것처럼 새 문구나 아이콘을 추가하지 않는다.

### REQ-PUB-A11Y-001 접근성·성능·안전

수용 기준:

- AC-A11Y-001: `prefers-reduced-motion: reduce`에서는 모든 모션과 자동재생을 중지하고 완성 상태를 즉시 보여준다.
- AC-A11Y-002: 실제 제목·설명·CTA는 애니메이션과 무관하게 DOM과 접근성 트리에 존재한다.
- AC-A11Y-003: 이미지 컨테이너 크기를 고정하고 CLS는 0.1 이하를 유지한다.
- AC-A11Y-004: 첫 장만 priority로 두고 나머지 이미지는 lazy 정책을 유지한다.
- AC-A11Y-005: axe 위반, console error, hydration error가 0건이다.
- AC-SAFE-001: 네이티브 앱·앱스토어·오프라인 지원을 제공하는 것처럼 표현하지 않는다.

## 5. 화면 구성

### 데스크톱

- 헤더: 로고 / 앱으로 다운로드 / 로그인 / 웹에서 시작하기
- 본문: 이미지 58% 안팎 / 문구 42% 안팎
- 장면 제어: 하단 한 줄, 기존 키보드·hover·click·재생 제어 유지

### 모바일

- 헤더: 로고 / 앱 받기
- 본문: 이미지 위 43~46% / 문구 아래
- 로그인·가입은 활성 장면 CTA로 유지
- 설치 안내는 화면 아래에서 올라오는 대화상자 형태로 표시하되 키보드 접근성을 충족한다.

## 6. 기술 구조

- `app/manifest.ts`: 설치 메타데이터만 담당한다.
- `features/install/components/InstallAppButton.tsx`: 브라우저 이벤트와 설치 상태를 담당한다.
- `features/install/components/InstallGuideDialog.tsx`: iOS·일반 안내와 포커스 복귀를 담당한다.
- `features/install/install-state.ts`: 순수 플랫폼·상태 판별 함수를 담당한다.
- `HomeStoryCarousel.tsx`: 활성 장면 식별자와 이미지 전경·배경만 렌더링한다.
- `PublicHome.module.css`: 장면별 모션과 반응형·reduced-motion을 담당한다.

외부 PWA 패키지는 추가하지 않는다. 서비스 워커와 데이터 캐시는 만들지 않는다.

## 8. 위험과 롤백

- 설치 프롬프트가 준비되지 않음: 설치 안내로 안전하게 전환하고 성공 문구를 표시하지 않는다.
- 320px 헤더 혼잡: 모바일에서 로그인·웹 시작을 헤더에서 숨기고 본문 CTA로 유지한다.
- 이미지 crop 실패: breakpoint별 위치를 분리하고 네 크기 캡처로 검사한다.
- GPU·LCP 악화: transform·opacity·clip-path 중심, 큰 blur와 무한 반복 금지, 첫 장 외 lazy 유지.
- 설치 기능 롤백: Install 컴포넌트와 manifest 연결을 제거하면 기존 헤더로 복구된다.
- 모션 롤백: 장면별 motion class를 제거하거나 reduced-motion 정지 상태를 기본으로 적용한다.

데이터베이스·권한·Production 변경이 없어 전체 변경은 되돌릴 수 있다.
