# 집신 유료 파일럿 배포 전 제품·UX 명세

- 작성일: 2026-10-13
- 상태: 최초 회의 사용자 승인 반영
- 기준 결정: `DEC-013 사무소 우선 유료 파일럿`
- 대상: 첫 20개 공인중개사무소, 8주 유료 파일럿
- 참가비: 사무소당 99,000원(8주 전체, 자동 결제·자동 전환 없음)
- 정식 출시 예정가: 249,000원(과금 주기와 포함량은 파일럿 후 별도 상품으로 확정)

> 채팅 범위와 권한은 후속 승인 문서 `2026-10-13-zipsin-chat-support-design.md`를 우선 적용한다. 채팅에는 별도 담당자 개념을 사용하지 않는다.

## 1. 목적

공인중개사무소가 집별 사진·문서·업무 기록과 다음 할 일을 직원 개인 휴대전화가 아니라 사무소의 비공개 공간에 남기고, 담당자가 바뀌어도 업무를 이어가게 한다.

파일럿의 최소 완결 흐름은 다음과 같다.

`대표 로그인 → 사무소 생성 → 첫 집 등록 → 담당자 배정 → 기록·사진·문서·할 일 등록 → 직원 초대 → 임대인·임차인 초대 → 집별 대화 → 권한 종료 확인`

파일럿이 배포 직전 단계에 도달했다는 뜻은 화면 수가 많은 것이 아니라, 실제 사무소가 관리 집 5채를 넣고 두 명 이상이 반복 사용할 수 있으며 권한 종료까지 안전하게 동작한다는 뜻이다.

## 2. 기존 공개형 V1과의 관계

`docs/12-public-self-service-v1-spec.md`는 임대인·임차인을 포함해 누구나 자신의 집으로 시작하는 장기 공개형 V1 문서로 보존한다. 폐기하거나 덮어쓰지 않는다.

이번 파일럿에서는 `DEC-013`에 따라 공인중개사무소를 첫 결제 고객과 첫 구축 흐름으로 우선한다. 두 문서가 충돌하면 유료 파일럿 범위에는 이 문서를 적용하고, 공개형 서비스의 장기 방향에는 기존 문서를 적용한다.

파일럿에서 사무소가 만드는 집은 등기·소유권이 확인된 전역 집 키가 아니다. 해당 사무소만 사용하는 비공개 관리 공간이다. 주소가 같아도 다른 사무소의 공간과 자동으로 합치지 않으며 주소 검색만으로 기존 기록을 발견하거나 열 수 없다.

## 3. 확정 원칙

1. 모든 구성원은 대표 계정을 공유하지 않고 개인 계정을 사용한다.
2. 개인의 주 역할과 사무소에서 맡은 역할은 분리한다.
3. 개인 주 역할은 대표 공인중개사, 소속공인중개사, 중개보조원, 임대인, 임차인을 지원한다.
4. 사무소 역할은 대표 공인중개사, 소속공인중개사, 중개보조원으로 구분한다.
5. 역할 선택만으로 사무소나 집 기록 접근 권한을 부여하지 않는다.
6. 대표는 사무소의 모든 활성 관리 집을 보고, 다른 구성원은 배정받은 집만 본다.
7. 중개보조원은 사진 등록, 일정·할 일 기록, 단순 자료 정리만 수행한다. 설명, 조건 조율, 계약 작성·승인은 수행하지 않는다.
8. 임대인·임차인은 유효한 초대를 수락한 뒤 현재 계약 공유 공간에서 읽고 기록할 수 있다.
9. 임대인·임차인은 사무소 내부 기록을 볼 수 없다.
10. 직원 퇴사, 담당 해제, 계약 종료, 공유 철회 즉시 접근을 종료한다. 이미 남은 사무소 기록은 유지한다.
11. 이전 계약자의 개인정보는 다음 계약자에게 자동으로 이어지지 않는다.
12. 초대는 원문 연락처를 저장하지 않는 만료·철회·일회성 링크로 시작한다.
13. 실제 카드 자동결제를 붙이지 않는다. 파일럿 참가와 수납은 운영자가 별도로 확인한다.
14. 실제 사용자 화면에서는 `데모`, `테스트`, `준비 중` 표현으로 정식 서비스의 신뢰를 떨어뜨리지 않는다. 작동하지 않는 메뉴는 노출하지 않는다.
15. 앱 화면은 짙은 잉크·네이비와 청록을 중심으로 고대비 타이포그래피를 사용하고, 그라데이션은 핵심 면과 CTA에만 절제하여 사용한다.

## 4. 역할별 가치와 권한

| 역할 | 파일럿 가치 | 볼 수 있는 것 | 할 수 있는 것 | 할 수 없는 것 |
|---|---|---|---|---|
| 대표 개업공인중개사 | 직원이 바뀌어도 사무소 기록과 업무를 유지 | 사무소의 모든 활성 집, 구성원, 내부·공유 기록, 할 일 | 사무소·집 생성, 직원 초대, 담당 배정·해제, 기록·파일·할 일 관리, 관계자 초대·종료 | 주소만으로 다른 사무소 기록 열기 |
| 소속공인중개사 | 배정된 집의 기록과 다음 행동을 한곳에서 확인 | 자신에게 배정된 집의 내부·공유 기록과 할 일 | 배정 집의 기록·파일·할 일 작성, 허용된 설명·계약 업무 표시 | 구성원·요금 관리, 미배정 집 열람 |
| 중개보조원 | 처리한 일과 다음 일을 남겨 인수인계를 단순화 | 자신에게 배정된 집의 허용된 내부·공유 기록과 할 일 | 사진 등록, 일정·할 일 기록, 단순 문서 정리 | 확인·설명, 조건 조율, 계약서 작성·승인, 미배정 집 열람 |
| 임대인 | 반복 연락이나 방문 없이 공유된 진행 상태 확인 | 초대받은 집의 현재 계약 공유 기록·파일·할 일 | 현재 계약 공유 공간에 기록과 사진 작성 | 사무소 내부 기록, 다른 계약 개인정보 열람 |
| 임차인 | 입주 상태와 요청을 현재 계약 공간에 보존 | 초대받은 현재 계약 공유 기록·파일·할 일 | 현재 계약 공유 공간에 기록과 사진 작성 | 사무소 내부 기록, 이전·다음 계약 개인정보 열람 |

## 7. 공통 상태 체계

모든 주요 화면은 해당되는 다음 상태를 명시적으로 제공한다.

| STATE-ID | 상태 | 표시와 복구 원칙 |
|---|---|---|
| STATE-EMPTY | 처음 사용·자료 없음 | 빈 이유와 한 개의 주요 행동을 표시 |
| STATE-LOADING | 불러오는 중 | 기존 내용을 지우지 않고 진행 상태 표시 |
| STATE-READY | 정상 | 역할과 관계에 허용된 정보와 행동만 표시 |
| STATE-SAVING | 저장 중 | 중복 제출을 막고 현재 입력 유지 |
| STATE-SUCCESS | 성공 | 무엇이 저장됐는지 짧게 알리고 다음 화면으로 연결 |
| STATE-VALIDATION | 입력 오류 | 항목 가까이에 쉬운 문장으로 표시하고 첫 오류로 이동 |
| STATE-NETWORK-ERROR | 네트워크·서버 오류 | 입력을 유지하고 다시 시도 제공 |
| STATE-PERMISSION-DENIED | 권한 없음 | 자료 내용을 노출하지 않고 홈으로 돌아가기 제공 |
| STATE-INVITE-EXPIRED | 초대 만료 | 만료 사실과 새 초대 요청 방법 표시 |
| STATE-INVITE-REVOKED | 초대 철회 | 자료를 노출하지 않고 초대한 사무소 문의 안내 |
| STATE-INVITE-USED | 이미 사용한 초대 | 현재 로그인 계정의 소속 여부를 확인하도록 안내 |
| STATE-RELATION-ENDED | 소속·담당·계약 종료 | 새 조회·작성을 차단하고 종료 사실만 표시 |
| STATE-PARTIAL-UPLOAD | 일부 업로드 실패 | 성공·실패 파일을 분리하고 실패 항목 재시도 제공 |

## 8. 기능 요구사항과 수락 기준

### REQ-PILOT-OFFICE-001 사무소 시작

- 역할: 대표 개업공인중개사
- 트리거: 역할 선택 완료 후 사무소가 없는 상태
- 사전조건: 인증된 개인 계정, 대표 역할
- 흐름: 사무소 이름 입력 → 생성 → 대표 멤버십 동시 생성 → 빈 업무 홈
- 개인정보 범위: 사무소 구성원만 사무소 존재와 이름을 확인
- 상태: `EMPTY`, `SAVING`, `SUCCESS`, `VALIDATION`, `NETWORK-ERROR`, `PERMISSION-DENIED`

수락 기준:

- **AC-OFFICE-001** 대표가 아닌 사용자의 생성 요청을 서버에서도 거부한다.
- **AC-OFFICE-002** 한 번의 성공 요청으로 사무소와 대표 멤버십이 함께 생성된다.
- **AC-OFFICE-003** 중복 제출로 사무소가 두 개 생성되지 않는다.
- **AC-OFFICE-004** 실패 시 입력한 이름을 유지하고 다시 시도할 수 있다.
- **AC-OFFICE-005** 성공 후 첫 집 등록을 주요 행동으로 보여준다.

### REQ-PILOT-HOME-001 첫 집 등록

- 역할: 대표 개업공인중개사, 생성 권한을 받은 소속공인중개사
- 트리거: 업무 홈의 `첫 집 등록` 또는 집 목록의 `집 등록`
- 사전조건: 활성 사무소 소속
- 흐름: 도로명 주소 입력 → 상세 위치·내부 구분명 입력 → 비공개 관리 공간 생성 → 생성자 자동 담당 → 빈 타임라인
- 개인정보 범위: 활성 대표와 해당 집 담당자만 정확한 주소 확인
- 상태: `EMPTY`, `LOADING`, `SAVING`, `SUCCESS`, `VALIDATION`, `NETWORK-ERROR`, `PERMISSION-DENIED`

수락 기준:

- **AC-HOME-001** 주소만으로 다른 사무소의 집이나 기록을 조회하지 못한다.
- **AC-HOME-002** 동일 주소 후보가 있어도 자동 병합하지 않는다.
- **AC-HOME-003** 생성자와 집 담당 관계를 한 작업으로 생성한다.
- **AC-HOME-004** 성공 후 새 집의 빈 타임라인으로 이동한다.
- **AC-HOME-005** 실패 시 주소와 상세 입력을 유지한다.

### REQ-PILOT-MEMBER-001 직원 초대

- 역할: 대표 개업공인중개사
- 트리거: 구성원 관리의 `직원 초대`
- 사전조건: 활성 대표 멤버십
- 흐름: 사무소 역할 선택 → 만료되는 일회성 링크 생성 → 상대가 개인 계정으로 확인 → 범위 확인 → 수락 → 활성 소속 생성
- 개인정보 범위: 초대 링크에는 사무소 이름과 예정 역할만 표시하고 기존 집·기록은 표시하지 않음
- 상태: `EMPTY`, `SAVING`, `SUCCESS`, `NETWORK-ERROR`, `PERMISSION-DENIED`, `INVITE-EXPIRED`, `INVITE-REVOKED`, `INVITE-USED`

수락 기준:

- **AC-MEMBER-001** 대표 계정이나 비밀번호를 공유하지 않는다.
- **AC-MEMBER-002** 초대 원문 토큰은 DB에 저장하지 않고 만료·철회·일회성 소비를 적용한다.
- **AC-MEMBER-003** 수락 전에는 사무소 집과 기록이 보이지 않는다.
- **AC-MEMBER-004** 중개보조원 초대로 공인중개사 전용 권한이 생기지 않는다.
- **AC-MEMBER-005** 만료·철회·이미 사용한 초대를 서버에서도 거부한다.
- **AC-MEMBER-006** 완전한 HTTPS 링크를 복사하거나 지원 기기 공유 메뉴로 전달할 수 있다.
- **AC-MEMBER-007** 미가입자는 가입·휴대전화 인증 뒤 원래 초대 화면으로 돌아온다.
- **AC-MEMBER-008** 유효한 초대 수락과 소속 생성은 원자적으로 처리되고 허용된 사무소 공간이 즉시 나타난다.
- **AC-MEMBER-009** 토큰 원문을 로그·분석·외부 미리보기 메타데이터에 남기지 않는다.

### 화면별 UX 규칙

- 업무 홈은 `오늘 처리할 일 → 최근 변경된 집 → 확인 필요한 기록 → 최근 활동` 순서다.
- 집 상세 상단에는 주소, 내부 구분명, 내 관계, 담당자를 표시한다.
- 기록 작성은 공간을 먼저 고르게 하고, 각 공간을 볼 사람을 바로 설명한다.
- 초대 수락 전에는 역할, 사무소 이름, 열리는 범위, 종료 조건만 보여준다.
- 위험한 권한 종료는 영향 안내와 재인증 뒤 실행한다.
- 빈 화면은 설명보다 시작 행동을 먼저 보여준다.
- 버튼과 입력은 모바일에서 최소 44×44px 터치 영역을 확보한다.
- 오류는 색상만으로 구분하지 않고 글자와 아이콘을 함께 사용한다.
- 모달 없이도 모든 핵심 흐름을 키보드로 완료할 수 있어야 한다.

## 11. 현실 사례 검증

### 사례 A: 보조원이 갑자기 퇴사

대표는 보조원의 소속과 담당을 종료한다. 보조원은 다음 요청부터 집을 볼 수 없다. 보조원이 남긴 사진과 완료 기록은 사무소에 유지된다. 대표는 미완료 할 일을 새 담당자에게 배정한다.

### 사례 B: 임대인이 집신을 모르는 상태

사무소는 임대인 가입 없이 내부 관리 공간을 만들고 광고 사진과 할 일을 정리한다. 이 공간은 소유권을 주장하거나 공개되지 않는다. 임대인이 초대를 수락한 뒤에도 사무소 내부 공간은 보이지 않고 현재 계약 공유 공간만 열린다.

### 사례 C: 새 임차인 입주

이전 계약을 종료하고 새 계약 초대를 발급한다. 새 임차인은 새 계약 공유 기록만 본다. 이전 임차인의 연락처, 요청, 사진, 대화는 보이지 않는다. 집에 계속 남길 수 있도록 별도로 승인된 비개인 공용 이력만 공유될 수 있다.

### 사례 D: 같은 주소를 여러 사무소가 관리

각 사무소는 자기 비공개 관리 공간을 가진다. 시스템은 동일 주소를 감지해도 공간이나 기록을 자동으로 합치지 않는다. 어느 사무소도 주소만으로 다른 사무소의 기록을 찾지 못한다.

## 14. UX 승인 기준

- 320px, 390px, 1440px에서 가로 넘침 없이 핵심 흐름을 완료한다.
- 각 화면에 주요 행동은 하나만 강하게 보인다.
- 역할과 관계에 없는 행동은 숨기기만 하지 않고 서버에서도 거부한다.
- 빈·로딩·저장·성공·입력 오류·네트워크 오류·권한 거부·관계 종료 상태를 제공한다.
- 사용자가 저장 실패 후 입력을 잃지 않는다.
- 초대받은 사람은 수락 전에 열릴 정보와 종료 조건을 이해한다.
- 집 주소, 계약 관계, 사진과 문서를 권한 없는 화면에 미리 노출하지 않는다.
- 빌드 통과와 실제 브라우저 검수 통과를 별도로 기록한다.
