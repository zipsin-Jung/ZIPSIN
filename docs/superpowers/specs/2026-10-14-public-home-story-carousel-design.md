# 공개 메인 4장 스토리 캐러셀 설계

- 날짜: 2026-10-14
- 상태: 사용자 재승인 반영 구현·독립 품질 게이트·Vercel Preview 검증 통과, 사용자 승인 대기
- 변경 대상: 공개 메인 `/`

## 1. 목표

방문자가 첫 화면에서 긴 설명을 읽지 않아도 `집의 상태를 살펴보고 → 뒤섞인 연락을 집별로 정리하고 → 사진·문서·대화·일정을 집 한 채에 모으고 → 사람이 바뀌어도 기록을 이어가는 서비스`라고 이해하게 한다. 네 장은 `서론 → 본론 → 과정 → 결론`, 조작 문구는 `살펴본다 → 정리한다 → 모은다 → 이어간다` 순서다.

## 2. 확인된 사실과 전제

### 확인된 사실

- 현재 공개 홈은 Hero와 아래 `ScenarioExplorer`에 유사한 내용을 나누어 보여준다.
- 현재 사례 데이터와 실제 React 제품 증거 UI는 네 장면을 지원한다.
- 사용자는 위에서 흩어진 정보가 집신으로 모이는 세로 이미지를 첫 대표 장면으로 선택했다.
- 사용자는 동일한 집을 봄·가을·겨울 세 시기로 나누고 사람만 바뀌며 기록선이 이어지는 이미지를 두 번째 장면으로 선택했다.
- 사용자는 외부 통화·문자·메신저·주소록의 혼란이 집신 앞에서 끝나고, 집신에서는 집별 연락처와 전용 채팅을 새로 사용하는 이미지를 세 번째 장면으로 선택했다.
- 사용자는 자동차 비교를 제외하고, 위치·계약 서류와 함께 에어컨·배관·난방·벽지·바닥의 관리 이력을 확인하는 이미지를 네 번째 장면으로 선택했다.
- 사용자는 자동 전환, 점에 마우스를 올려 장면 선택, 좌우 클릭 이동을 요청했다.

### 전제

- `책장이 넘어가는 느낌`은 사실적인 종이 말림이 아니라 얕은 겹침·그림자·수평 이동을 뜻한다.
- 첫 장 승인 원본은 `/var/folders/38/66fqc8v92m5g_g6w_h7jxctw0000gn/T/codex-clipboard-6e758a35-5e66-428a-b95a-f281849a8ca7.png`이다.
- 두 번째 장 승인 원본은 `/var/folders/38/66fqc8v92m5g_g6w_h7jxctw0000gn/T/codex-clipboard-c184b1af-c293-4565-88c2-961a993b65e6.png`이다.
- 세 번째 장 승인 원본은 `/var/folders/38/66fqc8v92m5g_g6w_h7jxctw0000gn/T/codex-clipboard-12d2cfde-16c8-4f1f-9e05-ba68aa1938dc.png`이다.
- 네 번째 장 승인 원본은 `/var/folders/38/66fqc8v92m5g_g6w_h7jxctw0000gn/T/codex-clipboard-2d06aee4-eae2-44f5-bd28-dc58ba015fd4.png`이다.
- 승인 원본은 구현 단계에서 프로젝트 공개 자산으로 복사한다. 임시 경로를 런타임에서 참조하지 않으며, Next.js 이미지 최적화를 사용한다.

## 3. 범위

### 포함

- 현재 Hero와 네 사례 탐색을 하나의 4장 메인 스토리 캐러셀로 통합
- 서로 다른 생활 문제를 보여주되 색감·타이포그래피·제품 UI가 연결되는 네 장
- 각 장의 짧은 카피, 생활 문제 이미지와 실제 React 제품 증거 UI
- 1회 자동재생, 점 hover 선택, 점 click/tap 선택, 이전·다음, 재생·일시정지, 모바일 swipe
- 키보드, 모션 감소, 이미지 실패, 탭 숨김, 포커스 상태
- 320·390·768·1440px 검수

### 제외

- 로그인 후 `/home` 변경
- DB·권한·계약·채팅 기능 변경
- 3D page-curl/WebGL/외부 캐러셀 패키지
- 무한 자동재생, 영상, 소리

- Production 배포

## 4. 네 장의 이야기

### 1장 — 서론 · 살펴본다

- 핵심 문장: `부동산, 아직도 위치와 서류만 보고 계신가요?`
- 보조 문장: `집도 시간이 지나면 노후됩니다. 사진·문서·대화·일정을 집 한 채에 연결해 에어컨·배관·마감의 관리 이력까지 확인하세요.`
- 이미지: 계약서·건물관리대장·위치 자료와 함께 에어컨·배관·난방·벽지·바닥의 기록이 한 공간에 보이는 승인 장면
- 제품 증거: `입주 → 점검 → 교체 → 수리 → 현재`
- 아하 모먼트: 위치와 계약 서류뿐 아니라 집 안에서 무엇을 언제 관리했는지도 판단의 근거가 된다.
- 결론 문장: `주거 이력이 가치가 되는 새로운 문화, 집신.`

### 2장 — 본론 · 정리한다

- 핵심 문장: `어디서 나눈 말인지, 누구의 집인지 헤매지 않도록.`
- 보조 문장: `외부 연락 기록을 가져오지 않습니다. 사람을 초대해 집별 연락처와 집신 채팅에서 새 기록을 시작하세요.`
- 이미지: 왼쪽에는 기존 구두 전달·통화·문자·개인 메신저·주소록이 여러 임대인·공인중개사·집과 섞인 혼란을 둔다. 이 외부 기록선은 중앙 집신 앞에서 분명히 끝난다. 오른쪽에는 `서초빌라 201호`, `집신아파트 1401호`, `한강오피스텔 603호`의 집별 연락처와 집신 채팅만 정돈해 보여준다.
- 제품 증거: `집별 연락처 / 초대된 사람 / 집신 채팅 / 새 기록`
- 아하 모먼트: 외부 기록을 가져오는 것이 아니라, 집신에 사람을 초대해 그 집의 새 연락과 대화를 한곳에서 시작한다.
- 기능 경계: 카카오톡·문자·통화 이력 연동 또는 가져오기는 현재 제공하지 않는다. 사용자가 사람을 초대하거나 연락처를 직접 저장하고 집신 채팅을 사용한 시점부터 새 기록이 쌓인다.
- 금지: 실제 전화번호·실명·카카오 상표와 복제 UI, 외부 대화가 자동 수집되는 표현을 사용하지 않는다.

### 3장 — 과정 · 모은다

- 핵심 문장: `부동산의 모든 정보를 집 한 채에 모아서.`
- 보조 문장: `계약서·사진·대화·일정을 흩어 두지 않고, 하나의 집 기록으로 이어서 관리하세요.`
- 이미지: 서류·사진·통화·대화·일정이 위에서 집 모양 ZIPSIN 기록함으로 모이는 승인 장면
- 제품 증거: `우리 집 기록 / 사진 · 문서 · 대화 · 일정` 타임라인 요약
- 아하 모먼트: 파일함이 아니라 집 자체가 기록함이 된다.
- 장면 모션: 위쪽의 흩어진 자료를 크게 보여준 뒤 카메라가 아래로 흐르며 집 속으로 빨려 들어가고, 마지막에는 집 모양 제품 UI가 확대된다.

### 4장 — 결론 · 이어간다

- 핵심 문장: `사람이 바뀌어도, 집의 기록은 남도록.`
- 보조 문장: `관계가 끝나면 접근 권한도 끝납니다. 집의 관리 기록만 이어지고, 이전 사람의 개인정보와 비공개 대화는 넘어가지 않습니다.`
- 이미지: 같은 집·같은 구도를 봄·가을·겨울 세 칸으로 분명히 나눈다. 임차인과 관계자는 바뀌지만 하단의 사진·문서·수리·일정 기록선은 끊기지 않는다.
- 제품 증거: `입주 사진 → 문서 → 수리 → 일정 → 접근 종료 → 새 관계 연결`
- 아하 모먼트: 사람의 휴대전화가 아니라 집에 관리 기록이 남는다.
- 개인정보 원칙: 이전 계약자의 개인정보와 비공개 대화는 다음 사람에게 자동으로 전달하지 않는다.
- 최종 문장: `집에 관한 일의 반복·누락·단절을 막는 집신과 함께합니다.`
- CTA: `내 집 기록 시작하기`, `로그인`
- 표현 제한: 집신이 사실을 법적으로 검증하거나 자산 가격 상승을 보장한다고 표현하지 않는다.

## 5. 화면 구조

### 데스크톱

- 하나의 고정된 제품 무대 안에서 4장만 전환한다.
- 카피와 CTA는 왼쪽, 이미지와 제품 증거 UI는 오른쪽에 둔다.
- 첫 세로 이미지를 가로로 늘이거나 핵심을 잘라내지 않는다. 같은 콘셉트를 오른쪽 무대 비율에 맞게 재구성한다.
- 다음 장의 가장자리를 약하게 보여 `한 권의 다음 페이지`를 암시한다.

### 모바일

- `핵심 문장 → 보조 문장 → 문제 이미지 → 제품 증거 UI → CTA·페이지 표시` 순서다.
- 3D 회전 대신 짧은 수평 이동과 페이드를 사용한다.
- 세로 스크롤을 방해하지 않는 명확한 수평 swipe만 장면 전환으로 처리한다.

### 메인 아래

- 현재 별도 `ScenarioExplorer`는 제거해 중복을 없앤다.
- 권한·개인정보 원칙, 이용 방법 3단계, 최종 CTA는 유지하되 같은 설명을 반복하지 않는다.

## 6. 전환과 조작

- 첫 장은 SSR에서 완전하게 보이며 CTA가 동작한다.
- 화면에 충분히 보일 때 7초 간격으로 1→2→3→4를 한 번만 자동재생하고 4장에서 멈춘다.
- 전환 시간은 550~700ms다. 얕은 `translateX`, 작은 `rotateY`, opacity와 그림자만 사용한다.
- 점은 네 장의 목차다. 점에 pointer가 250ms 머물면 짧은 제목을 표시하고 해당 장으로 전환한다.
- 빠르게 점을 스쳐 지나가면 전환하지 않는다.
- carousel hover·focus·pointer down·문서 숨김 상태에서는 자동재생을 멈춘다.
- 단순 hover가 끝나면 명시적 조작이 없고 4장에 도달하지 않은 경우에만 1.5초 뒤 이어서 재생한다.
- 점·화살표·키보드·swipe로 직접 조작하면 자동재생을 멈추고 재생 버튼을 눌러야 다시 시작한다.
- 이전·다음 버튼, `1 / 4`, 점 네 개와 재생·일시정지 버튼을 항상 제공한다.
- 모바일에서는 hover가 없으므로 점 tap, 화살표 tap과 swipe를 제공한다.
- `prefers-reduced-motion: reduce`에서는 자동재생과 회전·이동 애니메이션을 끄고 수동 즉시 전환만 제공한다.

## 7. 접근성·성능·실패 상태

- carousel region에 이름을 제공하고 현재 장을 `n / 4`로 알린다.
- 현재 장만 읽기·탭 순서에 노출한다. 자동 변경을 매번 live region으로 낭독하지 않는다.
- 점과 화살표는 최소 44×44px 실제 버튼이다.
- 좌우 화살표 키, Home, End를 지원하며 자동으로 키보드 포커스를 옮기지 않는다.
- 첫 장 이미지만 우선 로드하고 2~4장은 지연 로드한다.
- 이미지 영역의 비율과 최소 높이를 미리 확보해 레이아웃 이동을 막는다.
- 이미지가 실패해도 문장·제품 UI·가입 CTA와 고정 비율 폴백을 유지한다.
- JS가 실패해도 첫 장과 CTA는 남는다.
- 이미지 안의 작은 글자는 핵심 설명으로 사용하지 않고 HTML 카피와 대체 설명으로 같은 의미를 제공한다.

## 8. 요구사항과 수용 기준

### RC-HERO-STORY-001 — 네 장의 메인 이야기

- AC-01: 정확히 네 장이며 순서는 서론·살펴본다→본론·정리한다→과정·모은다→결론·이어간다다.
- AC-02: 선택 장면의 이미지·카피·제품 증거 UI가 같은 사례로 함께 바뀐다.
- AC-03: 첫 장만으로도 집신의 제품 정의와 시작 CTA를 이해할 수 있다.

### RC-HERO-MOTION-001 — 자동·수동 전환

- AC-04: 7초 간격으로 한 번 자동재생하고 4장에서 멈춘다.
- AC-05: 점 hover 250ms, 점 click/tap, 이전·다음, 키보드와 swipe가 동작한다.
- AC-06: 사용자의 명시적 조작 뒤 자동재생은 재생 버튼 전까지 멈춘다.
- AC-07: 모션 감소 설정에서는 자동재생과 책장형 모션이 없다.

### RC-HERO-SAFE-001 — 안전한 공개 표현

- AC-08: 공개 이미지는 교육용이며 개인정보·실제 계약 원본·가짜 고객 실적을 포함하지 않는다.
- AC-09: 주소만으로 기록을 보는 표현, 수리 중개 표현과 공인중개사 전용 표현이 없다.
- AC-10: 이미지 실패 상태에서도 설명·실제 경로 CTA·제품 증거 UI를 사용할 수 있다.

### RC-HERO-RESP-001 — 반응형·접근성

- AC-11: 320·390·768·1440px에서 가로 넘침과 전환 중 높이 점프가 없다.
- AC-12: 점·화살표·재생 버튼은 키보드와 터치로 사용할 수 있고 최소 44px이다.
- AC-13: axe 기본 위반, console·hydration 오류가 없다.
- AC-14: 첫 장 외 이미지를 초기 우선 로드하지 않으며 CLS는 0.1 이하를 목표로 한다.

## 11. 구현 경계

- `PublicHome`은 Server Component로 유지한다.
- 타이머와 입력 처리가 필요한 `HomeStoryCarousel`만 작은 Client Component로 만든다.
- 기존 `publicHomeScenarios`와 `ProductEvidence`를 새 네 장 구조에 맞게 재사용·확장해 데이터 원천을 하나로 유지한다.
- 외부 carousel 라이브러리는 추가하지 않는다.
- 사용자의 재승인 뒤 4→3→1→2 이미지 순서와 새 스토리 문구를 구현했다. Production 반영은 Preview 사용자 승인 뒤 별도로 진행한다.

## 12. 구현 결과

- 공개 `/`에 네 장을 하나의 캐러셀로 통합했고 기존 `ScenarioExplorer` 중복 노출을 제거했다.
