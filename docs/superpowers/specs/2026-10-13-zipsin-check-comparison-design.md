# 집신체크 비교 중심 V2 제품·UX 설계

- 작성일: 2026-10-13
- 상태: G1/G2 사용자 승인 · 구현계획 검토 대기
- 선행: `docs/19-zipsin-check-v1-product-spec.md`, `DEC-018`

## 1. 목적

사회초년생이 여러 집을 짧게 방문한 뒤 기억에 의존하지 않고 `빠른 기록 → 같은 기준 비교 → 담당자 재연락`을 집신체크 안에서 끝내게 한다. 비교 경험은 집별 요약 카드가 아니라 네이버 카드검색처럼 집 2~3채를 열로, 같은 비교 기준을 행으로 정렬한 표를 중심으로 한다.

## 2. 확정 방향

- 집은 여러 채 저장하고 그중 2~3채만 비교한다. MVP 보관 목표는 최소 10채다.
- 첫 등록은 `간단하게`가 기본이며 별명과 발견 경로만 보여준다. 별명도 비우면 `오늘 본 집 N`으로 즉시 시작한다.
- `상세하게`에서는 위치, 가격, 관리비, 출퇴근, 입주일, 담당자, 연락처와 매물 링크를 선택 입력한다. 방문 후에도 보충할 수 있다.
- 현장 기본 항목은 물·배수, 곰팡이·누수, 채광·소음, 창문·문, 옵션·파손의 5개다.
- 큰 항목 결과는 `괜찮음 / 다시 확인 / 미확인`이다. 상세 네모 체크박스는 결과 평가가 아니라 실제 행동을 해봤다는 기록이다.
- `메모`를 열었을 때 사진 추가를 함께 제공한다.
- 비교표는 점수·순위·안전 판정을 만들지 않는다.
- 주소·담당자 연락처·매물 링크는 가입 전 현재 브라우저에만 저장한다. URL, 분석로그, Git에 넣지 않는다.
- 개인정보가 포함된 후보는 비교 제외와 별개로 영구 삭제할 수 있어야 하며 텍스트와 사진을 함께 제거한다.
- 계정 저장과 `ck.zipsin.net → zipsin.net` 이전은 별도 후속 범위다.

## 3. 요구사항과 수락기준

### ZCC-001 간단·상세 등록

- 간단 등록은 별명과 발견 경로만 우선 표시한다.
- 상세 등록은 위치, 거래조건, 생활조건, 담당자와 매물 링크를 선택 입력한다.
- AC-001-A: 아무 입력 없이도 자동 별명으로 체크를 시작할 수 있다.
- AC-001-B: 간단 등록 후보를 방문 후 상세 정보로 보강할 수 있다.
- AC-001-C: 상세 입력을 취소해도 기존 체크·메모·사진은 유지된다.

### ZCC-002 현장 필수 5개

- 5개 큰 항목을 한 화면에 네모 체크 중심으로 표시한다.
- 상세 행동은 선택적으로 펼치며 큰 항목 결과와 의미를 분리한다.
- AC-002-A: 상세를 열지 않고 5개 결과와 메모만으로 방문을 끝낼 수 있다.
- AC-002-B: 메모 안에서 사진을 추가·교체·삭제할 수 있다.
- AC-002-C: 320px에서 가로 넘침 없이 모든 기본 행동이 44px 이상이다.

### ZCC-003 비교 후보 선택

- 저장된 후보 중 2~3채를 사용자가 선택한다.
- AC-003-A: 선택 순서가 비교 열 순서가 된다.
- AC-003-B: 네 번째 선택은 기록을 지우지 않고 기존 선택 변경을 안내한다.
- AC-003-C: 비교 해제는 후보·메모·사진을 변경하지 않는다.

### ZCC-004 동일 행 비교표

- 고정 행: 대표 사진, 별명·위치, 보증금·월세, 관리비, 월 고정 주거비, 출퇴근, 입주일, 발견 경로, 현장 5개, 다시 확인 개수, 사진 수, 담당자, 재연락, 매물 링크.
- AC-004-A: 미입력과 실제 0원을 다르게 표시한다.
- AC-004-B: 미확인과 다시 확인을 색상뿐 아니라 문구·아이콘으로 구분한다.
- AC-004-C: 한 집에서만 확인한 정보는 다른 집의 단점으로 계산하지 않는다.
- AC-004-D: 모바일은 왼쪽 항목 열과 상단 집 헤더를 유지하고 집 열만 가로 이동한다.

### ZCC-005 안전한 재연락

- 담당자 이름과 `전화하기`를 기본 표시하며 번호 전체는 상시 노출하지 않는다.
- AC-005-A: 전화는 사용자 선택 후 운영체제 전화 화면까지만 연다.
- AC-005-B: 연락처가 없거나 유효하지 않으면 실행하지 않고 수정 안내를 표시한다.
- AC-005-C: 매물 링크는 `http/https`만 허용하고 외부 링크임을 알린다.

### ZCC-006 정보 수정과 복구

- 비교 화면에서 후보 상세 수정으로 들어갔다가 같은 비교로 돌아온다.
- AC-006-A: 저장 실패 시 기존 화면과 입력을 유지한다.
- AC-006-B: 새로고침 뒤 비교 선택 순서와 데이터가 복구된다.
- AC-006-C: 후보 ID를 유지해 기존 IndexedDB 사진 연결이 끊기지 않는다.

### ZCC-007 비교 제외와 영구 삭제

- 비교 제외, 보관 제외, 영구 삭제를 구분한다.
- AC-007-A: 영구 삭제 전에 대상과 복구 불가를 확인한다.
- AC-007-B: 영구 삭제는 후보 텍스트와 연결된 사진을 함께 제거한다.
- AC-007-C: 부분 실패 시 남은 데이터와 재시도 방법을 알린다.

### ZCC-008 집신 저장 연결

- 비회원은 현재 기기에서 등록·체크·비교까지 완료할 수 있다.
- AC-008-A: `집신에 저장하기`를 선택했을 때만 가입으로 이동한다.
- AC-008-B: 가입 실패·취소 시 로컬 기록은 유지된다.
- AC-008-C: 서버 이전 전 주소·연락처·사진을 항목별로 확인하고 동의하게 한다.
- 실제 서버 이전은 이번 구현 범위에서 제외한다.

## 4. 화면과 흐름

```text
CK-S01 새 집 등록
  ├─ 간단하게(기본): 별명·발견 경로
  └─ 상세하게: 위치·가격·관리비·출퇴근·입주일·담당자·연락처·링크
       ↓
CK-S02 현장 체크: 필수 5개 + 항목별 메모
       └─ 메모 시트: 텍스트 + 사진
       ↓
CK-S03 집 목록: 여러 후보 보관 + 비교할 2~3채 선택
       ↓
CK-S04 집 비교표: 고정 항목 열 + 집별 가로 열
       ├─ 집 상세/수정
       ├─ 전화/매물 보기
       └─ 집신에 저장하기(후속 연결)
```

## 5. 비교표 UX

- 항목 열 88~96px, 집 열 136~152px를 기준으로 실제 320·390px에서 조정한다.
- 상단에는 대표 사진 한 장, 별명과 핵심 가격만 둔다.
- 긴 메모는 1~2줄 요약 후 선택 시 전체 메모와 사진을 보여준다.
- 값이 없으면 빈칸이나 0 대신 `미입력`, 체크하지 않았으면 `미확인`을 표시한다.
- 접근성 구조는 실제 `table`, 열 머리글과 행 머리글을 사용한다.
- 스크린리더는 `망원역 원룸, 관리비, 7만원`처럼 집·항목·값을 함께 이해할 수 있어야 한다.

## 6. 데이터 설계 경계

- 새 `schemaVersion: 2`와 새 저장 키 `zipsin-check:v2`를 사용한다.
- 기존 v1 원본은 자동 삭제하거나 덮어쓰지 않는다.
- `intakeMode`와 기존 `depth`를 분리한다.
- 후보에 구조화된 `listing`, `terms`, `contact`, `commute`를 둔다.
- 금액은 원 단위 정수 또는 미입력으로 저장한다.
- `compareCandidateIds`는 중복 없는 최대 3개 순서 목록이다.
- v1 후보 ID를 유지해 기존 사진을 그대로 연결한다.
- 마이그레이션 실패 시 v1을 보존하고 복구 안내를 표시한다.

## 7. MVP·후속·제외

### MVP

- 간단·상세 등록, 현장 5개, 메모 안 사진
- 후보 최소 10채 보관, 2~3채 선택 비교
- 동일 행 비교표, 정보 보강, 전화·매물 링크
- v1→v2 비파괴 마이그레이션과 후보 영구 삭제

### 후속

- `ck.zipsin.net` 운영 연결
- 집신 단일 로그인과 선택 기록 서버 이전
- 다른 기기 복원, 입주·퇴거 체크 연결

### 제외

- 자동 매물 수집·크롤링
- 자동 출퇴근 계산과 지도
- 전화·문자 발송 이력
- 추천 순위·종합점수·전세 안전 판정
- 연락처 기반 마케팅과 다른 사용자 자동 공유

## 8. 테스트와 품질 문턱

- v1→v2 정상·손상·중복·저장실패와 후보 ID/사진 연결 보존
- 후보 0·1·2·3·4개 선택, 순서, 비교 해제와 기록 보존
- 금액 0·미입력·음수·상한·만원 표시와 월세+관리비 조건부 합계
- 연락처 정규화, 위험 URL 차단, 메모의 출입정보 차단
- 영구 삭제 성공·사진 실패·부분 실패 안내
- 320px·390px·데스크톱, 200% 확대, 키보드·스크린리더 표 구조
- 대표 기능의 REQ/AC→FLOW/SCREEN/STATE→소스→테스트→실행 증거 매핑
- 측정 대상 제품 코드의 lines/statements/functions/branches 각각 80% 이상
- 독립 검수 P0·P1 0건

## 9. 작은 검증 실험

서버 없이 기존 로컬 후보를 사용해 2채와 3채 비교를 먼저 검증한다. 도움 없이 가격·관리비·현장 5개·담당자를 구분하고 다시 연락할 집을 찾을 수 있어야 한다. 가로 이동 후 집 이름을 반복해서 잃거나 현재 카드형보다 판단이 느리면 고정 열·헤더와 행 수를 조정한다.

## 10. 사용자 승인 항목

1. 집은 최소 10채 보관하고 그중 최대 3채만 비교한다.
2. 아무 입력 없는 즉시 시작을 유지하면서 간단·상세 등록을 선택할 수 있다.
3. 상세 행동 체크와 큰 항목 결과의 의미를 분리한다.
4. 주소·연락처를 로컬 저장하는 대신 후보 영구 삭제를 제공한다.
5. v1 원본을 남긴 채 v2로 비파괴 이전한다.
6. 첫 구현은 로컬 비교표까지이며 실제 계정·서버 이전과 운영 배포는 제외한다.
