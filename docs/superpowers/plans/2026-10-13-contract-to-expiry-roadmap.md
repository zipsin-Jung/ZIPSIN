# 집신 계약 후부터 만기까지 제품 구현 로드맵

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement each approved phase task-by-task. Do not start the next phase without its written plan and review.

**Goal:** 기존 집신 웹앱을 `계약 후부터 만기·연장·퇴거까지, 그 집에 필요한 기록과 다음 일을 순서대로 알려주는 제품`으로 완성한다.

**Architecture:** 화면 안내용 사용 목적과 실제 데이터 접근 권한을 분리한다. 전역 홈은 여러 집의 우선순위를, 개별 집 홈은 현재 계약의 D-day·계획·다음 행동을 보여준다. 기록·첨부·채팅은 기존 RLS와 비공개 저장소를 재사용하며, 새 상태 변경은 서버 RPC와 감사 이력으로만 처리한다.

**Tech Stack:** Next.js 16 App Router, React 19, TypeScript, Tailwind CSS, Supabase Auth/Postgres/RLS/Storage/Realtime, Vitest, Testing Library, Playwright

**Spec:** `docs/superpowers/specs/2026-10-13-contract-to-expiry-home-design.md`

## Global Constraints

- 새 프로젝트를 만들지 않고 현재 코드·문서·Git 기록을 보존한다.
- 네 사용 목적은 화면 개인화용이며 집 접근 권한이 아니다.
- 주소·집 ID를 아는 것만으로 기존 기록을 검색·연결·열람할 수 없다.
- 임대인과 임차인의 만기 계획 상태는 서로 덮어쓰지 않는다.
- 만기 계획 선택은 계약 연장·해지 통지가 아니며 제품 안에 이를 명시한다.
- 이전 계약자의 개인정보·채팅·현재 계약 기록은 다음 계약으로 자동 전달하지 않는다.
- 사진·PDF는 사용자가 직접 확인해 저장하고, 자동 수집·자동 공개하지 않는다.
- 전체 커버리지 Lines·Statements·Functions·Branches 각각 80% 이상을 유지한다.
- 타입·단위·통합·시나리오·권한·접근성·반응형 검증을 각각 수행한다.
- 사용자 승인 전에는 Production에 배포하지 않는다.

## 단계 1 — 계약 중심 집 홈

상세 계획: `docs/superpowers/plans/2026-10-13-contract-home-phase-1.md`

- `임차인 / 임대인 / 공인중개사 / 관리·기타`를 사용 목적 선택으로 저장한다.
- 공인중개사는 대표·소속·보조 세부 역할을 별도로 고른다.
- 사용 목적만으로 어떤 집도 열리지 않게 기존 관계 기반 권한을 유지한다.
- 현재 계약의 시작일·만기일을 권한 있는 공인중개사가 직접 입력한다.
- 임대인·임차인은 자신의 `아직 결정 전 / 연장 생각 중 / 퇴거 준비` 상태만 변경한다.
- 집 홈은 집 이름, 마스킹 주소, D-day, 계획, 다음 행동 최대 3개를 먼저 보여준다.
- 계약이 없거나 날짜가 없거나 권한이 없거나 조회가 실패한 상태를 서로 다르게 보여준다.

## 단계 2 — 집의 시간과 직접 업로드

별도 승인 계획에서 다음을 파일 단위로 확정한다.

- 계약 보관 → 입주 기록 → 거주·관리 → 만기·퇴거의 네 단계
- 계약서·건축물대장·등기사항증명서·고지서·영수증·설비 자료·기타 문서 종류
- 입주 전·현재·수리 전·중·후·퇴거·설비·영수증 사진 종류
- JPEG·PNG·HEIC·PDF 검증, 비공개 저장, 짧은 signed URL
- 현재 집·작성자·서버 시각 자동 입력과 종류·공유 범위 사용자 확인
- 기록 시간선과 행동·기한 캘린더 분리
- 업로드 성공 뒤 해당 집 화면 즉시 갱신

## 단계 3 — 집 안의 관계와 대화

별도 승인 계획에서 다음을 파일 단위로 확정한다.

- `이 집 사람들`에 현재 유효한 관계만 표시
- 개인 전화번호·이메일 기본 비공개와 휴대전화 주소록 미수집
- 집·현재 계약·수리 사건별 채팅 범위
- 읽지 않은 채팅 수와 일반 알림 수 분리
- 채팅 사진을 기록에 남길 때 별도 확인
- 퇴사·계약 종료·초대 철회·기간 만료 시 신규 접근과 발신 즉시 차단
- 이전 계약 대화와 개인정보의 다음 임차인 자동 노출 방지

## 후속 범위

- OCR은 날짜·문서 종류를 `제안`만 하고 사용자가 확정한다.
- AI 분류는 자동 저장이 아니라 저장 제안부터 시작한다.
- 선택한 기록·문서·대화·일정을 PDF로 묶는 기능은 별도 설계한다.
- 외부 알림, 앱 다운로드, 법적 통지, 실결제 활성화는 각각 별도 승인한다.

## 전체 완료 조건

- ZH-LIFE-001~008이 요구사항→소스→테스트→검수 결과로 연결된다.
- 대표 흐름 `가입 → 목적 선택 → 집 연결 → 계약 등록 → 기록 → 채팅 → 초대 → 권한 종료`가 실제 브라우저에서 통과한다.
- 320·390·768·1440px에서 가로 넘침이 없고 키보드만으로 핵심 행동이 가능하다.
- 콘솔 오류·hydration 오류·타입 오류가 0건이다.
- 권한 우회, 이전 계약 노출, 주소 기반 열람, 비공개 파일 public URL이 모두 거부된다.
- 미완성 기능을 완료처럼 표시하지 않고 Preview에서 사용자 승인을 받는다.

## 자체 검토

- 첫 단계만으로 `계약했다면 만기까지 집신으로`라는 핵심 가치를 실제 데이터로 보여줄 수 있다.
- 파일·채팅·관계 종료는 기존 기반을 재사용하되, 개인정보 경계를 지키기 위해 각각 독립 단계로 검수한다.
- 개인 시작 공간과 공유 집 연결 정책은 아직 결정되지 않았으므로 자동 병합이나 주소 검색 연결을 구현하지 않는다.
