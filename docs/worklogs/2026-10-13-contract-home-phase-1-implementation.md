# 계약 중심 집 홈 1단계 구현 기록

- 날짜: 2026-10-13
- 브랜치: `codex/contract-to-expiry-home`
- Production 변경: 없음

## 수행 순서

1. 기존 상태·인수인계·제품·권한 문서와 현재 코드를 확인했다.
2. 사용 목적과 실제 역할·관계 권한을 분리했다.
3. 계약 날짜와 사용자별 만기 계획을 보안 RPC와 감사 이벤트로 구현했다.
4. D-day, 네 단계 진행, 실제 데이터 기반 다음 행동 최대 3개를 순수 도메인 규칙으로 만들었다.
5. 개별 집 홈과 한 집·여러 집 업무 홈을 실제 데이터 우선 화면으로 재구성했다.
6. 요구→소스→테스트 연결을 갱신하고 자동·브라우저 검사를 실행했다.

## 변경 내용

- `profiles.usage_purpose`와 공인중개사 세부 역할을 추가했다.
- `contract_plan_states`, append-only `contract_plan_events`, 계약·계획 저장 RPC를 추가했다.
- 계약 요약 서비스와 여러 집 우선순위 서비스를 추가했다.
- 집 상세에 보호 주소, D-day, 본인 계획, 불일치 안내, 다음 행동, 집의 시간, 계약 폼을 연결했다.
- 업무 홈의 홍보형 배너를 제거하고 실제 집·만기·열린 일을 우선했다.
- 모바일·PC 내비게이션에 현재 위치를 표시했다.

## 2026-10-14 독립 검수 보완

- 계약 수정 가능 여부를 현재 사용자 ID까지 묶어 보조원·타 사무소 사용자의 화면 노출 가능성을 막았다.
- 상대 계약 당사자 계획은 `get_contract_party_plan_statuses` 보안 함수로만 읽고 사용자 UUID는 반환하지 않는다. 원본 상태·감사 표의 인증 사용자 직접 조회 권한도 회수했다.
- 집 목록의 상세 주소를 숨기고, 기록·채팅방·첨부 조회 오류는 빈 상태가 아닌 안전한 오류 화면으로 처리한다.
- 동일 상태 동시 저장은 계약·사용자 단위 트랜잭션 잠금으로 감사 이벤트 중복을 막는다.
- 기존 계약의 종류는 화면에서 잠그고 날짜만 수정할 수 있게 서버 규칙과 맞췄다.
- 코드 보완 커밋: `2952462`, `f612c47`
- 독립 재검수 결과: P0 0건, P1 1건, P2 0건. 남은 P1은 실제 Preview Postgres/RLS 다계정 검증이다.
- 바탕화면 문서 동기화에서 새 작업기록·품질보고서는 같은 구조로 복사했다. 기존 `WORK_STATUS.md`, `CONTINUE.md`, `docs/traceability/release-candidate-v1.md`는 바탕화면 사본이 Git 기준본과 달라 덮어쓰지 않고 충돌로 남겼다.
