# 2026-10-13 집신체크 V1 구현 작업일지

## 수행 순서

1. 사용자 승인과 기존 기준 문서를 확인했다.
2. 체크 카탈로그, 상태 규칙, 로컬 저장을 각각 실패 테스트부터 구현했다.
3. 시작, 체크, 설명, 요약, 비교, 복구 화면을 테스트 우선으로 연결했다.
4. 타입검사·전체 테스트·커버리지·정적 빌드를 실행했다.
5. 실제 미리보기에서 HTTP와 데스크톱·모바일 사용자 흐름을 검수했다.
6. 요구사항↔소스↔테스트↔실행 증거를 제품 명세에 연결했다.

## 구현 내용

- 경로: `/check`
- 빠른 체크: 공통 핵심 9개
- 꼼꼼 체크: 공통 핵심과 공간·생활·계약 추가 7개
- 항목 설명: 왜, 어떻게, 물어볼 말, 공식 확인 기준일
- 상태: 확인됨, 주의, 확인 못함, 전문가 확인
- 근거: 직접 확인, 설명, 서류, 전문가
- 결과: 점수 없는 상태별 요약과 다음 행동
- 비교: 활성 후보 최대 3채, 공통 핵심 9개만 같은 축으로 비교
- 저장: 브라우저 `localStorage`의 `zipsin-check:v1`, 손상·실패 시 현재 화면 보호
- 개인정보: 정확 주소·연락처·출입 비밀번호·사진 미수집, 위험 메모 저장 차단
- 삭제 방지: 후보는 삭제하지 않고 비교에서 제외한 뒤 복원

## 실제 브라우저 검수

- `/`, `/demo`, `/check`: 미리보기 HTTP 200
- 데스크톱: 빠른 체크에서 이유 펼침, 주의 선택, 요약 도달 확인
- 서로 다른 깊이: A집 빠른 체크와 B집 꼼꼼 체크 후 빠른 모드 전환, 공통 핵심 9행 비교 확인
- 새로고침: A집·B집 이어보기 복원 확인
- 390px·320px: 문서 가로 넘침 없음, 표시된 버튼 최소 높이 44px
- 포커스: 체크 진입 시 현재 항목 제목으로 이동
- 콘솔: 오류·경고 없음

빌드 성공과 실제 브라우저 검수 성공은 별도로 확인했다.

## 제외 범위와 남은 일

- 실제 집신 계정 가입·로그인·기기 간 저장
- 서버 데이터베이스, 사진 업로드, 정확 주소
- 공식 서류 자동 조회와 AI 하자·안전 판정
- 실제 사용자 3~5명 사용성 검증과 체크 문구 분야 전문가 검토

현재 상태는 독립 품질검수 후 `검수 통과, 사용자 승인 대기`로 보고한다. 프로덕션 배포는 이번 작업에 포함하지 않는다.
