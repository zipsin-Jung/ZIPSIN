# 2026-10-13 사무소·집 기록 권한 기반 작업

## 수행 순서

1. 기존 인수인계·상태·기획 문서를 확인했다.
2. 최신 `codex/public-v1-auth` 작업트리에서 이어서 작업했다.
3. 권한 경계를 먼저 테스트로 작성했다.
4. 사무소·담당 집·계약·기록·첨부 구조와 RLS 정책을 구현했다.
5. 현재 계약과 이전 계약의 개인정보 경계를 추가 검증했다.
6. TypeScript DB 타입과 기술 문서를 갱신했다.
7. 전체 타입 검사와 테스트를 수행했다.

## 변경 내용

- 사무소와 개인 계정을 분리했다.
- 대표·소속공인중개사·보조원의 사무소 역할을 정의했다.
- 주소가 아니라 활성 관계로 집 접근을 결정한다.
- 사무소 내부 기록, 현재 계약 기록, 공유 이력을 분리했다.
- 초대 토큰은 원문이 아닌 해시만 저장하도록 설계했다.
- 종료된 직원·임대인·임차인 관계의 접근을 차단했다.
- 현재 임차인이 이전 계약 기록을 볼 수 없도록 계약 단위 권한을 추가했다.
- 보조원에게 설명·조건 조율·계약 승인 권한을 부여하지 않았다.
- 빈 홈 화면을 역할별 시작 화면으로 교체했다.
- 대표 공인중개사는 사무소를 생성할 수 있고, 다른 구성원은 사무소 초대 안내를 본다.
- 사무소와 대표 멤버십은 `create_office` 함수에서 한 번에 생성되도록 구현했다.
- 아직 만들지 않은 집 등록·구성원 초대 경로는 동작하는 링크처럼 노출하지 않았다.
