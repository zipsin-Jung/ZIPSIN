# REQ-AUTH-LOGIN-001 통합 로그인 카드

## 목표

처음 방문한 임차인·임대인·중개사·수리기사가 로그인 방법을 헤매지 않고 한 화면에서 기존 계정, 간편 로그인, 회원가입 또는 집신체크 체험으로 이동한다.

## 승인 범위

- **AC-001** 한 입력칸에서 아이디·이메일·휴대전화번호를 받는다.
- **AC-002** 휴대전화번호는 인증 완료된 프로필만 계정으로 해석한다.
- **AC-003** 존재하지 않는 계정, 미인증 번호, 잘못된 비밀번호는 모두 같은 오류를 표시한다.
- **AC-004** `로그인 유지`를 선택하면 기존 영속 세션을, 선택하지 않으면 브라우저 세션 쿠키를 사용한다.
- **AC-005** Google·Kakao·Naver는 설정된 공급자만 원형 버튼으로 표시하고 접근 가능한 이름을 유지한다.
- **AC-006** `회원가입`은 기존 가입 화면, `체험하기`는 `/ck`로 이동한다.
- **AC-007** 320·390·768·1440px에서 가로 넘침 없이 키보드로 모든 요소를 사용할 수 있다.
- **AC-008** `로그인 유지`를 해제한 로그인은 서버·proxy·브라우저의 자동 토큰 갱신 뒤에도 브라우저 세션 쿠키로 남는다. 로그아웃하면 세션 전용 표시를 지운다. 간편 로그인은 선택지가 없으므로 기존처럼 유지되는 세션을 사용한다.

## 상태와 개인정보

- 로딩: 로그인 버튼에 처리 상태를 표시하고 중복 제출을 막는다.
- 성공: 안전하게 정제된 `next` 또는 `/home`으로 이동한다.
- 실패: 식별자 종류나 계정 존재 여부를 노출하지 않는다.
- 권한: 로그인 전 공개 화면이며, 서버만 아이디·전화번호를 실제 Auth 이메일로 해석한다.
- 저장: 새 개인정보를 추가 저장하지 않는다. 인증된 전화번호는 기존 `profiles.phone_e164`만 조회한다.
- 세션 전용 표시: `zipsin-session-only=1` 브라우저 세션 쿠키. 계정 정보가 없으며 브라우저 갱신 코드가 읽어야 하므로 HttpOnly를 쓰지 않는다.

## 제외

- 소셜 공급자 신규 개통, 비밀번호 없는 문자 로그인, 운영 배포는 포함하지 않는다.

## 테스트 ID

- `TEST-AUTH-LOGIN-001`: 통합 입력·로그인 유지·비밀번호 보기·가입·체험 UI
- `TEST-AUTH-LOGIN-002`: 아이디·이메일·인증 전화번호 정상 해석
- `TEST-AUTH-LOGIN-003`: 계정 열거 방지와 요청 제한
- `TEST-AUTH-LOGIN-004`: 세션 쿠키 영속/브라우저 세션 분기
- `TEST-AUTH-LOGIN-005`: 로그인 유지 해제 세션의 서버·proxy·브라우저 갱신, 로그아웃·간편 로그인 표시 정리
