# MVP 범위와 다음 단계

## MVP 목표

다가구 또는 여러 집을 관리하는 공인중개사무소가 직원 변경과 반복 연락으로 인한 기록 단절을 줄이고, 임대인·임차인과 집 관련 업무를 한곳에서 이어서 처리할 수 있는지 검증한다.

## 첫 유료 고객 가설

- 다가구 건물 또는 여러 임대 물건을 반복 관리하는 소규모 공인중개사무소
- 대표와 한 명 이상의 보조원이 함께 일하는 사무소
- 사진, 연락처, 계약서와 진행 상태가 개인 휴대전화에 흩어진 사무소

## MVP 필수 기능

1. 중개사무소 생성과 보조원 초대
2. 건물·집·호실 등록
3. 임대인·임차인 초대와 참여 확인
4. 담당자와 다음 할 일이 포함된 업무 진행판
5. 집별 사진첩
6. 계약서와 영수증 등 문서 촬영·첨부
7. 집 또는 사건에 연결된 채팅
8. 일정과 행동 중심 알림
9. 수리 전·중·후를 포함한 사건 기록
10. 선택 기록 PDF 생성
11. 직원 변경 시 업무 이전과 접근 종료

## MVP에서 제외할 기능

- 수리기사 중개 시장
- 견적 비교와 앱 내 결제
- 은행 송금 기능
- AI 사진 진단의 자동 확정
- 법적 소유권 자동 인증
- 모든 계약서 항목의 자동 추출
- 복잡한 사진별 공개 권한 설정
- 대규모 통계와 고급 회계 기능

## 핵심 화면 후보

1. 로그인·사무소 시작
2. 오늘의 업무
3. 집·건물 목록
4. 집 상세 타임라인
5. 업무 또는 사건 상세
6. 집 중심 채팅
7. 사진첩
8. 계약·문서함
9. 캘린더
10. 관계자·직원 관리
11. PDF 기록 선택·미리보기

## 유료 검증 원칙

긍정적인 인터뷰 답변만으로 결제 의사를 확정하지 않는다. 첫 유료 테스트 사무소 3곳을 대상으로 실제 관리 중인 집을 등록하고, 작은 금액이라도 결제받아 반복 사용과 업무 절감 여부를 확인한다.

## 측정할 행동

- 등록된 집 수
- 사무소 직원이 주간에 다시 방문한 횟수
- 집별 사진·문서·대화 등록 횟수
- 임대인·임차인의 초대 수락률
- 완료된 업무 수와 평균 처리 기간
- 직원 변경 시 인수인계에 걸린 시간
- PDF 생성과 공유 횟수
- 체험 후 유료 유지 의사와 실제 결제

## 다음 작업 순서

1. 상세 제품기획서 확정
2. 화면별 사용자 흐름과 와이어프레임 작성
3. 실제 사례 2~3개를 흐름에 대입
4. 첫 유료 테스트 조건과 가격 가설 작성
5. MVP 디자인
6. 데이터와 권한 구조 상세 설계
7. 웹앱 개발
8. 실제 사무소 테스트와 수정

## 사용자에게 필요한 입력

다음 자료는 개인정보를 제거한 형태로 제공받는다. 자료가 없어도 가상 사례로 먼저 설계할 수 있다.

- 매물 의뢰부터 입주까지의 실제 사례
- 보조원 인수인계가 끊긴 사례
- 수리 요청부터 완료까지의 실제 진행 순서
- 사용하는 계약서·사진 폴더·메모 또는 업무표 예시
- 보조원의 하루 업무 목록과 현장 용어
