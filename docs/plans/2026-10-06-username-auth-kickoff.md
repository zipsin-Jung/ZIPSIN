# 아이디 로그인·회원가입 개편 킥오프

- 날짜: 2026-10-06
- 상태: 설계 승인 대기
- 대상: 공개 V1 인증

## 목적

로그인 화면에서 이메일 대신 아이디와 비밀번호를 사용하면서 Google·카카오·네이버 간편 로그인을 함께 제공한다. 회원가입에서는 아이디·비밀번호·이메일을 받고, 기존 전화 인증·필수 동의·역할 선택으로 이어지는 실제 가입 흐름을 만든다.

## 사용자 승인 시안

- 왼쪽: 집신을 집·계약·수리·사진·일정·비용 기록을 집별로 관리하는 플랫폼으로 설명한다.
- 오른쪽: Google·카카오·네이버, 아이디, 비밀번호, 로그인, 아이디·비밀번호 찾기, 정확히 `회원가입` 버튼을 제공한다.
- 로그인 화면에는 이메일 입력란이나 `이메일로 회원가입` 문구를 두지 않는다.

## 네 역할 회의 결론

### 총괄비서

기존 소셜 인증을 보존하고 아이디 인증을 추가한다. 사용자 승인 전 배포와 운영 데이터 변경은 하지 않는다.

### 기획·디자인

로그인, 회원가입, 찾기, 오류, 로딩, 세션 만료 상태를 요구사항으로 분리한다. 모바일에서는 인증 행동을 설명보다 먼저 보이게 하고, 영구 라벨·44px 이상 터치 영역·키보드 사용을 보장한다.

### 설계·개발

비공개 아이디 매핑과 Supabase Auth를 결합한다. 비밀번호는 애플리케이션 DB·로그·Git에 저장하지 않는다. 아이디 로그인은 서버에서만 계정을 찾고 이메일을 화면과 응답에 노출하지 않는다.

### 검수·비판

아이디 열거, 중복 가입 경쟁, 무차별 로그인, 소셜 계정 자동 병합, 가입 부분 실패를 핵심 위험으로 지정한다. 실제 Preview 왕복과 RLS 음성 테스트 전에는 출시하지 않는다.

## 권장 설계

1. `/login`: 간편 로그인 3종과 아이디·비밀번호 로그인
2. `/signup`: 아이디·비밀번호·비밀번호 확인·이메일·필수 동의
3. 이메일 확인 후 휴대전화 인증과 이름 확인
4. 역할 선택 후 보호된 첫 화면 진입
5. 아이디 찾기·비밀번호 재설정은 별도 화면에서 가입 이메일 사용

아이디는 4~20자의 영문 소문자·숫자·밑줄로 제한하고 대소문자를 동일하게 취급한다. 초기 버전에서는 아이디 변경을 제공하지 않는다. 소셜 계정과 일반 계정은 이메일만으로 자동 병합하지 않는다.

## 데이터·보안

- `account_usernames` 비공개 매핑 테이블을 추가하고 DB 고유 제약으로 중복을 원자적으로 막는다.
- 비밀번호 검증과 세션은 Supabase Auth가 담당한다.
- 서비스 역할 키는 서버 전용 모듈에서만 사용한다.
- 로그인 실패는 계정 존재 여부와 관계없이 같은 문구를 사용한다.
- 로그인·가입·찾기 요청에 속도 제한을 적용한다.
- 아이디 로그인은 기능 플래그로 별도 중단할 수 있게 하고 소셜 로그인은 유지한다.

## 범위

### 포함

- 승인 시안 기반 반응형 로그인 화면
- 아이디 회원가입·로그인
- 세 소셜 로그인 진입과 오류 복귀
- 이메일 확인, 전화 인증, 필수 동의, 역할 선택 연결
- 아이디 찾기·비밀번호 재설정
- 단위·통합·E2E·권한·접근성 테스트와 80% 이상 커버리지

### 제외

- 이메일만으로 계정 자동 병합
- 아이디 변경
- 운영 결제와 실제 계약 접수
- 사용자 승인 없는 Production 배포

## 승인 지점

1. 이 설계와 가입 순서 사용자 승인
2. 상세 구현계획 사용자 승인
3. Preview 검수 결과 사용자 승인
4. Production 공개 별도 승인

## 다음 행동

사용자가 `아이디·비밀번호·이메일 → 이메일 확인 → 전화 인증·이름 → 필수 동의 → 역할 선택` 순서를 승인하면 요구사항과 상세 구현계획을 작성한다.
