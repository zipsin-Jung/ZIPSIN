# 공인중개사 영업용 데모 최초 회의

- 날짜: 2026-10-06
- 상태: 회의 완료 · 사용자 범위 승인 대기
- 참여 역할: 총괄비서, 기획·디자인, 설계·개발, 검수·비판

## 요청

공인중개사무소 영업을 시작하기 전에 직접 보여 줄 수 있는 결과물을 먼저 만든다.

## 공통 결론

`TEST-001~016` 전체나 실제 서비스를 한꺼번에 만들지 않는다. 첫 결과물은 다음 한 가지 흐름을 3분 안에 체험하는 모바일 우선 클릭형 데모다.

`멈춘 업무 발견 → 집별 기록 확인 → 사건 상태 확인 → 담당자 변경 → 새 보조원이 다음 행동 이어받기 → 기록 요약`

## 역할별 의견

### 총괄비서

- 영업 시작 속도와 핵심 가치 전달을 우선한다.
- 실제 서비스로 오인될 기능과 개인정보 입력은 제외한다.
- 범위를 승인한 뒤 설계·개발·독립 검수·사용자 승인 순서를 지킨다.

### 기획·디자인

- 현재 PhoneDemo는 공인중개사 역할에서도 임차인 관점 정보가 섞여 영업 메시지가 흐려질 수 있다.
- 한 가지 가상 누수 사례를 통해 업무와 기록의 연결, 담당자 변경, 결과 요약을 보여준다.
- 수리 플랫폼 오인을 막기 위해 `수리는 집에서 발생하는 사건 중 하나`임을 명시한다.

### 설계·개발

- 기존 `/`와 PhoneDemo는 보존하고 별도 `/demo`를 만든다.
- React 상태와 비식별 가상 데이터만 사용하며 외부 API, 인증, DB와 전역 상태 라이브러리는 추가하지 않는다.
- 공통 데모 셸, 업무 홈, 집 타임라인, 사건 상세, 담당 변경, 인수인계, 초기화로 구성한다.

### 검수·비판

- 기능 수보다 3분 안에 제품을 올바르게 설명할 수 있는지가 핵심 품질 기준이다.
- 실제 저장·전송 오인, 역할별 비공개 정보 노출, 수리 플랫폼 오인과 모바일 조작 실패를 P0/P1 위험으로 본다.
- 320px·390px, 역할 차이, 초기화, 반복 수행과 외부 전송 없음의 증거가 필요하다.

## 포함 범위

- `/demo` 영업용 클릭 데모
- 대표·보조원 역할 차이

- 가상 사진·영수증·기록 요약과 PDF 미리보기 예시
- 고정 데모 안내와 초기화
- 랜딩페이지의 데모 진입 CTA
