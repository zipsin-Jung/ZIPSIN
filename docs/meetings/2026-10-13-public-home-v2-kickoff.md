# 집신 공개 홈 V2 재설계 최초 회의

- 일자: 2026-10-13
- 범위: 토스·문토·홈노크 분석을 반영한 공개 홈 6장면 재설계
- 현재 게이트: G2 시각 시안 사용자 검토

## 목표와 사용자 가치

방문자가 10초 안에 집신이 `집 한 채를 기준으로 사진·문서·대화·일정을 연결하고, 임대인·임차인·공인중개사가 권한 범위에서 함께 쓰는 서비스`임을 이해하게 한다.

## 여섯 역할 결론

### 총괄비서

- 홈노크의 신뢰 구조는 배우되 문구·화면·그래픽을 복제하지 않는다.
- 시안 승인 전에 제품 코드를 변경하지 않는다.
- 프로덕션 배포는 별도 사용자 승인 후에만 한다.

### 제품기획

- 화면을 다 본 후 `집신은 집의 기록을 필요한 사람들이 함께 이어가는 서비스`라고 설명할 수 있어야 한다.
- 설명 30%, 실제 제품 장면 70%로 구성한다.
- 공인중개사 전용·수리 중개·자산관리 서비스로 오해받지 않는다.

### UX·UI 디자인

- 한 장면에 `생활 문제 1개 + 실제 UI 증거 1개`만 둔다.
- 신뢰 60% + 생활 온기 40%를 유지한다.
- 한 화면 한 문장, 동일한 제품 UI 언어, 한국의 실제 주거 장면을 사용한다.

### 설계·개발

- 비로그인 `/`의 `PublicHome`, 로그인 사용자의 `/home` 이동을 보존한다.
- 서버 컴포넌트와 CSS Module을 유지하고 무거운 스크롤·영상 도구를 추가하지 않는다.
- 실사는 로컬 자산과 `next/image`로 제공하고 Hero만 우선 로드한다.
- 현재 근거가 있는 기능만 작동하는 것처럼 표현한다.

### 검수·비판

- 320·390·768·1440px, 키보드, 색 대비, 줄인 애니메이션, 콘솔·수화 오류를 확인한다.
- 핵심 글자와 `/signup`·`/login` 링크, 금지문구 부재를 자동 테스트한다.
- 빌드 통과를 브라우저 검수 통과로 표현하지 않는다.

### 시간선·대안 분석

- 현 상태 유지는 즉시 비용이 없지만 단순하고 내용이 부족하다는 이탈 위험을 유지한다.
- 6장면을 시안 후 하나씩 구현하는 방식이 가장 되돌리기 쉽고 출시 후에도 확장하기 좋다.
- 홈노크식 전면 복제와 한번에 전면 개발은 정체성·지식재산·재작업 위험이 커서 제외한다.

## 6장면 범위

1. 집에 남는 기록: 따뜻한 실사 + 집 타임라인
2. 흘어진 기록의 합류: 사진·문서·대화·일정 → 집 타임라인
3. 세 사람의 같은 확인: 임차인 요청 → 공인중개사 확인 → 임대인 진행 확인
4. 수리 과정 기록: 수리 중개가 아닌 사진·첨부·대화 기록
5. 기록과 권한의 분리: 초대·열람 범위·계약 종료·이전 계약자 정보 분리
6. 즉시 시작: `내 집 기록 시작하기`, `사무소로 시작하기`, `로그인`

## 제외

- 시세·세금·임대료 수납·등기부·자산 자동 연결
- PDF 생성, 자동 업데이트, 완성된 캘린더를 현재 기능으로 표현
- 근거 없는 고객 수·절감률·성과 수치
- 사전가입·데모·출시 알림 CTA
- ‘담당자’ 중신 구조

## 승인 게이트

- G1 제품 범위: 통과
- G2 UX·시각 시안: 현재 사용자 검토
- G3 구현 설계: G2 승인 후
- G4 테스트 설계: G3와 함께 승인
- G5 자동·브라우저 검증: 구현 후
- G6 사용자 최종 승인: 배포 전

## 중단 조건

- 첫 화면만 보고 무슨 서비스인지 설명할 수 없음
- 공인중개사 전용·수리 중개·자산관리로 오해됨
- 홈노크의 문구·시각 자산과 혼동됨
- 실제 기능보다 과장된 UI를 보여줌
- 모바일에서 핵신 문장·UI·CTA가 잘림

## 다음 행동

생성된 시안의 전체 톤·6장면 연결·실제 제품성을 사용자가 검토한다. 승인 후에만 정식 명세와 구현계획을 작성한다.
