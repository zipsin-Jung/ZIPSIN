# 2026-10-14 단일 화면 휴대폰 인증 회원가입 최초회의

## 사용자 승인 방향

- 회원가입 화면의 이메일 바로 아래에 휴대폰 번호와 인증번호 입력을 둔다.
- 별도 휴대폰 인증 페이지를 신규 아이디 가입의 기본 흐름에서 제거한다.
- 휴대폰 인증 전에는 계정을 만들지 않는다.

## 역할별 결론

- 제품기획: 한 화면 가입과 인증 전 가입 데이터 0건을 `SUA-AUTH-001~005`로 정의했다.
- UX·UI: 큰 단계 탭을 제거하고 phone·OTP를 인라인으로 펼치며 필수동의는 한 번만 받는다.
- 설계·개발: 익명 challenge와 HttpOnly 가입 의도, claim→Auth→finalize saga를 권고했다.
- 검수·비판: 증거 재사용·세션 바꿔치기·동시 제출·고아 계정과 실제 SMS 미검수를 출시 차단으로 분류했다.
- 시간선·대안: 기존 2단계와 화면만 합치는 안보다 익명 사전 OTP가 현재 목표와 장기 운영에 가장 적합하다고 판단했다.
- 총괄비서: 신규 비밀번호 가입만 변경하고 OAuth·기존 미완료 복구는 보존하는 통합안을 채택했다.

## 합의된 기본값

- 이메일 확인은 현재 Supabase 설정을 유지한다.
- 성공 challenge 개인정보는 즉시 제거하고 실패·만료 데이터는 최대 24시간 안에 정리한다.
- 기존 미완료 계정은 새로 만들지 않고 이어서 완료한다.
- 구현 전에 서면 명세를 한 번 승인받고 이후 반복 확인 없이 실패 테스트부터 진행한다.

## 현재 상태

구현 전 사용자 서면 검토 대기다. 제품 코드는 변경하지 않았다.
