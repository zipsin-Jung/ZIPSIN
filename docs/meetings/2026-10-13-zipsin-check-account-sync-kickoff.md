# 2026-10-13 집신체크 단일계정·후보기록 이전 최초회의

- 상태: G1~G4 설계 전 사용자 방향 승인 대기
- 요청: 운영 배포를 제외하고 집신체크 사용자가 집신 회원으로 가입하고 선택한 체크 자료를 이어 쓰는 단계까지 준비
- 참여 역할: 총괄비서, 제품기획, UX·UI 디자인, 설계·개발, 검수·비판, 시간선·대안 분석

## 확인된 사실

- 집신체크는 현재 `/ck`의 로그인 없는 공개 도구이며 텍스트는 localStorage, 사진은 IndexedDB에만 저장한다.
- `집신에 저장하기`는 가입 영역으로 이동할 뿐 실제 인증·DB·파일 이전은 없다.
- 집신체크 전용 계정이 아닌 집신 단일 계정을 사용한다는 방향은 사용자 승인된 `DEC-014`, `DEC-017`, `DEC-019`와 일치한다.
- 현재 앱은 `output: export` 정적 구조이고 Supabase 의존성·환경값·마이그레이션·서버 세션이 없다.
- 역할 선택이나 주소 일치만으로 특정 집·계약의 접근 권한을 주어서는 안 된다.

## 회의 결론

비회원 사용자는 가입 없이 계속 체크한다. 저장을 직접 선택한 사용자만 집신의 가입·로그인으로 이동한다. 가입자는 `집신체크 유입`과 `집 구하는 중/임차인` 온보딩 제안을 받지만 직접 확인·변경할 수 있고, 이 값만으로 다른 집·계약 권한은 생기지 않는다.

이전 전에는 후보별로 별칭, 위치·조건, 담당자 연락처, 현장 5개, 메모와 사진을 보여 주고 포함 범위를 직접 선택하게 한다. 선택 자료는 계정 소유자만 보는 `후보집 초안`으로 저장하며 사무소·임대인·기존 집 이력에 자동 공유하거나 병합하지 않는다. 서버 확인 전 로컬 원본을 삭제하지 않고, 가입 취소·인증 오류·사진 부분 실패에는 로컬 기록과 재시도 경로를 유지한다.

## 구조 대안

### A. 같은 Next.js 앱 + Supabase 단일 백엔드 — 권고

- `/ck`, `/login`, `/onboarding`, `/my/candidates`를 같은 앱과 세션으로 운영한다.
- Supabase Auth, Postgres RLS, 비공개 Storage를 사용한다.
- 장점: 단일 계정과 기록 이전이 가장 단순하고 기존 결정과 일치한다.
- 위험: 정적 export를 서버 런타임으로 전환하므로 랜딩·데모·기존 경로 회귀검수가 필요하다.

### B. `ck.zipsin.net` 별도 앱 + 중앙 인증

- 캠페인 운영은 독립적이지만 쿠키 도메인, 콜백, 배포와 장애 범위가 복잡해진다.
- 현재 규모에서는 이른 분리이며 6개월 뒤 팀·트래픽·배포주기가 실제로 분리될 때 재검토한다.

### C. 가입 화면만 모의 구현

- 화면은 빠르지만 실제 유입·복원·권한을 검증할 수 없고 사용자가 실제 연동으로 오해할 수 있다.
- 배포 전 완성이라는 요청을 충족하지 못하므로 채택하지 않는다.

## 제안 범위

### 포함

- 집신 신규·기존 계정 로그인 진입과 세션 복구
- 가입 유입 출처와 `집 구하는 중/임차인` 유형 확인
- 후보 1~3채의 필드·사진 이전 사전검토와 별도 동의
- 본인 전용 후보집 초안, 중복 방지 키, 부분 실패·재시도·복구
- 다른 브라우저에서 서버 후보 복원
- 후보 삭제 진입과 로컬 원본 별도 삭제 선택
- 환경값 예시, DB 마이그레이션·RLS·Storage 정책, Preview 검수 자료

### 제외

- 운영 배포, DNS와 실제 Production OAuth 활성화
- 주소 기반 기존 집 이력 연결
- 사무소·임대인 자동 공유와 계약 관계 생성
- 입주·퇴거 기록 자동 전환, 공개 리뷰, 마케팅 자동 동의
- 실제 휴대전화 인증 공급자·결제 연결

## 제안 인증 범위

Preview 이전에는 Google·Kakao를 Supabase 기본 OAuth로 연결할 수 있게 구현하고, 환경값이 없으면 `준비 중`으로 표시한다. Naver Custom OAuth와 실제 휴대전화 인증은 어댑터·화면·실패 상태까지만 준비하고 운영 공급자 키 연결은 별도 승인으로 둔다. 이메일만으로 서로 다른 소셜 계정을 자동 병합하지 않는다.

## 요구사항 초안

- ZCA-001: 가입 없이 체크·비교를 계속하며 가입 취소·실패 뒤 로컬 기록을 유지한다.
- ZCA-002: 집신 단일 계정만 사용하고 인증 완료 전 이전 성공으로 표시하지 않는다.
- ZCA-003: 유입 출처와 임차인 유형을 저장하되 사용자가 확인하며 집 접근 권한과 분리한다.
- ZCA-004: 이전 후보·필드·사진과 목적·공개범위를 사전검토하고 별도 동의를 받는다.
- ZCA-005: 선택 자료만 본인 비공개 후보집 초안으로 중복 없이 이전한다.
- ZCA-006: 서버 저장 결과와 누락 항목을 검증하고 다른 브라우저에서 복원한다.
- ZCA-007: 취소·인증 오류·네트워크 중단·사진 부분 실패에 로컬 원본과 재시도를 보존한다.
- ZCA-008: 후보 초안과 장기 집 이력·계약 공간을 분리한다.
- ZCA-009: 서버 후보 삭제와 로컬 원본 삭제를 별도 행동으로 제공한다.

## 화면 흐름 초안

`/ck 결과·비교 → 이전 미리보기 → 집신 로그인/가입 → 임차인 유형·동의 → 텍스트·사진 이전 → 전체/부분/실패 결과 → 내 후보집`

가입·로그인을 취소하면 동일한 `/ck` 후보와 비교 선택으로 돌아간다. 이전 화면은 `나만 봄`, `옮기는 자료`, `옮기지 않는 자료`를 고정 표시한다. 현장 체크 중 가입 화면을 자동으로 띄우지 않는다.

## 위험과 검증 문턱

- 정확 주소·연락처·사진은 개인정보로 분류하고 서버·RLS·Storage에서 본인만 접근하게 한다.
- 이전 요청은 idempotency key로 중복 후보·사진을 막고 부분 성공 항목을 숨기지 않는다.
- 세션 없음, 다른 사용자 ID, 만료·철회, 직접 URL, 위험한 redirect를 서버에서 거부한다.
- 측정 대상 제품 코드의 statements/branches/functions/lines 각각 80% 이상, 권한 음성 시나리오 100%, P0/P1 0건을 요구한다.
- 320px·390px·1440px, 키보드, 200% 확대, 실제 OAuth Preview 취소·재시도, 다른 브라우저 복원을 검수한다.

## 사용자 승인안

권고안 A와 제안 범위로 서면 제품·UX·기술 명세와 구현계획을 작성한다. 민감정보 보존기간과 실제 공급자 키는 운영 배포 승인 때 확정하고, 배포 전 코드는 사용자 직접 삭제가 가능한 본인 비공개 후보 초안으로 제한한다.
