# 2026-10-13 집신 에이전트 시스템 확장 전체회의

## 참석 역할

- 총괄비서
- 기획·디자인 관점
- 설계·개발 관점
- 검수·비판 관점

새 체계 적용 뒤 최초 회의부터 제품기획, UX·UI 디자인, 설계·개발, 검수·비판, 시간선·대안 분석과 총괄비서의 여섯 역할을 사용한다.

## 공통 확인

- 기존 체계에 사전 순서 보고, 기획→설계→개발→테스트→승인, 문서·대화·Git 저장, 비삭제와 독립 검수가 이미 존재한다.
- 최신 요청을 강제하려면 기획과 UX 디자인 분리, 구현 전 테스트 설계, 네 커버리지 지표, 소스·테스트 증거 형식과 별도 시간선 역할이 필요하다.
- 현재 커버리지 80%는 저장소 전체가 아니라 데모 핵심 파일 2개 측정 결과다.

## 통합 결론

1. 기존 4역할 기록을 삭제하지 않고 6역할 체계로 확장한다.
2. 제품기획과 UX·UI 디자인을 별도 SOC·SOP로 분리한다.
3. 시간여행은 근거 기반 시간선·대안 분석 역할로 제한한다.
4. 모든 신규 프로젝트·서브프로젝트·기능·첫 구조 변경은 6역할 회의로 시작한다.
5. G1 제품기획, G2 UX·UI, G3 기술설계, G4 테스트설계를 승인받은 뒤 개발한다.
6. 대표 기능은 요구사항부터 소스 심볼, 테스트명과 실행 증거까지 양방향 매핑한다.
7. 제품 코드의 라인·문장·함수·분기 커버리지 각각 80%를 기본 게이트로 삼되 범위와 제외를 공개한다.
8. 에이전트는 영구 삭제를 실행하지 않고 복구·감사 계획과 사용자 결정을 요청한다.

## 시간선 스킬 baseline

`TL-BL-001`은 6개월 뒤 성공·실패를 확실히 말하라는 압력 상황이다. 기존 규칙만으로는 상태 유지안·가역 실험·근거 분리와 확률 위장을 자동 검사하기 부족하다고 판정했다. 새 `zipsin-timeline-analysis` 스킬은 이 실패를 직접 막도록 작성한다.

문서와 스킬 작성·검증 후 사용자 승인 대기.
