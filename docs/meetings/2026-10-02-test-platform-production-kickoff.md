# 테스트 플랫폼 실제 구축·배포 킥오프 회의

- 날짜: 2026-10-02
- 상태: 간편가입 구조 승인, 운영정보·인증업체 결정 대기
- 참석 역할: 총괄비서, 기획·디자인, 설계·개발, 검수·비판

## 사용자 요청

7개 승인 시안을 실제 클릭 가능한 플랫폼으로 만들고, 회원가입까지 연결해 배포한다.

## 확인된 현재 상태

- 기존 랜딩페이지는 Next.js App Router로 구현되어 `start.zipsin.net`에 배포되어 있다.
- `/test-platform`은 아직 존재하지 않는다.
- 현재 사전가입 폼은 검증 후 체험 완료 화면만 보여주며 개인정보를 저장하거나 전송하지 않는다.
- 프로젝트는 정적 내보내기 방식이므로 실제 접수를 위해서는 서버 런타임과 안전한 저장소가 필요하다.
- 7개 기준 시안은 `public/images/test-platform-flow-01~07.png`이다.

## 네 역할의 공통 결론

1. 기존 랜딩페이지를 유지하고 `/test-platform` 아래 7개 화면을 구현한다.
2. 집·기록·일정·챗봇은 우선 가상 데이터 기반의 완전한 클릭형 체험으로 만든다.
3. 회원가입의 의미를 먼저 확정해야 한다.
   - 로그인 가능한 실제 서비스 계정 생성
   - 출시 알림을 위한 사전가입 접수
4. 개인정보가 실제 저장되는 기능은 수집 항목, 목적, 보유기간, 삭제 요청 방법, 운영 문의처와 저장 서비스가 확정되어야 공개 배포할 수 있다.
5. 성공 화면은 서버 저장 또는 계정 생성 성공 응답을 받은 뒤에만 표시한다.
6. Preview 배포에서 가입·모바일·접근성·오류를 확인한 후 운영 배포한다.

## 요구사항 초안

- `TP-NAV-001`: 7개 화면의 공통 메뉴와 직접 URL 이동
- `TP-ONB-001`: 집 유형을 선택하는 첫 시작 흐름
- `TP-HOME-001`: 내 집 검색·선택·추가 체험
- `TP-REC-001`: 기록 목록·필터·빈 상태
- `TP-REC-002`: 새 기록 입력·검증·데모 저장
- `TP-REC-003`: 기록 상세·수정·상태 전환
- `TP-CAL-001`: 월 이동·필터·일정 추가·연결 기록 이동
- `TP-AI-001`: 실제 AI 연결 전 규칙형 챗봇과 관련 기록 이동
- `TP-PRIV-001`: 주소만으로 접근 금지, 이전 계약자 정보 미노출
- `TP-AUTH-001`: 회원가입 방식 결정 후 상세화

## 권장안

가장 작은 공개 MVP는 7개 클릭형 플랫폼과 실제 사전가입 접수를 결합하는 안이다. 로그인 가능한 계정은 인증, 복구, 세션, 탈퇴와 권한 정책이 추가되므로 별도 범위로 보는 것이 안전하다. 다만 사용자가 실제 계정 생성을 원하면 Supabase Auth 같은 검증된 인증 서비스를 사용하고 비밀번호를 직접 저장하지 않는다.

## 배포 차단 조건

- 회원가입 의미와 개인정보 운영 내용이 미확정
- 저장 성공 전에 가입 완료로 표시
- 비밀키 또는 개인정보가 Git·브라우저 코드·로그에 포함
- 핵심 버튼 미연결 또는 `/test-platform` 주요 경로 404
- 모바일·키보드 가입 불가
- 실제 배포 주소에서 브라우저 검수 미실시
- P0·P1 결함 존재

## 다음 승인 지점

사용자가 카카오·네이버·구글 간편가입, 별도 휴대전화 인증, 이름·이메일 확인과 약관 동의를 포함한 실제 계정 생성을 승인했다. 다음 승인 지점은 개인정보 운영정보와 휴대전화 인증업체 확정이다. 상세 결정은 `docs/decisions/DEC-008-social-signup-and-minimum-data.md`를 따른다.
