# 2026-09-30 에이전트 시스템 최초 회의

## 참석 역할

- 총괄비서
- 기획·디자인
- 설계·개발
- 검수·비판

## 목적

집신의 네 에이전트 지침과 재사용 스킬을 실제 파일로 만들기 전에 역할 경계, 작업 순서, 개인정보 위험과 품질 기준을 교차 검토한다.

## 역할별 핵심 의견

### 기획·디자인

- 요구사항마다 역할, 진입조건, 모든 화면 상태, 수락기준, 측정지표와 개인정보 범위를 기록해야 한다.
- 가격·인증·보존기간·법률적 의미·최종 권한 정책은 단독 확정하지 않는다.
- MVP를 집 등록→업무 기록→담당·다음 행동→인수인계 핵심 루프 중심으로 우선순위화해야 한다.

### 설계·개발

- 승인된 요구사항 ID가 없으면 구현하지 않는다.
- 구현 전에 권한표, 데이터 분류, 요구사항 추적과 개인정보 위협을 검토한다.
- 계약별 기록, 장기 집 이력, 사무소 내부 메모와 개인 데이터를 서버에서 분리해야 한다.
- 데이터 변경은 백업·호환성·롤백 계획이 선행되어야 한다.

### 검수·비판

- 검수자는 직접 수정하고 같은 결과를 스스로 승인하지 않는다.
- 테스트는 권한 거부, 계약 종료, 직원 퇴사, 초대 만료·재사용과 이전 계약 정보 누출을 포함해야 한다.
- 80% 커버리지는 품질 보증이 아니라 최소 경보선이다.
- 품질 판정은 통과·조건부 통과·실패로 통일하고 사용자 승인 전에는 승인 대기로 유지한다.

## 통합 결론

- 네 역할 구조를 유지하고 추가 역할을 만들지 않는다.
- 여섯 재사용 스킬에 세 역할의 세부 제안을 흡수한다.
- 개인정보·권한 설계, 요구사항 추적, 안전한 마이그레이션은 별도 에이전트가 아니라 `zipsin-feature-delivery`의 필수 단계로 포함한다.
- 독립 검수와 기록 동기화를 모든 큰 작업의 종료 조건으로 사용한다.

## 상태

회의 결론을 반영해 파일을 생성하고 검증했으며, 2026-09-30 사용자 최종 승인을 받았다.
