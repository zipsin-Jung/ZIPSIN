# 집신 로그인 홈 재설계 최초회의

- 일자: 2026-10-13
- 상태: 사용자 승인 대기
- 역할: 총괄비서, 제품기획, UX·UI, 설계·개발, 검수·비판, 시간선·대안

## 통합 결론

사용자 시안의 `좌측 탐색·현재 집 선택·기록 체크·최근 기록` 원리는 살린다. 그러나 모든 메뉴와 빈 카드를 그대로 구현하면 사용자가 우려한 복잡한 제품이 되므로, 모든 역할이 같은 집 중심 셸을 쓰고 `집 없음 → 기록 준비 → 일상 업무`의 세 상태에 따라 필요한 내용만 공개한다.

## 역할별 핵심 의견

- 제품기획: 로그인 홈은 광고가 아니라 집 등록·첫 기록·초대로 이어지는 실제 시작 화면이어야 한다.
- UX·UI: 첫 사용자에게는 한 화면 한 행동을 제공하고, 활동 사용자에게는 실제 집·기록·채팅·일정을 우선한다.
- 설계·개발: 실제 구현 문서 ZH-UX-001~004와 Task 1~6을 보강해 이어가며, 홈 조회와 권한 경계를 한 서비스에 모은다.
- 검수·비판: 가짜 진행률·AI·사진을 금지하고, 체크 완료를 실제 저장 데이터로만 계산한다. 알림 수와 채팅 수의 의미 오류도 수정 대상으로 포함한다.
- 시간선·대안: 전체 대시보드 복제는 메뉴 폭증 위험이 있고 온보딩 마법사만 제공하면 반복 사용자에게 느리다. 공통 셸과 상태별 점진 공개가 가장 가역적이다.
- 총괄비서: 디자인 승인 한 번 뒤 테스트 우선 구현, 브라우저 검수, Preview 승인을 거쳐야 한다.

## 이미지 결론

- 흩어진 컴퓨터 파일과 휴대전화 사진: 첫 사용자 기본 장면
- 외출 중 필요한 계약서와 집 서랍 종이: 계약·중요 날짜 상세 장면
- 확인하기 어려운 천장형 에어컨: 주요 설비 상세 장면
- 한 화면에는 큰 교육 이미지 한 장만 사용한다.
- 실제 집에는 AI·스톡 사진을 넣지 않는다.

## 선행 실패 분석

1. 보기 좋은 카드를 계속 추가하면 우선순위가 사라진다. 강한 CTA는 상태별 한 개로 제한한다.
2. 신규 사용자 설명을 영구 노출하면 반복 사용자가 이탈한다. 활동 상태에서는 교육 영역을 축소한다.
3. 역할별 홈을 복제하면 예외가 폭증한다. 공통 컴포넌트와 권한 기반 행동을 사용한다.
4. 수동 체크로 완료율을 만들면 제품 신뢰가 무너진다. 각 완료 근거를 실제 레코드로 정의한다.

## 승인 게이트

- G1: 공통 메뉴, 세 홈 상태, 기록 6항목 승인
- G2: 1440px·390px의 첫 사용자/활동 사용자 시안과 이미지 위치 승인
- G3: 데이터·권한·RLS·상태 전환 설계 확인
- G4: 단위·통합·E2E와 추적표
- G5: 실제 브라우저와 Preview 검수
- G6: 사용자 승인 뒤에만 Production 검토
