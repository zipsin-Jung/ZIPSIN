# 집신 테스트 플랫폼 구축·배포 통합 프롬프트

아래 내용을 개발 에이전트에게 그대로 전달하세요.

---

## 역할

당신은 집신(ZIPSIN)의 기획·설계·프론트엔드 개발·테스트·배포를 담당하는 숙련된 제품 개발자다. 기존 저장소를 보존하면서, 승인된 7개 화면 시안을 실제 클릭 가능한 Next.js 사이트로 구현한다. 계획만 제시하지 말고 구현, 검증, 문서화까지 완료한다.

## 작업 시작 순서

1. `AGENTS.md`, `WORK_STATUS.md`, `CONTINUE.md`, `CLAUDE.md`, `docs/BRIEF.txt`, `docs/00-working-rules.md`를 먼저 읽는다.
2. 현재 Git 상태와 기존 코드를 확인하고 사용자 작업 및 관계없는 변경을 보존한다.
3. 작업 순서와 영향 범위를 짧게 보고한다.
4. 기획 → 설계 → 개발 → 테스트 → 수정 → 완료보고 순서로 진행한다.
5. 기존 랜딩페이지를 삭제하거나 전면 교체하지 않는다.

## 목표

집 한 채를 기준으로 수리, 비용, 계약, 문서, 사진과 일정을 기록하고 다시 찾는 집신의 테스트 플랫폼을 구축한다. 고령 사용자도 첫 화면을 보고 바로 사용할 수 있어야 한다. 복잡한 관리자 도구나 담당자 배정 중심 화면을 만들지 않는다.

기존 랜딩페이지는 유지하고 테스트 플랫폼은 `/test-platform` 아래에 구현한다. 배포 후 랜딩페이지에서 테스트 플랫폼으로 이동할 수 있는 명확한 체험 버튼을 제공한다.

## 화면별 필수 기능

### 1. 처음 시작

- 문구: `처음이시군요. 집 한 채부터 천천히 시작해요.`
- 선택: `현재 사는 집`, `소유한 집`, `관리하는 집`
- 하나를 선택해야 `다음` 버튼이 활성화된다.
- `도움말 보기`를 누르면 쉬운 설명을 표시한다.

### 2. 내 집

- 집 카드, 집 이름 검색, 집 추가 카드를 제공한다.
- 카드의 `보기`를 누르면 해당 집 기록으로 이동한다.
- 데모 집은 `현재 사는 집`, `부모님 집` 두 채로 구성한다.
- 실제 주소나 개인정보는 사용하지 않고 가상 데이터만 사용한다.

### 3. 집 기록

- `전체`, `수리`, `비용`, `계약`, `점검` 필터를 제공한다.
- 기록은 날짜순 타임라인으로 보여준다.
- 예시 기록: 보일러 점검, 관리비 납부, 거실 페인트 시공, 임대차 계약 갱신.
- `새 기록 남기기`를 누르면 작성 화면으로 이동한다.

### 4. 새 기록

- 분류 선택, 사진·문서 추가, 내용 입력, 공개 범위를 제공한다.
- 파일 선택은 브라우저 안에서 미리보기만 제공하며 외부 서버에 전송하지 않는다.
- 필수 항목이 비어 있으면 항목 가까이에 쉬운 오류 문구를 표시한다.
- 저장하면 데모 데이터에 기록을 추가하고 성공 안내 후 기록 목록으로 이동한다.
- 새로고침하면 초기화될 수 있음을 화면에서 명확히 알린다.

### 5. 기록 상세·진행 확인

- 제목, 상태, 날짜, 집, 사진, 설명과 진행 이력을 표시한다.
- 상태는 `접수 → 확인 → 완료` 순서로 변경할 수 있다.
- `완료로 표시`와 `내용 수정`을 제공한다.
- 특정 직원이나 담당자 배정을 필수로 만들지 않는다.

### 6. 집 일정 캘린더

- 월 이동, 오늘 표시, 월간 달력, 오늘 일정, 다가오는 일정을 제공한다.
- 분류: 전체, 수리, 비용, 계약.
- `일정 추가`를 누르면 제목, 날짜, 분류, 연결할 집을 입력하는 간단한 창을 연다.
- 일정 선택 시 연결된 기록 상세 또는 일정 상세를 보여준다.
- 일정 추가와 변경은 프론트엔드 데모 상태로만 작동한다.

### 7. 집신이 챗봇

- 제목: `집신이에게 물어보기`
- 추천 질문:
  - `이번 달 집 일정 보여줘`
  - `보일러 점검 기록 찾아줘`
  - `계약 갱신 전에 무엇을 준비할까?`
- 사용자가 추천 질문을 누르거나 문장을 입력하면 미리 준비된 데모 답변을 표시한다.
- 답변에는 관련 집, 기록 또는 일정으로 이동하는 링크를 제공한다.
- 화면에 항상 `화면 예시 · 실제 AI 연결 전`이라고 표시한다.
- `선택한 집의 허용된 기록만 사용해요.`라는 개인정보 안내를 표시한다.
- 외부 AI API, 실제 계약서 분석, 법률 확정 답변은 구현하지 않는다.
- 계약 관련 답변에는 `일반적인 준비 안내이며 법률 자문이 아닙니다.`를 표시한다.

## 데이터와 권한 원칙

- 이번 버전은 가상 데이터로 작동하는 프론트엔드 테스트 사이트다.
- 로그인, DB, 결제, 실제 파일 업로드, 실제 AI, 실제 접수는 구현하지 않는다.
- 주소만 안다고 기록을 볼 수 있게 만들지 않는다.
- 이전 계약자의 개인정보가 다음 계약자에게 이어지는 것처럼 표현하지 않는다.
- 공개 범위는 복잡한 사진별 권한보다 `나만`, `현재 집 구성원`, `선택한 사람`처럼 쉬운 기본값을 우선한다.
- 실제 기능이 아닌 부분은 `데모`, `예시`, `연결 전`으로 명확하게 표시한다.

## 상태와 사용성

각 핵심 화면은 가능한 범위에서 다음 상태를 갖는다.

- 빈 상태
- 기본 상태
- 로딩 상태
- 성공 상태
- 입력 오류 상태
- 권한 없음 상태
- 찾을 수 없음 상태

모든 버튼은 실제 동작하거나 비활성 이유가 보여야 한다. 의미 없는 버튼과 `#` 링크를 남기지 않는다. 모바일 터치 영역은 최소 44px로 만들고, 200% 확대와 키보드 이동에서도 주요 기능을 사용할 수 있게 한다.

## 테스트 요구사항

- 단위 테스트: 필터, 상태 변경, 폼 검증, 달력 날짜 처리, 챗봇 데모 응답 매칭
- 컴포넌트 테스트: 집 선택, 새 기록 저장, 일정 추가, 추천 질문 선택
- 시나리오 테스트:
  1. 처음 방문 → 집 유형 선택 → 내 집 → 집 기록
  2. 새 기록 작성 → 목록 확인 → 상세 → 완료 처리
  3. 캘린더 → 일정 추가 → 다가오는 일정 확인
  4. 챗봇 추천 질문 → 답변 → 연결 기록 이동
- 접근성 검사: 레이블, 키보드, 포커스, 대비, 확대, 모바일 터치 영역
- 반응형 검사: 1440px, 1024px, 390px, 320px
- `npm run typecheck`, 테스트 명령, `npm run build` 모두 통과
- 새로 작성한 테스트 플랫폼 코드 기준 코드 커버리지 80% 이상을 목표로 하고 결과를 보고한다.
- 빌드 성공을 브라우저 검수 성공으로 표현하지 않는다.
- 실제 브라우저에서 메뉴, 폼, 필터, 상태 변경, 캘린더와 챗봇 흐름을 클릭 검수한다.

## 문서화

- 요구사항과 화면 흐름을 관련 `docs/` 문서에 반영한다.
- 제품 방향에 영향을 주는 결정은 `docs/decisions/`에 기록한다.
- 수행 순서, 변경 파일, 테스트·브라우저 결과와 남은 일을 `docs/worklogs/`에 기록한다.
- 긴 제품 대화는 `docs/conversations/`에 저장한다.
- 작성 문서는 바탕화면 문서함 `/Users/zipsin/Desktop/코덱스랑/집신/`에도 같은 구조로 복사한다.
- 개인정보, 인증정보와 실제 계약서 원본은 Git에 저장하지 않는다.

## 배포

1. 기존 Vercel 프로젝트와 설정을 먼저 확인한다.
2. 기존 랜딩페이지와 `start.zipsin.net` 연결을 깨뜨리지 않는다.
3. 모든 검사와 브라우저 검수 후 Git 변경사항을 검토한다.
4. 관련 파일만 커밋하고 원격 저장소에 안전하게 푸시한다.
5. Vercel 배포 결과와 실제 URL을 확인한다.
6. 배포된 `/test-platform`에서 데스크톱과 모바일 핵심 흐름을 다시 확인한다.
7. 인증정보를 요청하거나 코드에 넣지 않는다. 사용자 로그인이 필요한 경우에만 마지막에 간단히 안내한다.

## 완료 조건

- 7개 화면이 실제 경로와 React 컴포넌트로 구현되어 있다.
- 공통 메뉴로 모든 핵심 화면에 이동할 수 있다.
- 기록 작성, 상태 변경, 일정 추가와 챗봇 예시가 데모 범위에서 작동한다.
- 실제 저장·AI 연결이 아니라는 표시가 명확하다.
- 기존 랜딩페이지가 유지된다.
- 타입 검사, 테스트, 빌드와 실제 브라우저 검수 결과가 기록되어 있다.
- 배포 URL에서 핵심 흐름이 작동한다.
- 사용자 최종 승인 전에는 작업을 완전 종료로 표시하지 않는다.

최종 보고는 `완성한 내용`, `직접 확인한 결과`, `아직 데모인 기능`, `배포 주소`, `사용자 승인 필요사항` 순서로 짧고 쉽게 작성한다.
