# 토스 홈페이지 심층 분석과 집신 적용안

- 작성일: 2026-10-13
- 목적: 토스를 복제하지 않고 집신 메인페이지의 정보 밀도·신뢰·장면 전환 원칙을 설계한다.
- 비교 참고: 문토의 따뜻한 생활 감성

## 1. 핵심 결론

토스의 완성도는 파란색, 큰 글씨, 휴대전화 목업 하나에서 나오지 않는다. 사용자가 스크롤할 때마다 **생활 장면 → 불편의 해소 → 실제 제품 동작 → 안전과 결과**가 한 장면씩 이어지기 때문에 이해가 빠르다.

집신은 토스의 제품 설명 구조와 문토의 따뜻한 생활 감성을 결합하는 방향이 적합하다.

- 토스에서 가져올 것: 한 화면 한 메시지, 실사와 실제 UI의 결합, 강한 정보 위계, 제품 동작 증명, 일관된 컴포넌트
- 문토에서 가져올 것: 생활감 있는 사진, 크림색 배경, 부드러운 색, 친근한 카테고리 진입
- 집신이 독자적으로 지킬 것: 집별 기록, 초대와 관계 권한, 개인정보 분리, 기록의 연속성

권장 비율은 **신뢰 60% + 따뜻함 40%**다.

## 2. 토스 현재 홈페이지의 화면 문법

### 첫 장면

- 전체 폭 실사 영상으로 사용자의 평범한 일상을 먼저 보여준다.
- 제품 설명을 길게 하지 않고 “금융부터 일상까지, 마침내 토스 하나로”라는 결과를 크게 보여준다.
- 상단 메뉴는 얇고 조용하며 본문 장면을 방해하지 않는다.

### 제품 장면

- “몇 번만 누르면 끝나는 송금”처럼 행동과 결과가 한 문장에 들어간다.
- 설명 옆에는 장식 이미지가 아니라 실제 사용 순간과 제품 화면이 함께 나온다.
- 스크롤 중 배경과 문장이 교체되며 사용자는 기능 목록이 아니라 사용 장면을 경험한다.

### 정보 위계

1. 가장 큰 결과 문장
2. 실제 생활 사진 또는 제품 동작
3. 짧은 보충 설명
4. 필요한 경우에만 버튼과 세부 정보

한 장면에 여러 카드와 긴 문단을 동시에 넣지 않는다.

### 신뢰 방식

- 안전을 추상적인 자물쇠 아이콘만으로 설명하지 않는다.
- 실제 위험 상황, 경고, 보호 기능과 결과를 구체적으로 보여준다.
- 성과 수치는 기준 날짜와 출처 범위를 함께 표시한다.

## 3. 토스 디자인 시스템에서 확인한 원칙

토스 디자인 시스템은 디자인 파일에만 머무르지 않고 코드와 연결된 공통 언어를 지향한다. 목표는 최소 품질 보장, 일관성 유지, 생산성 향상, 인터랙션·애니메이션·템플릿의 완성도 통일이다.

집신도 페이지마다 다른 카드·색·버튼을 즉흥적으로 만드는 방식에서 벗어나 다음을 공통화해야 한다.

- 색상 토큰
- 제목·본문·보조문구 크기
- 버튼의 우선순위
- 기록 카드와 상태 배지
- 집 카드와 타임라인
- 채팅 말풍선과 첨부
- 빈 화면·오류·권한 종료 상태

## 4. 문토와 토스의 차이

| 구분 | 문토 | 토스 | 집신 적용 |
|---|---|---|---|
| 첫 인상 | 밝고 다정한 생활 | 차분하고 영화 같은 신뢰 | 따뜻한 집의 실사 + 단단한 문장 |
| 정보 구조 | 많은 콘텐츠를 빠르게 탐색 | 한 장면씩 제품 이해 | 메인은 장면 중심, 로그인 후는 탐색 중심 |
| 색 | 크림·핑크·노랑 등 감성색 | 흰색·회색·블루 중심 | 아이보리·세이지 + 딥네이비·청록 |
| 이미지 | 사람·취향·후기 중심 | 생활 실사 + 제품 UI | 집 안의 실제 순간 + 집신 UI |
| 신뢰 | 후기와 참여자 | 제품 동작·안전·수치 | 권한·기록·과정의 가시화 |

문토식 카드 나열을 메인 전체에 적용하면 집신이 가벼운 커뮤니티로 보일 수 있다. 토스식 차가운 금융 분위기만 적용하면 집이 가진 생활감과 공감이 사라진다.

## 5. 현재 집신 메인의 문제

- 스크롤 길이에 비해 실제 제품 화면이 적다.
- 문장과 단순 카드가 반복되어 다음 장면의 기대가 약하다.
- 계약·사진·수리·일정·채팅이 실제로 어떻게 연결되는지 한눈에 보이지 않는다.
- 따뜻한 집의 감정과 기록 보안의 신뢰가 분리되어 있다.
- 사용자가 “그래서 들어가면 무엇을 하는가”를 충분히 확인하지 못한다.

## 6. 집신 메인 권장 구조 — 다섯 장면

### 장면 1 — 집의 순간

핵심 문장: **이 집에서 있었던 일, 필요한 순간 다시 찾을 수 있도록.**

- 따뜻한 오후의 실제 집 사진
- 작은 집신 타임라인 UI
- CTA: `내 집 기록 시작하기`, `로그인`

### 장면 2 — 흩어진 기록이 집으로 모이는 순간

핵심 문장: **사진첩·대화방·서류철에 흩어진 기록을 집 하나에.**

- 왼쪽에서 사진·PDF·대화·일정이 들어온다.
- 오른쪽 집 타임라인에 실제 항목으로 정리된다.
- 추상적인 아이콘만 사용하지 않고 제품 UI를 보여준다.

### 장면 3 — 세 사람이 같은 내용을 보는 순간

핵심 문장: **한 번 남기면 필요한 사람들이 같은 기록을 봅니다.**

- 임차인의 수리 요청
- 공인중개사의 확인
- 임대인의 진행 과정 확인
- 별도 ‘담당자’ 개념은 넣지 않는다.

### 장면 4 — 권한과 개인정보가 분리되는 순간

핵심 문장: **집의 기록은 이어지고, 사람의 권한은 필요한 만큼만.**

- 주소만으로 열람 불가
- 초대·관계 확인 후 접근
- 계약 종료 시 이전 임차인의 개인정보 자동 분리
- 말이 아니라 권한 상태 UI로 보여준다.

### 장면 5 — 필요한 기록을 꺼내는 순간

핵심 문장: **퇴거할 때도, 수리할 때도, 다시 찾지 않도록.**

- 입주 사진, 계약 문서, 수리 전·중·후, 영수증, 대화를 타임라인에서 선택
- PDF 정리는 ‘추후 제공’으로 표시하거나 출시 범위에서 제외
- 마지막 CTA로 실제 회원가입 연결

## 7. 시각 방향

### 색상

- 기본 배경: 따뜻한 아이보리 `#FAF7F1`
- 본문 글자: 딥네이비 `#173142`
- 신뢰 강조: 청록 `#0E7668`
- 생활 강조: 세이지 `#C9DCCB`
- 감정 포인트: 살구 `#F2B49A`
- CTA: 블루 또는 청록 중 하나만 주 행동으로 사용

### 이미지

- 한국 아파트·빌라·원룸의 자연스러운 실사
- 손, 창가, 입주 박스, 벽 상태 확인, 수리 과정처럼 기록이 필요한 순간
- 과장된 모델 포즈, 큰 3D 집 아이콘, 캐릭터 중심 Hero 금지

### 타이포그래피

- 한 화면의 가장 큰 문장은 1개
- 설명은 두세 줄 이내
- 문장보다 제품 UI가 더 많은 정보를 증명하게 한다.

## 8. 가져오면 안 되는 것

- 토스의 로고·브랜드 블루·영상·문구·레이아웃 복제
- 스크롤 애니메이션을 위한 과도한 무거운 영상
- 실제로 구현하지 않은 기능을 작동하는 것처럼 표현
- 근거 없는 고객 수·절감률·성과 수치
- 따뜻함을 이유로 보안과 권한 설명을 약하게 만드는 것
- 문토처럼 콘텐츠 카드를 끝없이 나열하는 구조
