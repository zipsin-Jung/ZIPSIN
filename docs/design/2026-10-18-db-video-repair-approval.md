# DB 설계: 30초 동영상 · 수리 5단계 · 임대인 승인(DEC-029)

- 작성: 2026-10-18 (Claude, 브랜치 `claude/app-rebuild-2026-10-18`)
- 상태: 설계안. **Preview DB 적용 전 대표 승인 필요.** 운영 DB는 출시 때 새로 만든다(D2 추천).
- 근거: 2026-10-18 고르기판 "제안" 전부 채택(⑥ 임대인 승인 3번 누르기, ⑦ 단계마다 누르는 사람 고정·작은 수리 건너뛰기), DEC-029, 수리 5단계(접수 중 → 임대인 확인 → 일정 조율 → 수리 완료 → 영수증 첨부), 30초 동영상 포함 결정
- 검사 방법: 로컬 Postgres에 모든 migration 적용 + 여러 계정 권한 검사(`supabase/tests/local/`). 이것은 "로컬 RLS 검사"이며 Preview DB 검수와 다른 증거다.

## 0. 원칙

1. 화면에서 숨겨도 최종 판단은 DB가 한다. 새 기능도 모두 `security definer` 함수 + RLS로 막는다.
2. 기존 기록은 지우지 않는다. 상태와 이력만 더한다.
3. 이전 계약자의 개인정보·대화는 다음 계약자에게 넘어가지 않는다. 집 이력에는 이름·연락처를 넣지 않는다.
4. 실제 문자 발송·외부 계정 설정은 대표 승인 뒤에만 켠다.

## 1. 30초 동영상 (migration `202610180001`)

| 항목 | 설계 |
|---|---|
| 형식 | `video/mp4`, `video/quicktime`(아이폰 .mov) |
| 크기 | 동영상 50MB 이하, 사진·PDF는 지금처럼 20MB 이하 |
| 길이 | 30초 이하. 휴대폰에서 올리기 전에 길이를 재서 막는다(서버는 길이를 못 잰다 → 크기로 한 번 더 막음) |
| 저장소 | `home-records` 버킷 허용 형식에 동영상 추가, 버킷 한도 50MB |
| 확인 필요 | Supabase 요금제별 업로드 한도(무료 50MB). 현재 요금제 확인 전에는 "50MB"를 확정으로 쓰지 않는다 |

## 2. 수리 5단계 (migration `202610180002`)

- `records`에 수리 칸 추가: `repair_stage`(received · landlord_review · scheduling · completed · receipt_attached), `repair_stage_changed_at`, `repair_estimated_cost_won`
- `repair_stage_events`: 누가 · 언제 · 어느 단계에서 어느 단계로 · 방법(앱에서 누름 / 전화 확인 / 작은 수리 건너뜀). 서버 전용, 화면에는 함수로만 보여 준다.
- 단계를 넘기는 함수 `advance_repair_stage(record, to_stage, method, note)` 하나로만 바꾼다.

| 단계 → 다음 | 누르는 사람 | 조건 |
|---|---|---|
| 접수 중 → 임대인 확인 | 임차인 · 중개사(대표·소속) | 수리 기록이 "이번 계약 공유" 칸이어야 함(임대인이 봐야 하므로) |
| 임대인 확인 → 일정 조율 | **임대인**(앱) | — |
|  | 중개사: **임대인에게 전화로 확인받음** | 체크한 사람·시각을 남긴다(DEC-029 A안과 같은 방식). 임대인에게 알림 |
|  | 중개사: **작은 수리라 건너뛰기** | 임대인이 미리 정한 금액 이하일 때만. 금액은 임대인 승인 때 임대인이 정한다(없으면 버튼 안 보임) |
| 일정 조율 → 수리 완료 | 중개사 | 이 단계가 시작된 뒤 올린 **후 사진**이 있어야 함 |
| 수리 완료 → 영수증 첨부 | 중개사 | 수리 완료 뒤 올린 파일(영수증)이 있어야 함 |

- 수리기사·임차인 전용 화면은 파일럿 뒤(⑧). 수리기사 버튼은 이번 범위에서 만들지 않는다.
- 사무소 내부 칸의 수리 기록은 단계 없이 메모로 남는다.

## 3. 임대인 승인 (migration `202610180003`, DEC-029)

### 흐름 (임대인은 3번 누르기)
1. 중개사: 임대인 휴대폰 번호 입력 + **"등기부상 소유자와 본인을 확인했어요"** 체크 → 요청
2. 임대인: 문자 링크(48시간·1회용) → 문자 인증번호 → 공유 범위 미리보기 → **승인 / 거절**. (선택) 작은 수리 허용 금액
3. 승인 뒤 언제든 철회: 같은 방식(문자 링크 → 인증)으로 철회

### 표
- `landlord_approval_requests`: 집, 사무소, 요청한 사람, 확인 체크한 사람·시각, 임대인 번호(해시 + 끝 4자리만), 토큰 해시, 만료(48시간), 사용 시각, 상태(대기·승인·거절·만료·철회)
- `home_landlord_approvals`: 집, 사무소, 승인 시각, 철회 시각, 작은 수리 허용 금액. **집마다 활성 승인은 한 사무소만.** 다른 사무소를 승인하면 예전 승인은 자동 철회
- 원래 전화번호는 문자 발송 순간에만 서버 메모리에서 쓰고 DB·Git·기록에 남기지 않는다.

### 권한 변화
| 칸 | 읽기 | 쓰기 |
|---|---|---|
| 집 이력 `shared_history` | 승인받은 사무소 직원, 현재 계약 임대인 | 승인받은 사무소의 대표·소속 |
| 예전 사무소(승인 철회·변경) | 자기 사무소가 쓴 집 이력만 | 없음 |
| 이전 임차인(DEC-029 4번) | 자기가 올린 기록·파일 + 자기 계약 요약 | 없음 |

### 하지 않는 것 (첫 버전)
- 휴대폰 인증을 "소유자 인증"이라고 표시하지 않음
- 등기부 업로드·대조, 공동 소유·법인·대리인 승인
- 주소로 기존 기록이 있는지 알려 주기

## 4. 알림

- `notifications.notification_kind`에 `repair_stage`, `landlord_approval` 추가. 지금은 채팅 알림만 있어 `room_id`, `message_id`가 필수인데, 새 종류에서는 `record_id` 또는 `home_id`를 쓰도록 바꾼다.
- 알림을 받는 사람: 수리는 다음에 누를 사람 + 접수한 사람, 승인은 요청한 사무소 대표·요청자.

## 5. 대표 결정이 필요한 것

| 번호 | 질문 | 추천 | 이유 |
|---|---|---|---|
| D-a | 임대인이 집신에 가입하지 않았을 때 "임대인 확인"은? | 중개사의 **"전화로 확인받음" 체크**(누가·언제 남김) + 임대인에게 알림 문자 | 지금도 전화로 확인하는 현장 방식을 그대로 기록. 문자 링크 승인은 집 승인에만 먼저 쓰고, 수리까지 넓힐지는 파일럿 승인 비율을 보고 결정 |
| D-b | 작은 수리 허용 금액 | 임대인이 승인할 때 고르게(예: 없음 / 5만 / 10만 / 20만원) | 사무소가 정하면 임대인 동의 근거가 없음 |
| D-c | 문자 발송(Solapi) | **노출된 Secret을 새로 발급한 뒤**에만 켜기 | 노출된 키로 보내면 남이 대신 보낼 위험 |

## 6. 적용 순서

1. 로컬 Postgres 적용 + 여러 계정 권한 검사 통과(필수)
2. 대표 승인 → Preview(지금 DB)에 복사 버튼 페이지로 적용
3. Preview에서 실제 계정 여러 개로 다시 확인
4. 출시 때 새 운영 DB에 전체 migration 적용
