# 공개형 V1 계정 데이터와 접근 통제

## 데이터 등급

| 데이터 | 등급 | 저장·표시 원칙 |
|---|---|---|
| 사용자 UUID·주 역할 | 내부 | 본인 세션에서만 조회 |
| 이름·이메일 | 개인정보 | 본인만 조회·수정, 로그 제외 |
| 전화번호·인증 시각 | 중요 개인정보 | 번호 마스킹, 인증번호 저장 금지 |
| 동의 종류·버전·시각 | 준법 기록 | 본인 조회, 필수 이력 덮어쓰기 금지 |
| OAuth·SMS 비밀값 | 비밀정보 | 환경 비밀 저장소만 사용, DB·Git 금지 |

## 접근 원칙

- 네 테이블 모두 RLS를 활성화한다.
- `profiles`, `consent_acceptances`, `user_roles`는 `auth.uid() = user_id`인 본인만 읽을 수 있다. 민감한 쓰기는 검증된 `SECURITY DEFINER` RPC로만 수행한다.
- `phone_verification_states`는 본인이 결과만 읽을 수 있고 쓰기는 서버 전용 경로만 수행한다.
- 역할 선택은 집·사무소·계약 참여 레코드를 만들지 않는다.
- 서비스 관리자용 우회 정책은 이번 단계에 추가하지 않는다.

## 위협과 대응

- 타인 UUID 변조: RLS와 서버 세션 사용자 ID를 함께 검사한다.
- 전화 인증 결과 위조: 브라우저 쓰기 권한을 회수하고 공급자 검증 성공 후 서버만 기록한다.
- 동의 이력 덮어쓰기: 같은 문서 종류·버전은 처음 기록을 유지하고, 새 버전은 별도 행으로 보존한다.
- 비밀키 노출: 공개 환경변수에는 Supabase URL과 anon key만 허용한다.

## migration과 되돌림

첫 배포 전 빈 데이터베이스에 migration을 적용한다. 적용 실패 시 트랜잭션을 취소한다. 되돌려야 할 때는 신규 가입 진입을 먼저 끈 뒤, 데이터가 없는 Preview에서는 생성 역순으로 네 테이블을 삭제할 수 있다. 실제 사용자 데이터가 생긴 환경에서는 내보내기·행 수 검증·보존정책 확인 없이 테이블을 삭제하지 않는다.

## 감사 대상

이번 단계에서는 동의 버전과 시각을 보존한다. 집 초대, 참여 종료, 역할 권한 변경과 결제 상태 변경 감사는 해당 기능 단계에서 추가한다.

## 집·사무소 기록 접근 경계

- 주소나 집 ID만으로는 어떤 기록도 열 수 없다.
- 사무소 구성원은 개인 계정으로 접속하고, 활성 사무소 소속과 활성 집 담당 관계를 모두 확인한다.
- 대표 공인중개사는 사무소가 맡은 집을 볼 수 있고, 소속공인중개사와 보조원은 자신에게 배정된 집만 본다.
- 임대인·임차인·수리 참여자는 활성 `home_memberships` 관계가 있어야 집에 접근한다.
- `office_internal` 기록은 해당 사무소만, `current_contract` 기록은 그 계약 참여자와 담당 사무소만, `shared_history`는 현재 권한이 있는 참여자만 본다.
- 현재 임차인은 같은 주소의 이전 계약과 이전 임차인 정보를 볼 수 없다.
- 보조원은 사진 등록·일정 관리·단순 문서 정리는 할 수 있지만, 설명·조건 조율·계약 승인 권한은 갖지 않는다.
- 관계가 종료되면 사람의 접근 권한은 즉시 끝나고, 집과 사무소의 업무 기록은 삭제하지 않고 보존한다.

이번 migration은 로컬 코드에만 추가했다. Supabase Preview나 운영 DB에는 아직 적용하지 않았다.
