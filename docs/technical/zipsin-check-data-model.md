# 집신체크 계정 이전 데이터 모델

## 소유권과 분류

- `profiles`와 `signup_attributions`는 계정 정보입니다. 특정 집·계약·사무소 권한이 아닙니다.
- `candidate_drafts`는 계정 소유자만 보는 집 후보 초안입니다.
- 답·메모·사진은 후보에 종속되며 후보 삭제 시 함께 삭제됩니다.
- 이전 manifest는 재시도와 서버 검증을 위한 운영 메타데이터입니다.

## 접근 제어

모든 제품 테이블은 RLS를 사용합니다. 후보와 manifest는 `auth.uid()`가 소유자와 같을 때만 접근합니다. 하위 답·사진·이전 항목은 부모 레코드의 소유자를 확인합니다. Storage bucket `candidate-photos`는 비공개이며 첫 경로 조각이 `auth.uid()`와 같아야 합니다.

## 삭제 경계

서버 후보 삭제는 그 후보의 답과 사진 메타데이터만 연쇄 삭제합니다. Storage 객체 삭제 결과는 별도로 확인해야 합니다. 다른 후보, 장기 집 이력, 계약, 사무소 관계에는 영향을 주지 않습니다. 현재 브라우저의 로컬 원본도 자동 삭제하지 않습니다.

## 적용과 롤백

Preview 환경에서 `supabase db reset`과 `supabase test db`를 통과한 뒤 migration을 적용합니다. 롤백은 계정 저장 CTA를 먼저 비활성화하고 기존 로컬 흐름을 유지합니다. 이미 저장된 사용자 데이터는 자동 삭제하지 않으며, 파괴적 down migration 대신 후속 migration으로 정책·schema를 수정합니다.

현재 개발 컴퓨터에는 Docker 실행환경이 없어 pgTAP 테스트를 실제 DB에 적용하지 못했습니다. 이 항목은 Preview 전 필수 차단 게이트입니다.
