## 2026-10-13 현장형 간소화 승인 요구사항

사용자의 실제 현장 판단을 최우선으로 하여 `/ck`의 기본 흐름을 입력·설명 중심에서 즉시 기록 중심으로 바꾼다. 기존 ZC 요구사항은 방문 후 요약·비교·꼼꼼히 보기에서 유지하고, 현장 기본 화면에는 다음 요구사항을 우선 적용한다.

| REQ-ID | 요구사항 | 수락기준 |
|---|---|---|
| ZCF-001 | 즉시 시작 | 로그인과 필수 입력 없이 `바로 체크 시작` 한 번으로 자동 별칭 후보를 만들고 핵심 9개 화면에 진입한다. |
| ZCF-002 | 현장 빠른 체크 | 항목마다 `괜찮음 / 확인 필요`를 한 번 눌러 기록하며, 미선택은 미확인으로 남는다. 버튼은 44px 이상이고 320px에서 가로 넘침이 없다. |
| ZCF-003 | 짧은 메모 | 각 항목에서 120자 이내 메모를 바로 적을 수 있고 상태를 고르지 않아도 저장된다. 연락처·출입정보는 저장 전에 차단한다. |
| ZCF-004 | 선택 사진 | 항목별 사진을 선택해 썸네일로 확인할 수 있고 사진 없이도 완료한다. 사진은 재인코딩 후 현재 브라우저 전용 저장소에만 저장하며 외부로 전송하지 않는다. |
| ZCF-005 | 실패 분리 | 사진 권한 거부·취소·형식 오류·용량 초과가 발생해도 기존 상태와 메모는 유지된다. 실제 사진 저장 전에 완료로 표시하지 않는다. |
| ZCF-006 | 같은 기록의 꼼꼼히 보기 | `꼼꼼히 보기`는 같은 후보 답·메모·사진을 유지하면서 추가 7개와 이유·방법·근거를 보여준다. |
| ZCF-007 | 방문 종료 | `방문 끝내기`로 요약에 이동하며 괜찮음·확인 필요·미확인을 분리해 보여준다. |

사진은 계정 저장이나 백업이 아니다. 브라우저 데이터가 지워지면 복구할 수 없고 다른 기기로 이동하지 않는다. 사람 얼굴, 신분증·계약서, 상세 주소·문패, 출입 비밀번호와 귀중품은 촬영하지 않도록 사진 입력 가까이에 안내한다.

## 1. 제품 목표

> 2026-10-13 공개형 UX 보정: 집신체크는 데모나 체험판이 아니라 누구나 로그인 없이 바로 쓰는 집신의 유입용 공개 도구다. 대표 진입 경로는 `zipsin.net/ck`이며 `/check`도 호환 경로로 유지한다. 첫 화면에서 후보 별칭, 선택적 동네·건물 별칭, 발견 경로, 주택 유형, 거래 유형을 한 번에 받고, 빠른 9개 또는 꼼꼼한 16개 항목을 넘김 없이 한 화면에 보여준다. 결과는 신용카드 비교표처럼 후보 카드와 공통 9개 기준표로 비교한다.

집을 짧게 보고 결정해야 하는 사람, 빠뜨림 없이 꼼꼼히 확인하고 싶은 사람, 무엇을 왜 확인하는지 모르는 사람이 **같은 핵심 기준**으로 집을 확인하고 비교하게 한다.

집신체크는 사용자를 세 종류로 고정하지 않는다. 같은 사람이 첫 집에서는 자세한 설명을 보고, 다음 집에서는 빠르게 체크할 수 있다. 따라서 하나의 체크 항목에 다음 세 층을 둔다.

1. **빠르게 체크**: 현장에서 바로 판단하는 공통 핵심 항목
2. **더 꼼꼼히**: 공간·계약·생활 조건에 따른 추가 항목
3. **왜 확인하나요?**: 이유, 확인 방법, 이상할 때 물어볼 질문

## 2. 대상과 역할별 가치

| 역할 | 현재 문제 | V1 가치 | 범위 |
|---|---|---|---|
| 예비 임차인 | 짧은 방문 중 무엇을 확인할지 모르고 집마다 다른 방식으로 메모함 | 핵심은 빠르게, 필요하면 자세히 확인하고 같은 기준으로 비교 | V1 주 사용자 |
| 임차인 | 집을 선택한 뒤 방문 기록이 입주 기록으로 이어지지 않음 | 선택한 집의 확인 결과를 이후 입주 체크로 전환 | V1은 전환 예고, 실제 연결은 후속 |
| 공인중개사 | 고객마다 반복 질문이 다르고 확인 내용을 다시 설명함 | 고객이 다시 물어볼 항목을 정리해 질문 가능 | V1 자동 공유 제외 |
| 임대인 | 방문자의 주관 메모가 사실 판정처럼 유통될 수 있음 | 사용자 관찰·설명·서류·전문가 확인을 구분 | V1 직접 참여 제외 |

## 3. 제품 원칙

- 깊이 선택은 시작 장벽을 낮추는 수단이지 다른 체크 기준을 만드는 기능이 아니다.
- 빠른 체크와 꼼꼼 체크는 공통 핵심 항목을 공유해 후보 집 비교가 가능해야 한다.
- `왜 확인하나요?`는 별도 긴 강의가 아니라 각 항목에서 필요할 때 펼친다.
- 설명을 읽지 않아도 체크를 완료할 수 있고, 설명을 펼치면 `왜·어떻게·무엇을 물을지`를 알 수 있어야 한다.
- 체크 결과는 안전·하자·법률 판단이 아니라 사용자 관찰과 추가 확인 목록이다.
- `확인 못함`은 나쁜 점수가 아니라 다음 행동을 알려주는 상태다.
- 한 화면에서 여러 항목을 바로 체크하되, 완료를 위한 주요 행동은 `체크 결과 정리하기` 하나로 둔다.

## 4. 정보 구조

```text
집신체크 시작
├─ 빠르게 체크
│  └─ 공통 핵심 8~10개
└─ 꼼꼼하게 체크
   ├─ 공통 핵심 8~10개
   └─ 공간·생활·계약 추가 항목

각 체크 항목
├─ 상태 선택: 확인됨 / 주의 / 확인 못함 / 전문가 확인 필요
├─ 더 꼼꼼히: 추가 확인
└─ 왜 확인하나요?
   ├─ 이유
   ├─ 확인 방법
   └─ 물어볼 질문

완료
→ 장점 / 주의 / 미확인 / 다시 물어볼 것
→ 후보 2~3채 비교
→ 저장·복원 시 집신 가입
```

## 5. 기능 요구사항

### ZC-001 시작 방식 선택

- 사용자: 예비 임차인
- 트리거: 집을 보러 가기 전 또는 현장 도착
- 전제: 가입하지 않아도 시작 가능
- 주 흐름: `빠르게 체크` 또는 `꼼꼼하게 체크` 선택
- 상태:
  - 빈 상태: 첫 방문 안내와 두 선택지만 표시
  - 로딩: 체크 항목 준비 중 표시
  - 성공: 첫 공통 핵심 항목으로 이동
  - 오류: 기본 빠른 체크로 다시 시작 가능
  - 권한거부: 해당 없음, 비회원 가능
  - 종료: 언제든 나가되 기기 내 임시 진행 복구 안내
- 개인정보: 동네·건물 별칭은 선택 입력이며 상세 주소·동호수·연락처는 받지 않는다.
- AC-ZC-001-A: 두 선택의 예상 시간과 항목 수가 표시된다.
- AC-ZC-001-B: 어느 방식을 선택해도 동일한 공통 핵심 항목이 포함된다.
- AC-ZC-001-C: 진행 중 `빠르게만 보기` 또는 `더 꼼꼼히 보기`로 바꿔도 기존 답이 유지된다.
- 성공지표: 시작 선택 후 첫 항목 도달률 90% 이상을 검증 목표로 삼는다.

### ZC-002 공통 핵심 빠른 체크

- 사용자: 시간이 부족하거나 반복 방문 중인 예비 임차인
- 트리거: 빠르게 체크 선택
- 전제: 주택·거래유형을 알면 맞춤 표시, 모르면 공통 항목 제공
- 주 흐름: 핵심 9개를 넘김 없이 한 화면에서 원하는 순서로 확인
- 핵심 범주: 습기·곰팡이, 채광·환기, 소음, 수압·배수, 창호, 냉난방, 보안·공용부, 관리비·생활동선, 계약 전 공식 확인 안내
- 상태: 답변 전, 답변 완료, 건너뜀, 이전 답변 수정, 연결 끊김 후 복구
- 개인정보: 후보 별칭과 동네·건물 별칭은 선택 입력이며, 상세 주소·동호수는 입력하지 않도록 안내한다.
- AC-ZC-002-A: 사진 없이도 모든 핵심 항목을 완료할 수 있다.
- AC-ZC-002-B: 각 항목은 최소 44×44px 터치 영역과 읽기 쉬운 한국어를 사용한다.
- AC-ZC-002-C: 건너뛴 항목은 자동으로 `확인 못함`에 모인다.
- AC-ZC-002-D: 빠른 체크 완료 목표 시간은 사용성 테스트에서 중앙값 3~5분 이내다.
- 성공지표: 시작 대비 빠른 체크 완료율 70% 이상을 검증 목표로 삼는다.

### ZC-003 꼼꼼한 추가 체크

- 사용자: 중요한 결정을 앞두고 빠뜨림 없이 확인하려는 예비 임차인
- 트리거: 시작 시 꼼꼼하게 선택하거나 진행 중 추가 확인 펼침
- 전제: 공통 핵심과 동일한 후보에 연결
- 주 흐름: 공간별·생활별·계약 준비별 추가 항목 확인
- 상태: 추천 추가 항목 있음, 해당 없음, 모두 접음, 일부 완료, 모두 완료
- 개인정보: 개인 메모는 기본 비공개
- AC-ZC-003-A: 공통 핵심 답변을 다시 요구하지 않는다.
- AC-ZC-003-B: 추가 항목은 방·욕실·주방·창호·공용부·생활환경처럼 짧은 묶음으로 나뉜다.
- AC-ZC-003-C: 사용자는 추가 묶음을 건너뛰거나 `해당 없음`으로 표시할 수 있다.
- AC-ZC-003-D: 꼼꼼 모드를 중단해도 공통 핵심 결과 요약을 볼 수 있다.
- 성공지표: 꼼꼼 모드 사용자의 공통 핵심 완료율이 빠른 모드보다 낮아지지 않는지 확인한다.

### ZC-004 왜·어떻게·무엇을 물을지 설명

- 사용자: 체크 이유나 방법을 모르는 예비 임차인
- 트리거: 항목의 `왜 확인하나요?` 선택
- 전제: 설명 없이도 상태 선택 가능
- 주 흐름: 짧은 이유 → 확인 방법 → 이상할 때 물어볼 질문 확인
- 상태: 접힘, 펼침, 공식 확인 필요, 외부 근거 갱신 필요
- 개인정보: 없음
- AC-ZC-004-A: 설명은 기본으로 접혀 있고 체크 진행을 막지 않는다.
- AC-ZC-004-B: 설명은 `왜`, `어떻게`, `물어볼 말`을 각각 1~3문장으로 제공한다.
- AC-ZC-004-C: 법률·전기·가스·구조·권리관계는 사용자 관찰과 공식 서류·전문가 확인을 구분한다.
- AC-ZC-004-D: 근거가 바뀔 수 있는 항목은 출처와 확인 기준일을 관리할 수 있어야 한다.
- 성공지표: 설명을 펼친 사용자가 도움 여부를 5점 척도 평균 4점 이상으로 평가하는지 검증한다.

### ZC-005 관찰 상태와 메모

- 사용자: 모든 예비 임차인
- 트리거: 체크 항목 확인
- 주 흐름: `확인됨 / 주의 / 확인 못함 / 전문가 확인 필요` 중 하나 선택, 선택적으로 메모
- 상태: 미선택, 선택, 수정, 저장 실패, 금지정보 경고
- 개인정보: 현관 비밀번호·열쇠 위치·연락처·상세 주소 입력 금지
- AC-ZC-005-A: `확인됨`은 안전 보증이 아니라 사용자가 직접 확인했다는 뜻으로 설명된다.
- AC-ZC-005-B: 사용자 관찰, 중개인 설명, 서류 확인, 전문가 확인 출처를 구분할 수 있다.
- AC-ZC-005-C: 상태 변경 이력이 최종 요약에 올바르게 반영된다.
- AC-ZC-005-D: 금지 안전정보로 판단되는 입력에는 저장 전 경고한다.
- 성공지표: 상태 의미를 안전등급으로 오해하는 사용성 테스트 사례 0건.

### ZC-006 방문 결과 요약

- 사용자: 방문을 마친 예비 임차인
- 트리거: 체크 종료
- 주 흐름: 장점, 주의, 확인 못함, 다시 물어볼 질문을 항목 근거와 함께 확인

## 13. 미결정 사항

- V1의 정확한 공통 핵심 8~10개와 공식 근거 문구
- 전세·월세 중 첫 광고 메시지 우선순위
- 비회원 임시 결과의 기기 내 보존기간
- 사진 기능을 V1에서 완전히 제외할지 제한적으로 포함할지
- 가입 후 후보 기록 보존기간과 삭제·내보내기 정책
- 프로토타입 검증 후 가입 전환 성공 기준

이 항목은 G3 기술 설계나 공개 전에 결정하며 제품 명세 승인과 동시에 임의 확정하지 않는다.

## 14. 승인 요청

사용자에게 다음을 승인받으면 G1 제품기획과 G2 UX·UI 범위를 고정하고 기술 설계와 구현계획 단계로 넘긴다.

1. 하나의 체크 항목에 `빠르게 / 더 꼼꼼히 / 왜 확인하나요?` 세 층을 둔다.
2. 공통 핵심 8~10개로 서로 다른 체크 깊이의 집도 비교한다.
3. 첫 MVP는 사진 없이도 완주 가능하며 최대 3채 비교까지 포함한다.
4. 첫 결과는 가입 없이 보고, 저장·복원 가치에서 집신 가입을 안내한다.
5. 단일 안전점수·등급과 AI 판정은 제외한다.

## 15. 2026-10-13 비교 중심 V2 구현 증거

현재 구현 기준은 `docs/superpowers/specs/2026-10-13-zipsin-check-comparison-design.md`의 ZCC-001~008이다. 간단·상세 등록, 필수 5개, 메모 안 사진, 선택 순서형 2~3채 비교, 전체 사진 펼침, 안전한 재연락과 영구 삭제를 구현했다. 세부 AC→화면→함수→정확한 테스트명 연결은 `docs/worklogs/2026-10-13-zipsin-check-comparison-implementation.md`의 요구사항 추적표를 기준으로 한다.

최종 자동 실행은 `npm run test:coverage` 15개 파일·81개 테스트 전부 통과, statements 86.04%, branches 83.18%, functions 84.81%, lines 95.31%다. `npm run typecheck`와 `npm run build`도 통과했고 `/ck` 정적 생성을 확인했다.
