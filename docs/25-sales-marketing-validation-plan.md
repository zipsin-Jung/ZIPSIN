# 집신 영업·마케팅 검증 계획

- 작성일: 2026-10-18
- 상태: **G1 제품 방향·G2 접점 흐름 사용자 승인 대기**
- 개발 원칙: 제품 개발은 Claude에서 진행하며, 이 계획은 코드 변경을 포함하지 않는다.

## 1. 목표와 사용자 가치

집신의 첫 영업 목표는 많은 사람에게 알리는 것이 아니라, 문제가 뚜렷한 공인중개사무소가 실제 자료·직원·일정을 투입하고 향후 결제까지 약속할 정도로 집신의 가치를 느끼는지 확인하는 것이다.

핵심 고객 가설은 다음 조건을 가진 사무소다.

- 대표와 직원 1명 이상이 함께 근무한다.
- 다가구·임대관리 등 여러 집을 반복 관리한다.
- 최근 6개월 안에 직원 변경 또는 인수인계를 경험했다.
- 사진·문서·일정·연락이 개인 휴대전화, 카카오톡, PC와 종이에 흩어져 있다.
- 자료 찾기, 반복 연락, 답변 대기, 재방문 또는 업무 누락이 실제로 발생한다.

핵심 메시지 초안은 다음과 같다.

> 집 사진과 다음 할 일을 집 한 채에 모아, 담당자가 바뀌어도 업무가 이어집니다.

## 2. 확인된 사실과 가설

### 확인된 사실

- 집신은 수리기사 매칭 서비스가 아니라 집 중심 기록·업무 협업 서비스다.
- 초기 결제 고객과 도입 채널은 공인중개사무소다.
- 실제 사용자는 대표 공인중개사, 보조원, 임대인과 임차인이다.
- 현재 영업 자산은 랜딩페이지와 가상 자료 기반 `/demo`다.
- 실제 가입, 저장, 초대, 상담 접수, 결제와 PDF 다운로드는 아직 구현되지 않았다.

### 검증할 가설

- 담당 변경과 자료 찾기 문제가 반복되는 사무소는 집신 도입에 시간과 비용을 쓸 의사가 있다.
- `집별 기록 + 담당 업무 인계` 메시지가 수리 또는 광고 플랫폼으로 오해되지 않는다.
- 월 249,000원과 299,000원 중 하나를 실제 결제로 검증할 수 있다.

월 99,000원은 2026-10-02 초기 가설이고, 249,000원·299,000원은 2027 계획의 최신 비교 가설이다. 사용자 승인 전에는 어느 가격도 확정 가격으로 외부에 표시하지 않는다.

## 3. 채널 우선순위

1. **대표 직접영업:** 고객의 실제 업무, 반대 이유와 언어를 가장 빠르게 학습한다.
2. **따뜻한 소개:** 업계 지인, 기존 인터뷰 참여자와 지역 교육 모임에서 소규모로 재현성을 확인한다.
3. **콘텐츠:** 인터뷰에서 반복된 문제를 익명·가상 사례로 만들어 직접영업을 돕는다.
4. **유료광고:** 실제 사용, 결제, 8주 유지와 획득비용 근거가 생긴 뒤에만 시험한다.

세 채널을 동시에 확대하지 않는다. `직접영업으로 고객군·문구 검증 → 소개로 재현성 확인 → 콘텐츠·광고로 규모화` 순서를 따른다.

## 4. 영업 흐름

`대상 선정 → 최근 실제 사례 인터뷰 → 3분 가상 데모 → 현재 업무 확인 → 미래 파일럿 조건 협의 → 실제 집 5채·구성원 2명 준비 약속 → 제품 준비 후 14일 체험 → 실제 결제 → 8주 유지`

현재 단계에서는 미래 파일럿 참여 약속까지만 검증한다. 제품이 준비되지 않은 상태에서 체험, 실제 사용 또는 결제가 완료됐다고 표현하지 않는다.

### 접점별 한 가지 행동

- 전화·문자: 최근 인수인계 또는 자료 찾기 사례를 묻고 15분 방문을 약속한다.
- 첫 방문: 현재 사용하는 휴대전화·폴더·수첩 흐름을 확인한다.
- 데모: `멈춘 업무 → 집 기록 → 담당 변경 → 새 담당자의 다음 행동`을 직접 보게 한다.
- 데모 종료: 실제 집 5채와 구성원 2명으로 검증할 설계 파트너 참여 의향을 묻는다.
- 후속 연락: 확인한 문제, 다음 일정과 준비 행동만 짧게 정리한다.

데모 시작과 끝에는 `가상 자료·비저장·비전송·비접수`임을 분명히 고지한다.

## 5. 4주 최소 실험

### 1주차: 문제 확인

- 적합 조건의 사무소 20~30곳을 목록화한다.
- 10곳에 접촉하고 최소 5곳의 최근 실제 사례를 인터뷰한다.
- 자료 위치 수, 찾는 시간, 반복 연락, 최근 인수인계와 업무 누락을 기록한다.

### 2주차: 메시지와 데모 확인

- 문제 강도가 높은 5~8곳에 3분 데모를 관찰한다.
- 30초 소개문 두 안만 비교한다.
- 완료 시간, 도움 요청, 중단 지점과 자발적 한 문장 설명을 기록한다.

### 3주차: 비용 있는 약속 확인

- 가장 반응이 좋은 고객군과 문구 하나로 8~10곳에 추가 접근한다.
- 적격 사무소에만 미래의 14일 파일럿 조건을 설명한다.
- 실제 집 5채 준비, 직원 1명 동석, 시작 일정 확정과 가격 대화 여부를 확인한다.

### 4주차: 계속·수정·중단 판정

- 퍼널, 문제 강도, 오해, 거절 이유와 다음 행동을 결산한다.
- 최소 3곳이 실제 자료·직원·일정 준비에 동의하면 제품 준비 후 유료 실증으로 이동한다.
- 기준 미달이면 광고비와 영업 인력을 늘리지 않고 고객군·메시지·핵심 흐름을 다시 정한다.

## 6. 성공지표와 증거 수준

### 4주 영업 전 검증 지표

- 적합 사무소 20~30곳 목록
- 10곳 이상 접촉
- 5곳 이상 최근 사례 인터뷰
- 5곳 이상 데모 관찰
- 데모 참여자 5명 중 4명 이상이 3분 안에 핵심 흐름 완료
- 5명 중 4명 이상이 집신을 `집별 기록과 사무소 업무 인계 서비스`에 가깝게 설명
- 3곳 이상이 실제 집 5채·구성원 2명·시작 일정 준비에 동의
- 2곳 이상이 제시 가격과 결제 조건을 구체적으로 협의

### 증거 단계

- E0: 내부 추측
- E1: 호감과 사용 의향 발언
- E2: 최근 실제 사례의 구체적 설명
- E3: 허락받은 현장 관찰, 시간 측정 또는 비식별 비용 확인
- E4: 일정 확정, 직원 동석, 자료 준비처럼 비용이 드는 행동
- E5: 반복 사용
- E6: 실제 결제와 8주 유지

이번 4주의 목표는 E3~E4다. E5~E6은 실제 제품 준비 후 별도 검증한다.

## 7. 최소 운영 도구와 개인정보 기준

- 기존 `/demo`, 통화·대면 인터뷰, 비식별 검증표와 주간 30분 회고만 사용한다.
- 새 CRM, 자동발송 도구와 유료광고는 이번 4주에 도입하지 않는다.
- 검증표에는 무작위 ID, 구 단위 권역, 인원 구간, 유입경로, 단계, 문제 증거, 데모 결과, 거절 이유와 다음 날짜만 둔다.
- 실명, 개인 휴대전화, 정확 주소, 계약서, 등기, 계좌와 임대인·임차인 정보는 검증표·Git·공유 문서에 저장하지 않는다.
- 후속 연락처가 필요하면 검증표와 분리된 접근 제한 연락처부에 목적과 보유기간을 정해 보관한다.

## 8. 위험과 중단 조건

- 칭찬만 있고 자료·직원·일정 준비가 없으면 검증 실패다.
- 대표만 관심 있고 직원이 참여하지 않으면 파일럿 적격에서 제외한다.
- 수리기사 매칭 또는 광고 앱으로 오해하면 문구를 수정하고 확대하지 않는다.
- 한 고객만 요청한 맞춤 기능은 세 곳 이상에서 반복 확인되기 전 영업 약속으로 만들지 않는다.
- 가격 반대와 가치 부족을 구분해 기록한다.
- 개인정보 원본을 복사하거나 데모를 실제 제품으로 오인시키면 즉시 중단하고 절차를 수정한다.

## 10. 역할과 승인 게이트

- 총괄비서: 범위, 주간 판정, 기록과 승인 관리
- 제품기획: 고객 조건, 문제, 메시지, 퍼널과 지표
- UX·UI: 접점별 한 행동, 데모 이해와 오해 기록
- 설계·개발: 개인정보 최소화와 향후 파일럿 측정 구조 검토
- 검수·비판: 증거 수준, 과장 표현, 중단 기준 검사
- 시간선·대안: 직접영업→소개→광고 전환 조건 점검

승인 게이트는 다음과 같다.

- G1 제품: 고객군, 메시지, 4주 목표와 성공지표 사용자 승인
- G2 접점 UX: 연락·인터뷰·데모·후속 흐름 사용자 승인
- G3 운영 설계: 개인정보 분리, 기록표와 파일럿 조건 승인
- G4 검증 설계: 지표, 증거 단계, 계속·수정·중단 기준 승인
- G5 실행 검수: 4주 결과와 원자료 없는 비식별 증거 검토
- G6 사용자 승인: 다음 단계인 유료 실증 또는 채널 확대 승인

## 12. 네이버 블로그 실행 기록

2026-10-18 사용자 승인에 따라 비용 없는 콘텐츠 채널의 첫 실행으로 기존 네이버 블로그를 집신 기준으로 정비했다.

- 기존 글은 삭제하지 않고 모두 비공개 상태로 보존했다.
- 블로그명은 `집신 | 집 한 채의 기록과 업무`, 닉네임은 `집신지기`로 정리했다.
- 소개문은 계약부터 입주·수리·퇴거까지 집 한 채의 기록과 다음 할 일을 연결한다는 가치로 통일했다.
- `집신 소개`, `공인중개사 실무`, `집 기록 이야기`, `창업·개발 기록`의 네 하위 카테고리를 만들었다.
- 첫 글은 담당자 변경 시 흩어진 사진·문서·일정을 다시 찾는 문제를 설명하고, 현재는 실제 접수가 아닌 가상 3분 데모와 현장 문제 확인 단계임을 밝혔다.
- 첫 글 주소: `https://blog.naver.com/2hiworld/224445649666`

다음 콘텐츠는 실제 고객 사례를 꾸며내지 않고, 인터뷰에서 반복 확인된 문제 또는 가상 예시만 사용한다. 공개 게시물은 매회 사용자에게 제목·핵심 주장·공개 범위를 확인받은 뒤 발행한다.

### 공개 콘텐츠 정보 경계

- 공개 글은 고객이 자신의 문제를 알아차릴 수 있는 상황, 징후와 일반적인 점검 질문을 중심으로 작성한다.
- 제품의 데이터 구조, 권한 분리 방식, 상태 전환, 업무 인계 로직과 구현 순서는 공개 글에서 설명하지 않는다.
- 구체적인 해결 방식과 제품 차별점은 대상이 확인된 상담·인터뷰·가상 데모 안에서 필요한 범위만 보여준다.
- 실무 팁을 제공하더라도 그대로 복제할 수 있는 완결된 운영 설계나 체크리스트는 공개하지 않는다.
- 각 초안은 발행 전에 `독자 가치가 있는가`, `제품 핵심을 과도하게 공개하지 않는가`, `현재 제공 기능처럼 오해되지 않는가`를 함께 검수한다.

### 반복 운영 일정
