# 2026-09-30 에이전트 시스템 설계 대화 기록

## 사용자 요구의 변화

사용자는 처음에 기획, 설계, 개발, 테스트, 비판적 사고, 시간선 분석, 기록관리와 총괄 기능을 각각 에이전트로 두는 방안을 검토했다. 에이전트 수가 너무 많다는 판단에 따라 다음 네 역할로 단순화했다.

- 총괄비서
- 기획·디자인
- 설계·개발
- 검수·비판

사용자는 이 네 에이전트에 실제 지침과 설계 스킬을 적용해 만들고 최종 승인을 요청하도록 지시했다.

## 합의된 운영 방향

- 기획과 설계는 구분한다.
- 큰 작업의 시작에는 네 역할의 최초 회의를 진행한다.
- 작업 전 순서 보고, 작업 후 문서·대화·결정·결과 저장을 의무화한다.
- 사용자 승인 없이 영구 삭제하지 않는다.
- 기획 → 설계 → 개발 → 테스트 → 수정 → 완료 보고 → 사용자 승인 순서를 지킨다.
- 테스트는 PRD·유저플로우·UI·코드 추적성과 대표 기능의 소스·테스트 매칭을 보여준다.
- 코드 커버리지 80%는 최소 기준으로 사용하되 핵심 개인정보·권한 흐름은 더 엄격하게 검사한다.

## 스킬 설계 원칙

에이전트는 책임 주체이고 스킬은 반복 가능한 절차다. 제품의 현재 기능·가격·정책은 스킬에 중복 저장하지 않고 제품 문서에서 관리한다. 스킬은 프로젝트 시작, 제품기획, 기능 전달, 품질 검수, 결정 분석과 기록 동기화 여섯 개로 제한했다.

## 현재 상태

네 에이전트 파일과 여섯 스킬을 작성하고 형식 검증 및 역할별 독립 검토를 완료했다. 사용자의 최종 승인을 기다린다.
