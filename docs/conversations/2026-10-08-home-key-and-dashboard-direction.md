# 2026-10-08 집 키·홈 화면 방향 대화 정리

## 대화 목적

집신 홈페이지가 단순 기능 소개에 머무르지 않고, 사용자가 왜 필요하고 왜 비용을 낼 수 있는지 한눈에 이해하도록 제품 방향을 다시 정리했다. 공개 랜딩페이지와 로그인 후 실제 홈 화면을 구분하고, `집 키`의 의미와 안전한 접근 원칙을 논의했다.

## 사용자가 지적한 문제

- 기존 시안은 기능이 나열됐지만 사용자가 돈을 내야 하는 이유와 실제 사례가 약했다.
- 화면이 초보자가 만든 것처럼 보였고 전문성과 신뢰감이 부족했다.
- 공인중개사와 수리기사는 별도 세계의 사용자가 아니라 특정 집과 관계를 맺는 참여자다.
- 집 기록을 집 단위로 이어간다는 점은 등기부등본의 구조처럼 이해할 수 있다.
- 중요한 날짜는 로그인 후 홈에서 가장 먼저 보여야 한다.
- 한 집 화면에 매매 잔금, 전세 만기, 월세 납부를 동시에 넣은 시안은 실제 계약 상태를 섞은 잘못된 예시였다.
- 공개 홈페이지와 로그인 후 홈을 혼동하면 안 된다.

## 현재 합의된 제품 이해

### 공개 홈페이지

- 방문자가 집신이 어떤 플랫폼인지 바로 이해하는 소개 화면이다.
- 오른쪽 상단에 `로그인`과 `회원가입`을 항상 표시한다.
- 집신이 필요한 실제 상황과 결과를 설명한다.
- 개인의 실제 집 일정은 보여주지 않는다. 제품 미리보기는 하나의 일관된 가상 사례만 사용한다.

### 로그인 후 홈

- 사용자가 매일 확인하는 실제 서비스 화면이다.
- 집 한 채를 가진 일반 사용자를 첫 기준으로 삼는다.
- 선택한 집의 현재 관계는 자가·전세·월세 중 하나로만 표시한다.
- 가장 가까운 중요 일정 하나와 지금 해야 할 행동을 우선한다.
- 예: `전세 만기 D-38` → `임대인에게 갱신 의사 전달` → 입주 사진·계약 기록 확인.
- 여러 집을 관리하는 사용자는 집마다 가장 가까운 일정 하나씩 별도 카드로 확인한다.

## 아하 모먼트

첫 핵심 경험은 다음 문장으로 정의한다.

> 내가 놓치면 안 되는 우리 집의 다음 일이 바로 보인다.

기록을 많이 저장했다는 사실보다, 지금 중요한 날짜와 다음 행동을 놓치지 않는 경험을 먼저 제공한다. 수리 이력, 사진, 비용, 참여자는 그 행동을 돕는 근거로 연결한다.

## 비용을 낼 이유로 제안된 사례

| 상황 | 집신이 주는 결과 |
|---|---|
| 보일러가 다시 고장남 | 이전 업체·부품·사진·비용을 바로 확인 |
| 입주·퇴거 상태가 다름 | 입주 전후 사진과 요청 시점을 같은 흐름에서 확인 |
| 담당자가 변경됨 | 개인 카카오톡이 아니라 집에 남은 일정과 다음 행동을 인계 |
| 수리기사가 방문함 | 해당 수리에 필요한 사진·일정만 기간 한정으로 공유 |
| 다음 계약을 준비함 | 개인정보를 제외한 집 이력과 증빙을 보고서로 정리 |

단순 저장공간이나 기능 수보다 `놓친 일정 방지`, `반복 설명 감소`, `증빙 정리`, `인수인계`라는 결과를 과금 이유로 검증한다. `700원`은 확정 가격이 아니라 집 이력 보고서에 대한 구매 의향을 확인할 가설이다.

## 집 키의 권장 정의

`집 키`는 주소를 아는 사람이 입력하는 영구 비밀번호나 소유권 증명이 아니다.

- 주소는 집 후보를 찾는 시작점으로만 사용한다.
- 집 키가 없는 검색자에게는 주소·건물 구분 같은 공개 기본정보만 보인다.
- 집신 가입 여부, 기록 존재, 관계자, 사진, 일정과 비용은 공개하지 않는다.
- 집 키는 역할·범위·기간이 지정된 일회성 또는 단기 초대권이다.
- 로그인과 관계 확인 후 활성 멤버십을 만들고 키 자체는 재사용하지 않는다.
- 계약 종료, 직원 퇴사, 수리 완료 시 접근도 종료한다.

역할별 최소 범위:

- 임대인·임차인: 현재 계약과 자신이 참여한 기록
- 공인중개사·보조원: 배정된 현재 계약·업무
- 수리기사: 특정 수리 사건의 주소·방문 일정·필요 사진·완료 기록

## 개인정보·표현 금지선

- 주소만으로 비공개 기록을 열거나 기록 존재 여부를 노출하지 않는다.
- 하나의 영구 마스터 집 키를 사용하지 않는다.
- 이전 임차인의 연락처·대화·계약서·생활 사진을 다음 계약에 자동 승계하지 않는다.
- `공식 등기부`, `검증된 집 사실`, `소유권 증명`처럼 공적 효력을 암시하지 않는다.
- 장기 집 이력은 개인정보를 제거하고 필요한 확인을 거친 내용만 별도 보관한다.

## 폐기한 시안과 이유

- 매매 잔금, 전세 만기, 월세 납부를 한 집의 중요 일정처럼 동시에 보여준 시안은 폐기한다.
- 서로 양립하기 어려운 계약 상태를 섞어 실제 사용자의 상황을 표현하지 못했다.
- 랜딩페이지와 로그인 후 홈의 역할도 혼합되어 아하 모먼트가 불명확했다.

## 아직 결정되지 않은 사항

1. 집 키가 없는 주소 검색자에게 공개 기본정보를 어디까지 보여줄지
2. 최초 집 관리자 연결을 누가 어떤 근거로 확인할지
3. 어떤 기록을 개인정보가 제거된 장기 집 이력으로 올릴지
4. 계약 종료 후 임차인이 자신의 자료를 열람·내보낼 수 있는 기간
5. 첫 과금 실험을 건별 보고서, 집별 구독, 사무소 구독 중 무엇으로 시작할지

## 다음 작업

1. 공개 홈페이지와 로그인 후 홈의 목적·콘텐츠를 별도 명세로 나눈다.
2. 로그인 후 홈은 `집 한 채·전세 거주자·가장 가까운 일정 하나` 사례로 먼저 시각화한다.
3. 일반 사용자 시안 승인 후 여러 집을 관리하는 임대인·중개사 화면을 별도로 만든다.
4. 집 키 공개 범위와 최초 관리자 확인 방식을 사용자 결정으로 확정한다.
5. 시안 승인 뒤에만 실제 코드를 변경하고, 배포 전 다시 사용자 승인을 받는다.

## 승인 상태

제품 문제와 권장 방향은 정리됐으나 집 키 정책과 새 화면 시안은 **사용자 승인 전**이다. 구현·배포는 시작하지 않았다.
