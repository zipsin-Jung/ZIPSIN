# 공개 홈 한 화면 전환 대화 기록

- 날짜: 2026-10-14
- 참여: 사용자, Codex
- 상태: 구현·로컬 검증 완료, Preview 대기

## 사용자의 핵심 수정

사용자는 기존 공개 홈이 한 화면 뒤에도 내용이 계속 이어져 다시 긴 랜딩페이지처럼 보인다고 지적했다. 공개 홈은 아래로 읽는 방식이 아니라 첫 화면 안에서 네 이야기를 좌우로만 넘겨야 한다고 확정했다.

첫 장에서는 승인한 세로 이미지가 처음에 확대되어 보이다가 집 모양 쪽으로 모여드는 느낌을 주고, 오른쪽에는 다음 의미가 글을 쓰듯 나타나야 한다고 요청했다.

> 계약과 동시에 흩어지는 부동산 정보를 집신 한곳에 모아 관리하고, 하나의 집 이력으로 가치를 키운다.

## 확정한 화면 원칙

- 공개 `/`은 로고·로그인·시작 버튼이 있는 헤더와 네 장 가로 캐러셀만 제공한다.
- 소개·기능·이용 방법·최종 CTA·푸터처럼 아래로 이어지던 섹션은 공개 홈에서 제거한다.
- 데스크톱은 이미지 왼쪽·문구 오른쪽, 모바일은 이미지 위·문구 아래로 배치한다.
- 첫 합성 이미지는 개별 서류를 따로 움직이지 않고 전체 카메라 확대·축소와 빛의 흐름으로 집에 모이는 인상을 만든다.
- 핵심 문장은 실제 HTML로 항상 존재하고 시각적으로만 구절별 reveal 효과를 사용한다.
- 네 장은 화살표·목차·키보드·모바일 swipe로 이동하고 자동재생은 한 번만 진행한다.
- 모션 감소 설정에서는 애니메이션과 자동재생을 끄고 완성 화면을 즉시 보여준다.

## 검수에서 보완한 점

- 320·390px에서 긴 핵심 문장이 잘리던 문제를 줄바꿈 허용과 크기 조정으로 해결했다.
- 1440px에서도 타이핑 문장의 오른쪽이 잘리는 것을 직접 캡처로 발견해 수정하고 자동 회귀 검사를 추가했다.
- 독립 검수에서 320px `다음 장면` 버튼이 아래로 밀리던 문제를 발견했다. 320px에서 페이지 숫자를 숨기고 제어를 한 줄로 고정했으며, 모든 제어의 경계가 viewport 안에 있는지 자동 검사한다.
- 768px에서는 카카오 문의 버튼이 자동재생 버튼을 덮는 문제를 독립 검수로 발견했다. 태블릿 너비에서 문의 버튼을 제어줄 위로 올리고 실제 포인터가 자동재생 버튼에 도달하는지 검사한다.
- 연락 장면은 외부 통화·문자·메신저를 가져오는 기능처럼 표현하지 않고, 사람 초대 뒤 집별 연락처와 집신 채팅에서 새 기록을 시작한다고 명시했다.

## 제품 경계

이번 변경은 비로그인 공개 홈에만 적용한다. 로그인 후 제품, 데이터베이스, 권한, 결제, 외부 연락 연동과 Production은 변경하지 않는다.
