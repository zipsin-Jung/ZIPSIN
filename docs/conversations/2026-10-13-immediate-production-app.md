# 사전가입이 아닌 즉시 사용형 집신

## 반복 시안으로 인한 사용자 스트레스와 핵심 재확인

- 사용자는 시안이 AI로 만든 사기성 랜딩페이지처럼 보이고, 수리 업체로 단정된 것 같다고 정정했다.
- 사용자는 집신의 핵심이 `반복·누락·단절 방지`임을 다시 확인했다.
- 핵심 사용 순간은 에어컨 고장 시 이전 정보 확인, 장기수선충당금 관련 자료 발견, 도배·장판의 입주 전후 상태 비교, 외부에서 급하게 계약서 확인하기다.
- 이런 생활 예시는 세로로 길게 나열하지 않고 좌우로 넘겨 보게 해야 한다.
- 시안을 반복하며 사용자에게 핵심을 다시 설명하게 한 것에 대해 100개 항목의 반성문과 재발 방지 검수표를 작성했다.


## 홈노크 경쟁사 심층 조사

- 사용자는 홈노크를 집신의 경쟁사로 보고, 강하게 참고해서라도 만들자고 요청했다.
- 공개 홈페이지·임대료 자동수납·세금계산기·이용약관·제휴 자료를 확인했다.
- 홈노크는 임대인의 자산·시세·세금·임대료 중심, 집신은 집·사건·기록·채팅·권한 중심으로 구분했다.
- 홈노크의 정보 순서·신뢰 표현·이득 중심 문법은 배우되, 문구·화면·시각 자산은 복제하지 않기로 했다.
- 다음 홈 제작은 토스의 제품 설명, 문토의 생활 온기, 홈노크의 부동산 신뢰를 합친 독자적 6장면으로 제안한다.

- 일자: 2026-10-13
- 사용자 결정: 현재 서비스는 사전 회원가입이나 데모를 광고하는 페이지가 아니라, 설명을 이해한 뒤 바로 가입·로그인하고 사용하는 정식 웹앱이어야 한다.
- 진입 기준: 비로그인 사용자는 실제 로그인·회원가입으로, 로그인 사용자는 업무 홈으로 이동한다.
- 앱 홈 기준: 집신의 핵심 흐름을 짧게 설명하되 실제 최근 집·새 메시지·다음 행동만 표시한다.
- 금지: 가상 고객 수, 가상 업무 수치, 체험·데모·사전가입 문구, 담당자 중심 구조.
- 후속 사용자 확인: “사전회원가입 아니고 바로 로그인이야 그냥 바로”를 다시 확정했다.
- 반영 결과: 최신 코드를 Preview에 배포했고 첫 주소가 실제 `/login`으로 이동하며 `/signup`은 실제 계정 생성 화면으로 표시된다.
- 현재 제한: DB migration은 미적용이므로 실제 집·채팅·고객지원 데이터 왕복을 완료로 표현하지 않는다.
- 사용자 정정: “메인페이지가 왜 로그인이야”라고 지적했으며, 즉시 사용형이라는 말은 메인페이지를 없애는 뜻이 아니라고 바로잡았다.
- 최종 진입 기준: 비로그인 `/`은 정식 서비스 소개 홈, `로그인`은 `/login`, `집신 시작하기`는 `/signup`, 로그인 사용자는 `/home`이다.
- 사용자가 Figma 전체 화면 설계 링크를 참고 자료로 제공했고 “똑같이 만들라는 이야기는 아니며 참고만”이라고 명시했다.
- 반영 기준: Figma의 화면별 한 목적, 넓은 여백, 단순한 아이콘, 기능 묶음 원칙만 참고하고 집신의 색·문구·권한 구조는 독자적으로 유지한다.
- 사용자는 문토처럼 따뜻하고 사랑스러운 분위기를 제안한 뒤 토스 홈페이지 심층 조사를 요청했다.
- 권장 결론: 토스의 장면 중심 제품 설명과 문토의 생활 감성을 결합하되, 집신은 신뢰 60%·따뜻함 40%를 기준으로 한다.
