# 2026-10-02 `test` 페이지 기능 정의

## 사용자 요청

참조 대화 `집신 웹앱 기획 설계 준비`를 토대로 `test` 페이지 기능정의 표를 만들기로 했다.

## 반영한 기존 맥락

- 첫 결제 고객과 도입 채널은 공인중개사무소다.
- 실제 제품 역할은 대표 공인중개사, 보조원, 임대인, 임차인이다.
- 기록은 개인 직원이 아니라 집·계약·사무소 업무에 연결한다.
- 주소만으로는 접근할 수 없고 계약별 초대와 역할 확인이 필요하다.
- 집의 이력은 이어지되 이전 계약자의 개인정보는 이어지지 않는다.
- 수리는 집에서 발생하는 사건 중 하나이며, 제품을 수리 중개 플랫폼으로 정의하지 않는다.
- 선택한 사진·문서·처리 기록을 PDF로 정리하되 법적 효력을 보장한다고 표현하지 않는다.

## 이번 초안의 판단

`/test`는 실제 서비스나 광고 랜딩페이지가 아니라, 가상 데이터로 핵심 흐름을 검증하는 클릭형 기획 페이지로 정의했다. 실제 로그인, 본인 확인, 저장, 초대 발송, 파일 업로드, PDF 생성과 접수는 제외했다.

기능표에는 요구사항 ID `TEST-001~016`, 역할, 시작 조건, 핵심 동작, 예외 상태, 권한 기준, 완료 기준과 범위를 포함했다. 우선 검증할 흐름은 사무소 인수인계, 임차인의 사건 기록, 임대인의 공실 현황 공유 세 가지로 정리했다.
