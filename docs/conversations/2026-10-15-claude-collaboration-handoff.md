# Claude 협업 인수인계 대화 기록

- 일자: 2026-10-15
- 상태: 인수인계 문서화 완료, 사용자 승인 대기

## 사용자 요청

사용자는 Codex와 Claude를 함께 사용해 집신 개발을 계속하려 한다. 지금까지의 파일과 작업 전체를 Claude가 이해하도록 인수인계하고, Claude에서 다음 작업까지 이어갈 수 있는 복사·붙여넣기용 프롬프트를 요청했다.

사용자가 다시 강조한 운영 요구는 다음과 같다.

- 아키텍처 작업은 기능 정의, 스펙, 테스트 케이스, 단위·스트레스·시나리오 검수, 테스트 자동화 순으로 관리한다.
- 코드 커버리지 네 지표는 각각 80% 이상을 기준으로 삼는다.
- 대표 기능의 요구사항, 유저플로우, UI·UX, 소스코드와 테스트코드가 연결돼야 한다.
- 모든 요구, 순서, 결과와 긴 대화를 문서로 남긴다.
- GitHub와 바탕화면 문서함을 함께 갱신한다.
- 모든 에이전트는 기획→설계→개발→테스트→수정→완료보고→사용자 승인 순서를 따른다.
- 기획과 설계를 구분하고 역할별 SOC와 SOP를 둔다.
- 큰 작업은 전체 역할 회의로 시작한다.
- 비판 역할과 시간선·대안 분석 역할은 다른 결정의 과거·현재·미래 영향을 근거와 가정으로 구분한다.
- 총괄비서는 기존 자료를 복구 불가능하게 삭제하지 않고 최종 결과에 사용자 승인을 받는다.

## 확인한 충돌

- 과거 `CLAUDE.md`는 집신을 사전가입·프론트 체험용으로 정의하고 로그인·DB·채팅을 제외해 현재 코드와 충돌했다.
- 과거 인수인계 문서는 이전 worktree·브랜치·기능 상태를 담고 있었다.
- 현재 저장소의 에이전트 파일은 네 책임 파일로 통합돼 있지만, 사용자가 요구하는 업무 관점은 제품기획과 UX·UI 분리 및 시간선 분석을 포함한 여섯 관점이다.
- 공개 홈 검수 통과와 전체 제품 출시 가능 상태가 같은 의미로 오해될 위험이 있었다.

## 정리한 결론

- 날짜가 있는 `docs/24-claude-collaboration-handoff-2026-10-15.md`를 Claude 협업의 단일 기준 문서로 만든다.
- `CLAUDE.md`는 현재 제품·인증·다음 과업을 자동으로 읽도록 교체한다.
- 과거 문서는 삭제하지 않고 역사 자료 안내를 추가한다.
- 사용자의 최신 다음 과업은 로그인 중앙 카드 기본·오류·390px 모바일 시안이다.
- 실제 로그인은 아이디+비밀번호이며 이메일·전화번호 로그인을 가짜로 추가하지 않는다.
- 전체 출시의 별도 P1은 Preview 다계정 Postgres/RLS 검증이다.
- 사용자 승인 전에는 로그인 코드와 Production을 변경하지 않는다.

## 사용자에게 전달할 사용법

Claude에서 같은 저장소와 `codex/contract-to-expiry-home` 브랜치를 열고 `docs/24-claude-collaboration-handoff-2026-10-15.md` 마지막의 짧은 시작 문장을 붙여 넣는다. Claude가 시안을 제출하면 사용자는 마음에 들 때 `승인`이라고 답하면 된다. 실제 Vercel·Supabase 로그인이나 테스트 계정 준비가 필요할 때만 사용자가 직접 처리한다.
