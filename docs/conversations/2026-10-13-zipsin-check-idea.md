# 2026-10-13 집신체크 제품 대화

## 사용자 제안

- 집을 구할 때, 입주한 뒤, 퇴거할 때 필요한 체크리스트를 제공한다.
- 집을 보며 체크한 목록을 신용카드 분석처럼 정리해 보고 온 집을 비교한다.
- 집신 가입 유입을 만드는 서브 프로젝트로 사용한다.
- 집신 가입은 하나로 유지한다.
- 무엇을 준비하면 웹앱을 더 잘 만들 수 있는지 요청했다.

## 통합 결론

- `집신체크`를 별도 회원 서비스가 아니라 집신 안의 서브서비스로 정의한다.
- 신용점수처럼 집의 안전을 단일 등급으로 판정하지 않고, 확인·주의·미확인·전문 확인 필요와 근거를 제공한다.
- 첫 MVP는 집 보기와 후보 2~3채 비교에 집중하고 입주·퇴거는 후속 단계로 둔다.
- 체크 결과는 개인 초안으로 시작하며, 선택한 집만 명시적 동의를 거쳐 집신 기록으로 전환한다.
- 비회원도 첫 체크를 완료하게 하고 저장·복원·장기 비교가 필요할 때 가입을 안내한다.

## 사용자 결정이 필요한 항목

첫 거래유형, 첫 주택유형, 실제로 놓친 사례, 비교 기준, 광고 채널과 가입 유도 시점.

상세 내용은 `docs/18-zipsin-check-kickoff.md`와 `docs/decisions/DEC-014-zipsin-check-subservice-direction.md`에 기록했다.

## 추가 승인과 핵심 요구

사용자는 집신체크가 단순한 체크박스가 아니라 다음 세 요구를 함께 담아야 한다고 강조했다.

- 간단하게 끝내고 싶은 사람
- 빠뜨리지 않고 꼼꼼하게 확인하고 싶은 사람
- 무엇을 왜 확인해야 하는지 배우고 싶은 사람

이에 사용자를 고정된 세 유형으로 나누지 않고 하나의 체크 항목에 `빠르게 체크 / 더 꼼꼼히 / 왜 확인하나요?`를 단계적으로 제공하는 구조를 제안했다. 사용자는 이 방향을 승인하고 제품 명세 작성을 요청했다.

## 통합 프롬프트와 끝까지 제작 요청

사용자는 집신 AI 통합 운영 프롬프트를 제공하고 해당 규칙을 기억해 마지막 단계까지 제작해 달라고 요청했다. 원문은 `docs/20-zipsin-ai-integrated-operating-prompt.md`에 그대로 보존했다.

현재 제품 명세 다음 단계로 기존 정적 Next.js 구조를 유지하는 로컬 저장형 V1 기술 설계와 테스트 우선 구현계획을 작성했다. 실제 계정·서버 저장·사진은 개인정보와 보존정책 승인 전까지 제외하고, `/check`에서 체크·요약·최대 3채 비교를 먼저 검증하는 안이다.

## 공개 도구 UX 보정과 최종 승인

사용자는 항목을 하나씩 넘기는 흐름은 번거로워 이탈을 만들 수 있다고 지적했다. 첫 화면에서 주소·건물명, 이 집을 알게 된 경로, 주택 유형, 거래 유형 등을 받고, 꼼꼼 모드도 전체 항목을 한 번에 볼 수 있어야 한다고 요청했다. 또한 신용카드 분석처럼 후보 집을 카드로 비교하고, 고급스러움보다 밝고 설레는 분위기를 원했다.

집신체크는 데모가 아니라 사람들이 로그인 없이 막 쓸 수 있는 공개 홍보 도구로 확정했다. 대표 경로는 `zipsin.net/ck`, 기존 `/check`는 호환 경로다. 집신체크 전용 계정을 새로 만들지 않고, 향후 집신 단일 계정과 로그인 상태를 공유하는 방향을 유지한다. 사용자는 이 범위의 마무리 구현을 승인했다.

## 현장 사용성 재정의

사용자는 남의 집을 보는 자리에서 기존 입력과 9~16개 큰 카드를 하나씩 여유 있게 다룰 사람은 없다고 지적했다. 그 자리에서 즉시 간단히 체크하고 메모와 사진을 남기는 도구로 바꾸라고 요청했다.

여섯 역할 회의 결과, `/ck`는 필수 입력 없는 `바로 체크 시작`, 핵심 항목별 `괜찮음 / 확인 필요`, 120자 메모, 선택 사진, `방문 끝내기`를 기본 흐름으로 삼는다. 기존 긴 설명과 추가 항목은 삭제하지 않고 같은 기록의 `꼼꼼히 보기`로 내린다. 사진은 서버 전송 없이 현재 브라우저에만 저장하고 다른 기기 복구 불가와 민감한 집 내부 촬영 주의를 고지한다.
