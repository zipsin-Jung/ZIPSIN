# 2026-10-13 에이전트 시스템 확장 대화

## 사용자 요구

사용자는 아키텍처, 기능 정의, 스펙, 테스트 케이스, 단위·스트레스·시나리오 검수, 테스트 자동화와 80% 이상 커버리지를 명시했다. 대표 기능에서 소스코드와 테스트코드가 실제로 연결되는 증거, PRD·유저플로우·UI·UX 매칭도 요청했다.

모든 작업은 순서를 먼저 보고하고 다시 문서화하며, 긴 대화·결정·작업 결과·에이전트 지침·스킬·디렉터리를 GitHub에 보존하도록 요구했다. 에이전트는 기획→설계→개발→테스트→수정→완료보고→사용자 승인 순서를 지키고, 역할별 SOC·SOP와 별도 디자인 역할, 최초 전체회의, 비판적 사고, 시간여행 관점과 총괄비서의 비삭제·최종 승인 책임을 가져야 한다.

## 해석과 결정 제안

- ‘시간여행’은 예언이 아니라 근거 기반 시간선·대안 분석으로 구현한다.
- 실제 학습은 파인튜닝 주장이 아니라 근거·사례·회귀 테스트를 지침과 스킬에 축적하는 운영 지식 학습이다.
- 모든 결과를 무조건 새 스킬로 만들면 충돌하므로, 반복 가능한 절차로 검증된 결과만 새 스킬이나 기존 스킬 개선으로 승격한다.
- 비판적 사고는 독립 품질 판정을 위해 검수·비판 역할에 유지한다.
- 기존 네 역할 기록을 보존하면서 제품기획, UX·UI 디자인과 시간선 분석을 분리한 여섯 역할 체계로 확장한다.

## 승인 상태

지침·스킬·템플릿과 결정안을 작성하고 사용자 최종 승인을 기다린다.
