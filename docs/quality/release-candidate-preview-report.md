# 집신 출시 후보 Preview 검수 보고서

## 범위와 환경

- 기준 브랜치: `codex/public-v1-auth`
- Preview DB: `ZIPSIN Preview` 서울 리전
- 실제 개인정보 대신 `Preview 검수 사용자`, 가상 주소·전화·계약만 사용했습니다.
- Production DB와 Production 배포는 변경하지 않았습니다.

## 실제 확인 결과

| 시나리오 | 결과 | 증거 |
|---|---|---|
| 공개 홈 → 회원가입 | 통과 | Preview에서 계정 생성 후 `/signup/verify` 진입 |
| 역할 → 사무소 → 집 | 통과 | 대표 역할, 사무소 1개, 집 1개 생성 |
| 첫 기록 → 타임라인 | 통과 | 집 내부 기록 저장과 타임라인 표시 확인 |
| 저장 후 화면 이동 | 통과 | 새 기록 저장 후 실패 문구 없이 해당 집 타임라인으로 이동 |
| 대표 직속 고객지원 | 통과 | 공식계정 방 생성, 메시지 전송·새로고침 후 보존 |
| 임대인 초대 | 통과 | 수락 전 주소 미노출, 한 번 수락 후 재사용 `invitation_used` |
| 계약 기록 범위 | 통과 | 임대인은 `current_contract` 1건만 조회, 사무소 내부 기록 미노출 |
| 관계 종료 | 통과 | 종료 직후 동일 임대인 조회 0건 |
| 저장소 공개 여부 | 통과 | `home-records`, `chat-attachments`, `repair-images` 모두 비공개, 공개 버킷 0개 |

## 검수 중 발견·수정

1. SQL 별칭 `authorization` 예약어 충돌을 `authz`로 교체했습니다.
2. Supabase의 `pgcrypto` 함수 호출을 `extensions.digest`로 명시했습니다.
3. `account_usernames`에 `service_role` 최소 권한을 추가했습니다.
4. 집·기록 저장 성공 후 실패 문구가 뜨던 화면 이동 처리를 명시적 `router.push` 방식으로 변경했습니다.
5. 보안 권고가 적용된 Next.js 16.4.0과 `source-map-js` 1.2.2로 올려 감사 결과 0건을 확인했습니다.

## 제한과 판정

- 실제 문자 공급자와 소셜 OAuth는 아직 연결되지 않았습니다.
- Preview에서는 이메일 확인을 꺼 가상 가입을 검수했습니다. Production은 변경하지 않았습니다.
- 계약 생성 화면과 실제 브라우저 사진·PDF 업로드 왕복은 아직 검수하지 못했습니다.
- 동일 기록 20회 동시 저장 자동 검사는 전용 Preview 환경값을 주입하지 않아 skip 상태입니다.
- 독립 품질검수: P0 0건, P1 5건, P2 1건.
- 판정: **FAIL — 일부 Preview 흐름은 확인했지만 실제 가입, 계약 생성 초대, 첨부·종료 경계의 필수 브라우저 증거가 없어 Production 승인 단계가 아닙니다.**
- 추가 권고: 공용 PC 사용자를 위한 로그아웃 UI와 테스트가 필요합니다.
