# 미션 5 가상 수리 기록 CRUD 명세

상태: 사용자 지시로 범위 승인(2026-10-08)

## 목적

기존 집신 랜딩페이지와 영업용 데모를 보존하면서, Supabase에 실제로 저장되는 `가상 수리 기록`의 등록 → 목록 → 상세 → 수정 → 삭제 순환을 완성한다. 새로고침 후에도 데이터와 이미지가 유지되어야 한다.

## 제품 경계

- 이 기능은 부트캠프 미션용 공개 데모이다.
- 실제 주소, 이름, 전화번호, 계약서, 계좌번호를 저장하지 않는다.
- 인증·사용자별 권한·RLS 정책은 미션 7 범위로 제외한다.
- 현재 구조는 누구나 가상 기록을 조회·수정·삭제할 수 있으므로 실서비스용으로 사용하지 않는다.

## 사용자 가치와 흐름

- 대표 공인중개사: 여러 집의 수리 진행 상태를 빠르게 찾는다.
- 보조원: 가상 수리 기록을 등록·수정해 업무 이력을 남긴다.
- 임대인·임차인: 개인정보 없이 집 중심 기록의 가치를 체험한다.

```text
랜딩페이지 → /records 목록
  ├─ /records/new 등록 → 생성된 상세
  └─ /records/[id] 상세
       ├─ /records/[id]/edit 수정 → 상세
       └─ 삭제 확인 → 목록
```

## 요구사항과 수락 기준

### M5-REC-001 목록·탐색

- `/records?page=1&query=&status=`에서 최신 수정 순으로 페이지당 6건을 표시한다.
- 제목·집 별칭 검색과 전체·접수·처리 중·완료 상태 필터를 URL에 유지한다.
- 로딩, 전체 빈 상태, 검색 결과 없음, 조회 오류를 구분한다.
- 7건 이상에서 다음 페이지로 이동할 수 있다.

### M5-REC-002 등록

- 필수: 제목 2~80자, 집 별칭 2~40자, 종류, 상태, 설명 10~1000자, 유효한 수리일.
- 선택: JPG·PNG·WebP 이미지 1장, 최대 5MB.
- 잘못된 항목 가까이 오류를 표시하고 첫 오류로 초점을 이동한다.
- 저장 중 중복 제출을 막고, 실패 시 입력값과 재시도 안내를 유지한다.
- 성공하면 생성된 상세로 이동한다.

### M5-REC-003 상세

- 동적 경로 `/records/[id]`에서 모든 필드, 생성·수정 시각, 첨부 이미지를 표시한다.
- 이미지가 없으면 `첨부 이미지 없음`을 표시한다.
- 잘못된 UUID, 없는 레코드, 삭제된 주소는 전용 404 안내로 처리한다.

### M5-REC-004 수정

- `/records/[id]/edit`에서 기존 값과 이미지를 불러온다.
- 등록과 같은 검증을 재사용하고 이미지 유지·교체·삭제를 지원한다.
- 성공 후 상세에 변경값과 `updated_at`이 반영되고 새로고침해도 유지된다.

### M5-REC-005 삭제

- 상세에서 확인 절차 전에는 삭제하지 않는다.
- 확인 후 레코드와 연결 파일을 삭제하고 목록으로 이동한다.
- 부분 실패는 일반 성공으로 숨기지 않고 재시도 안내를 표시한다.

### M5-REC-006 보안·배포·문서

- Supabase URL과 서버 전용 service role key는 환경 변수로만 관리하고 Git에 저장하지 않는다.
- service role key는 `NEXT_PUBLIC_` 이름을 사용하지 않고 브라우저 번들에 포함하지 않는다.
- Storage는 비공개 `repair-images` 버킷과 UUID 경로를 사용한다.
- README에 스키마, 환경 변수 이름, 실행법, 배포 URL, QA 결과와 인증 제외 한계를 기록한다.

## 데이터 모델

`repair_records`

| 컬럼 | 형식 | 규칙 |
|---|---|---|
| `id` | `uuid` | PK, 자동 생성 |
| `title` | `varchar(80)` | 필수 |
| `home_alias` | `varchar(40)` | 필수, 실주소 금지 안내 |
| `category` | `text` | `plumbing/electrical/heating/interior/other` |
| `status` | `text` | `received/in_progress/completed` |
| `description` | `text` | 10~1000자 |
| `repair_date` | `date` | 필수 |
| `image_path` | `text` | 선택 |
| `created_at` | `timestamptz` | 자동 생성 |
| `updated_at` | `timestamptz` | 자동 갱신 |

## 기술 구조와 실패 처리

- Next.js App Router Server Component가 목록·상세를 조회한다.
- Server Action이 입력을 서버에서 다시 검증하고 등록·수정·삭제한다.
- 이미지 업로드 후 DB 저장이 실패하면 새 파일을 정리한다. 교체는 새 파일·DB 갱신 성공 후 기존 파일을 제거한다.
- 업로드·삭제의 부분 실패는 서버 로그와 사용자 재시도 문구로 남긴다.
- 기존 정적 `output: export`는 제거하고 Vercel Next.js 서버 런타임을 사용한다.

## QA 필수 시나리오

- 빈 값·길이·날짜·파일 형식·크기 오류
- 등록 후 목록·상세 반영과 새로고침 유지
- 수정 후 값·수정 시각 반영
- 삭제 취소·확인·삭제 후 404
- 이미지 없음·업로드 실패·교체·삭제
- URL 검색·필터·페이지 유지
- 1440px·390px·320px, 키보드 초점, 라벨·오류 연결
- 로컬과 배포 환경의 CRUD·Storage 전체 순환을 별도로 확인

## 후속·제외
