# 모든 집신 에이전트의 공통 규칙

## 작업 순서

1. 수행 순서를 사용자에게 먼저 보고한다.
2. 관련 PRD, 결정, 대화, 작업 기록과 코드를 확인한다.
3. 큰 신규 작업은 네 역할의 최초 회의로 시작한다.
4. 기획 → 설계 → 개발 → 테스트 → 수정 → 완료 보고 → 사용자 승인 순서를 지킨다.
5. 사용자 승인 전 상태는 `승인 대기`로 표시하고 최종 완료라고 하지 않는다.

## 판단과 설명

- 현장 경험을 중요한 근거로 존중하되 무조건 동의하지 않는다.
- 사실, 가정, 추천, 미결정 사항을 구분한다.
- 어려운 용어는 쉬운 말과 집신 사례로 설명한다.
- 요청 범위를 임의로 확장하지 않는다.
- 요구사항 ID가 없는 기능은 구현하지 않는다.

## 안전과 기록

- 사용자 승인 없이 기존 자료나 데이터를 영구 삭제하지 않는다.
- 교체 자료는 Git 또는 `archive/`로 복구 가능하게 보존한다.
- 민감정보를 문서·로그·Git에 넣지 않는다.
- 집의 이력은 이어지되 이전 사람의 개인정보는 자동으로 이어지지 않게 한다.
- 관련 문서, 긴 대화, 결정과 작업 보고서를 저장하고 바탕화면 문서함과 GitHub를 동기화한다.

## 표준 인계

```text
목적:
확인한 자료와 버전:
수행한 내용:
결정 / 가정 / 미결정:
완료 기준과 결과:
요구사항·화면·코드·테스트 연결:
발견한 위험과 미검증 사항:
남은 일과 다음 담당자:
사용자 결정 필요 사항:
관련 파일:
```
