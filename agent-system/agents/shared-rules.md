# 모든 집신 에이전트의 공통 규칙

## 작업 순서

1. 수행 순서를 사용자에게 먼저 보고한다.
2. 관련 PRD, 결정, 대화, 작업 기록과 코드를 확인한다.
3. 새 프로젝트·서브프로젝트·새 기능·처음 다루는 구조 변경은 여섯 역할의 최초 회의로 시작한다. 단순 오탈자나 승인 범위 안의 결함 수정은 회의 생략 사유를 작업로그에 남긴다.
4. 기능 정의 → UX·UI 스펙 → 기술 설계 → 테스트 케이스 → 개발(TDD) → 자동검사 → 독립 검수 → 수정·재검수 → 완료 보고 → 사용자 승인 순서를 지킨다.
5. 사용자 승인 전 상태는 `승인 대기`로 표시하고 최종 완료라고 하지 않는다.

## 단계별 승인 게이트

- G1 제품기획: 요구사항 ID, 범위, 수락기준과 성공지표
- G2 UX·UI: 유저플로우, 화면, 모든 상태, 접근성과 복구 방식
- G3 아키텍처: 데이터, API, 서버 인가, 실패·복구·롤백과 비기능 조건
- G4 테스트 설계: TEST-ID, 정상·실패·권한·경계 시나리오와 자동화 범위
- G5 구현·검수: 승인된 추적표, 자동검사와 실제 브라우저 증거
- G6 사용자 승인: 검수 통과 뒤에도 사용자가 승인하기 전에는 완료가 아니다.

## 판단과 설명

- 현장 경험을 중요한 근거로 존중하되 무조건 동의하지 않는다.
- 사실, 가정, 추천, 미결정 사항을 구분한다.
- 어려운 용어는 쉬운 말과 집신 사례로 설명한다.
- 요청 범위를 임의로 확장하지 않는다.
- 요구사항 ID가 없는 기능은 구현하지 않는다.

## 안전과 기록

- 에이전트는 사용자 자료·제품 문서·원본·운영 데이터를 영구 삭제하지 않는다. 삭제가 법적 의무나 개인정보 요청으로 필요하면 실행하지 말고 대상·근거·복구 가능성·감사 방법과 실행 주체를 사용자에게 보고한다.
- 수정·교체 자료는 Git 또는 `archive/`로 복구 가능하게 보존한다. 재생성 가능한 캐시·빌드 산출물도 명시적 대상과 재생성 방법을 확인한 뒤에만 안전하게 정리한다.
- 민감정보를 문서·로그·Git에 넣지 않는다.
- 집의 이력은 이어지되 이전 사람의 개인정보는 자동으로 이어지지 않게 한다.
- 관련 문서, 긴 대화, 결정과 작업 보고서를 저장하고 바탕화면 문서함과 GitHub를 동기화한다.
- 중요한 결정은 즉시 저장한다. 그 외 제품 대화는 본문 약 1,500자 또는 실질 왕복 10회 중 먼저 도달하면 대화 기록을 만든다.
- 모든 실질 작업 종료 때 결과가 반복 가능한 절차인지 평가한다. 반복 입력·출력·승인 게이트가 안정된 경우에만 스킬을 만들거나 갱신하고, 일회성 결과는 문서와 작업로그에 남긴다.

```text
남은 일과 다음 담당자:
사용자 결정 필요 사항:
관련 파일:
```
