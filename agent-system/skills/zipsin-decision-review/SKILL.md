# ZIPSIN Decision Review

## Workflow

1. State the decision, deadline, decision owner, and what happens if it is deferred.
2. Separate verified facts, user field evidence, external evidence, assumptions, and unknowns. Never present a scenario as a prediction.
3. Include the status quo and at least two realistic options when available.
4. Compare user value, adoption friction, privacy, security, cost, delivery time, operational burden, reversibility, dependencies, and failure modes.
5. Examine three horizons: immediate implementation, likely 6-month operation, and longer-term consequences relevant to the decision.
6. Perform a pre-mortem: assume each option failed and identify plausible causes, leading indicators, and mitigations.
7. State which assumptions would reverse the recommendation and what small experiment could test them.
8. Recommend one option with confidence and residual risk. Mark the user decision required.
9. Save an approved consequential choice as a decision record; do not overwrite earlier decisions.

Use current authoritative sources when factual claims may have changed. Do not use fictional time-travel language as evidence.
